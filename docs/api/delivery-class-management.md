# 班级管理与调班 API

## 2026-10-22：查看全部班级与操作权限

新增配置按钮 `zsjos:delivery-class:query-all`（查看全部班级），挂在既有班级管理页面下，与页面查询权限累积使用。拥有该权限时，管理班级分页、分组/子班分页、筛选上下文、详情和班内名单可读取当前租户全部符合查询条件的班级。查询和计数在分页前应用范围；租户、逻辑删除、教学参与及状态/关键词等筛选继续生效。我的班级及显式 `SELF`/`USER` 继续按指定人员读取。

Workbench 与 Vue Admin 将新增权限识别为管理读取入口；未获得时保持原管理/本人规则。该权限不替代 `query-managed` 在既有写命令中的对象资格，也不授予创建、编辑、结课、归组或调班权。班级响应的 `availableActions` 使用 `UPDATE`、`COMPLETE`、`MOVE_GROUP` 表示当前对象可执行动作；班内名单和学员联系上下文使用 `DIRECT_TRANSFER`、`REQUEST_TRANSFER` 表示可用调班入口。前端累计检查对应功能权限及服务端动作后显示入口、加载辅助选项和发送命令，后端命令仍独立复核。

创建独立班级沿用 `create` 与班主任同部门等既有前置条件。Workbench 仅有创建权限而没有 `query-managed` 时仍可创建独立班级，批量多选也固定为 `groupMode=NONE`；创建班级组、加入父级及归组维护继续要求原管理资格与对象动作，不因全读而开放。

`zsjos:student:query-all`（查看全部学员）是学员管理的独立全读权限。班级全读不自动开放范围外的学员详情，学员全读不开放班级全读。V348 仅定义两个按钮和版本记录，不写角色授权或业务数据。需要与后端动作投影和两个前端一起交付；管理员仍通过系统角色管理分配权限。

## 2026-10-21：班级父子分组（Workbench）

工作台主从卡片和桌面表格共用服务端分组查询。普通班可以独立存在或属于一个同部门班级组，只允许两层。父级保存名称、固定部门、可选参考考期和版本；小班保留自己的编号、名称、实际考期、班主任、状态及服务关系。修改父级参考日期不修改已有小班。系统 `UNSCHEDULED` / `EXCEPTION` 分别投影为“未确定考期”/“异常结业”父级，按班型动态收纳，不持久化虚拟班级、不允许手工维护；`PENDING` 保持独立。

### 分组查询

新增 `/zsjos/delivery-class/group` 下的接口，均使用标准 `CommonResult`：

| 方法及路径 | 契约 |
| --- | --- |
| `GET /page`、`GET /my-page` | 与原管理/个人班级读取范围及筛选一致，返回 `{list,total,classTotal}`；`total` 为顶层条目数，`classTotal` 为匹配的实际班级数 |
| `GET /children`、`GET /my-children` | `key=group:<id>` 或 `system:UNSCHEDULED/EXCEPTION`，其余筛选与顶层一致，返回实际班级的 `PageResult` |
| `GET /options` | 有维护权限的当前部门普通父级，关键词搜索及服务端分页；用于创建或调整归组 |
| `GET /candidates` | 当前部门可维护普通班，包含服务中及已结课，排除系统班，关键词搜索及服务端分页；返回当前 `groupId/groupName` |

节点 `type=CLASS/GROUP/SYSTEM`，`key` 分别为 `class:<id>`、`group:<id>`、`system:<kind>`。普通父级的 `group` 包含参考日期、版本和服务端计算的 `canCreate/canUpdate/canDelete`；独立班放在 `single`。摘要包含小班数、班主任数、服务条数、服务中/已结课数量、实际考期摘要与去重项目。参考考期不代替实际考期，多日期显示“多个考期”。

筛选及授权先作用于实际小班，再分组及顶层分页，每页12个顶层条目；组内独立每次12条。项目、人员、数量只来自当前可见且匹配的小班。关键词同时匹配组名、小班名称和编号，组名命中时保留满足其他条件的小班；仅小班命中时 `autoExpand=true`。空组只对有维护权限的用户、默认管理范围、服务中/全部且无小班属性筛选时展示，关键词可匹配空组名。顶层排序为待分班、未确定考期、普通组/独立班、异常结业，普通条目按创建时间及ID倒序。

主从模式使用可展开分组卡片，展开区满行，组内保留小班卡片；移动端单列。表格使用同一 BusinessTable 的父子行，子班和“加载更多”不占顶层分页条目。支持多组展开、收起全部、查询/展开/加载页数及返回位置的会话恢复。顶层与组内独立加载/失败/重试；权限拒绝时清除旧数据并停止无效重试。

工作台卡片以完整班级名称为主标题，允许自动换行；班主任姓名在下方作为次要信息展示。系统班级由 `classKind`（旧响应兼容 `systemClass`）、系统父组由 `type=SYSTEM` 识别，不根据名称或有无考期推断。待分班、未确定考期、异常结业的卡片及展开后的小班使用主题浅色背景、虚线边框和“系统班级/系统分组”标识，精简为名称、实际班主任（如有）、班级/服务数量及原操作入口；不展示编号、考期或项目。表格系统行使用相同标识和背景，对应无关单元格留空。普通班保留实际考期、编号、有效项目和原操作，无项目时不显示占位文案；普通班未填考期仍显示“未设置”。只调整呈现，不改变排序、分页、筛选、权限或班级归属。

### 创建与维护

| 方法及路径 | 请求与行为 |
| --- | --- |
| `POST /create` | `{name,referenceDate?}`，创建当前部门空组 |
| `PUT /{id}` | `{name,referenceDate?,version}`，修改父级；清空参考日期不会修改子班 |
| `DELETE /{id}?version=` | 仅删除实际为空的组，逻辑删除，独立 `group-delete` 按钮权限 |
| `POST /create-classes` | 原批量字段加 `groupMode=NONE/EXISTING/NEW`、`groupId?`、`newGroup?:{name,referenceDate?}`；返回 `{groupId,classIds}`，新父级和全部小班同事务 |
| `POST /move` | `{classes:[{id,version}],targetGroupId:null或ID}`，最多200个普通班，全部校验及同事务调整；空目标表示移出为独立班 |

具有管理资格时，创建弹窗单班默认独立，多选班主任默认新建父级，初始父级名称/参考日期带入小班名称/日期；允许改选已有组或独立创建。只有独立班级创建权限时，单选、多选均创建独立班级，不加载归组选项。从父级添加小班固定父级并默认带入组名及参考日期，小班仍可调整名称和实际日期。失败保留完整表单，不回退逐条创建。

历史班级不自动归组，不按同名或创建时间推断批次；通过整理弹窗人工勾选，在同一弹窗内切换到核对步骤展示原归属及目标，不叠加第二个确认弹窗；可返回修改，失败保留选择。允许已结课普通班调整收纳，原有编辑限制不变。归组只更新 `group_id/version`，并同事务记录 `zsjos_delivery_class_membership_event` 的原/新组及操作者；不触发学员调班，不改 owner、服务状态、待办、日期或历史。

创建组复用 `zsjos:delivery-class:create`，修改/归组复用 `update`，删除空组使用 `zsjos:delivery-class:group-delete`。写操作累计要求原主管入口、当前直接部门及命令范围；组和涉及小班分别校验对象权限。归组按组ID顺序锁定源/目标组，再按小班ID锁定并检查版本，删除空组/向已有组创建也先锁组，避免并发悬空关联。错误分别表示不存在、无权限、跨部门、版本冲突、非空组与非法系统班操作。

旧平铺查询、单条/批量创建、编辑、报名和调班契约保持兼容。旧编辑不提交归组字段，不会清空已有归属；报名和调班始终选择真实小班。Vue Admin 本期保留平铺界面。部署先执行 V343、V344，再发布后端和工作台；V344 仅定义删除空组权限元数据，不写角色授权。已有历史班级 `group_id` 保持空。DDL 不可依赖事务回滚，保留组、归组审计和班级数据，失败核对实际结构及双账本后重放。

验证入口：`DeliveryClassGroupServiceTest`、`DeliveryClassGroupPermissionTest`、原班级回归；`script/sql/mysql/tools/test_delivery_class_groups.py`；工作台 `deliveryClassGroups.test.ts` 和 `test/delivery-class-groups-browser.py`。浏览器夹具隔离所有业务请求，不能代替部署或真实账号验收。

本文档描述租户级交付班级、逐课程服务调班和 BPM 引用契约。接口均为 Admin API，使用
标准 `CommonResult`；菜单权限、部门数据范围和 ZSJOS 对象权限累积生效。

### 严格读取范围（2026-10-19）

`query`/`query-managed` 入口兼容保留，读取部门仅消费 System 返回的部门集合或全部范围，不把“仅本人”映射为当前部门。班级管理分页、筛选上下文、班级详情/班内学员以及学员服务列表/详情保持一致；本人班主任关系独立保留。管理范围是本人关系与获授权部门的并集，不自动授予同部门其他班主任的数据。只持普通 `query` 不显示系统待分班；持 `query-managed` 的既有待分班读取例外不变，显式 SELF/USER 不额外附加待分班。

命令授权仍使用原有独立范围与归属校验，本次读取收紧不调整创建、编辑、结课、直接调班、BPM 调班或联系人操作规则。不修改角色授权、学员归属、迁移或数据库。双端接口及响应形状保持兼容。

## 班级查询与维护

### 工作台视图（2026-10-18）

班级管理遵循全局主从/表格设置：主从视图保留卡片网格和滚动加载；桌面表格视图使用统一 BusinessTable；父子分组上线后每页 12 个顶层条目，展开小班不占顶层分页，展示名称、编号、状态、项目、班主任、考期、服务数量和操作。切换视图或筛选条件从第一页重新查询，表格翻页替换当前页数据。移动端沿用工作台既有规则显示卡片。两种视图共用班级筛选及学员入口，编辑与结课沿用原有权限、服务中状态和系统班限制。下文关于卡片网格的描述适用于主从视图。

### 工作台快捷筛选（2026-10-15）

工作台提供项目、班主任、班级名称/编号、考期范围与服务中/已结课/全部筛选。默认服务中，其余不限；条件取交集，切换后从第一页查询，关键词防抖300ms，回车立即查询。刷新保留条件，重置恢复默认。待分班与正式班级使用同一卡片网格和学员入口，由服务端置顶并参与分页、总数和筛选；不再单独展示待分班区域。待分班无固定班主任和考期，指定班主任或考期时自然不匹配；项目按班内服务快照匹配。

- /page、/my-page 新增可选 projectCategoryId、examDateStart、examDateEnd、excludeSystemClass。日期为 YYYY-MM-DD，包含首尾当天；倒置范围返回参数校验错误。省略新参数保持旧行为，包括 Admin 和学员管理班级选择调用。旧 categoryId 仍查询历史班级分类，不与新服务项目参数混用。
- 项目取班内 active/paused/completed 服务关联订单商品 product_snapshot 中的 categoryId/categoryName/categoryPath，不读取当前产品分类或旧班级分类作为替代。任一服务项目匹配即可命中班级，不重复班级；服务条数仍为整个班级原有统计。无订单、快照缺失或无有效分类ID的服务不推断项目，空班在不限项目时可见。响应 projects: [{id,name,path}] 为历史快照投影；缺少名称显示“项目名称未记录”，工作台无项目时隐藏该项，系统班级和系统父组不展示项目摘要。
- 考期使用班级冻结 exam_schedule_snapshot，与自主日期契约一致，不读取后来修改的考期日历日期。支持单日、区间和旧“名称 · 日期”格式，区间相交即命中；不可解析、无效或倒置区间只在不限日期时可见。SQL在分页前筛选，保留原有排序。
- 快捷范围按 Asia/Shanghai 计算：本月/下月为自然月；未来30/90天包含今天，到今天后第29/89天。自定义选齐范围后生效，清空为不限。
- 新增 GET /filter-context 和 /my-filter-context，分别使用与 /page、/my-page 相同权限；接受 readScope/targetUserId，经同一范围解析，不应用当前筛选条件。返回 {projects,homerooms,pendingClass}。项目与班主任覆盖可见服务中/已结课正式班；班主任采用班级记录的人员ID、姓名和部门快照，停用人员仍可作为历史筛选项。不要求创建/编辑权限，不复用写候选接口。
- pendingClass 仅在原范围允许查看系统班时返回，为既有消费者保留兼容；工作台卡片直接使用分页中的系统班，筛选上下文只负责选项。列表与上下文请求分别处理错误和重试，选项加载失败不阻止已成功加载的班级入口，禁止静态替代。

本次不新增权限、角色授权或数据库结构，不改创建、编辑、分班、调班和结课规则。后端先于工作台发布；Admin保留原界面与兼容参数。验证入口：DeliveryClassFiltersTest、只读可选 DeliveryClassFilterMysqlTest、Workbench日期及页面定向测试。

- `GET /zsjos/delivery-class/page`：按当前用户严格部门 DataPermission 与本人班主任关系分页查询；
  租户级 `PENDING` 系统班级仅向持有 `query-managed` 或既有租户全量读取能力的用户返回。
- `GET /zsjos/delivery-class/my-page`：返回当前用户担任班主任的班级，包含未确定考期与异常结业系统班。旧消费者继续使用此平铺响应；Workbench 父子布局使用 `/group/my-page` 与 `/group/my-children`，卡片只展示班级摘要和服务条数，不展示班内学员。
- `GET /zsjos/delivery-class/{id}`、`GET /zsjos/delivery-class/{id}/students`：读取班级及课程
  服务分页；调用方必须传递并消费 `pageNo`、`pageSize` 和响应 `total`，不得截断为固定前 50 条。
  学员行以 `serviceRelationId` 为操作边界，并返回订单商品所属 `categoryId`。Workbench 从“班级管理”
  进入学员管理时通过路由 state 传递该 ID；主管管理视图不因此获得 owner 专属的学员服务操作权。
- `GET /zsjos/delivery-class/options?categoryId=&includePending=`：返回服务中的普通班和有效规划师的未确定考期班，按
  可选 `categoryId` 过滤；不传时返回当前租户全部服务中班级。`includePending` 默认 true，包含并置顶服务中的租户待分班班级。报名分班不传分类参数，也不以产品、SKU、考期或分类匹配作为保存/完成前置条件；双端平铺展示。
  无分类请求仅按服务状态查询，不拼接系统班/正式班互斥条件。显式分类筛选使用“系统班或该分类”条件；MySQL 回归通过实际 Mapper 与租户拦截器核对结果，避免仅验证前端样本或未执行的 SQL。
- `GET /zsjos/delivery-class/homeroom-candidates`：返回主管直接部门内账号启用且持有启用的
`study_planner` 角色的用户。
- `GET /zsjos/delivery-class/product-options`：返回教务端同源的启用产品、规格和 SKU。
- `GET /zsjos/delivery-class/exam-options`：直接返回当前租户所有已发布、未结束考期，展示名称与日期。
  不需要分类、产品、规格或 SKU 参数；旧筛选参数不再限制结果。精确考期按 `exactDate`、多日考期按
  `endDate`，结束日期次日起不再作为参考候选。响应增加 `exactDate/startDate/endDate`，供弹窗日历定位与选择。
- `POST /zsjos/delivery-class/create`、`PUT /zsjos/delivery-class/{id}`、
  `POST /zsjos/delivery-class/{id}/complete`：创建、编辑和手动结课。

### 主管多选班主任创建（2026-10-20）

工作台新建班级支持多选班主任，确认按钮显示将创建的班级数量。每位学习规划师分别对应一个名称、考期日期相同的独立班级，各有独立编号；编辑已有班级仍为单选。候选使用现有 `homeroom-candidates`，资格沿用主管直接部门、账号启用且持有启用的 `study_planner` 角色，不由前端推断。

`POST /zsjos/delivery-class/batch-create` 复用 `zsjos:delivery-class:create` 权限，请求为 `{className,startDate,homeroomUserIds}`，日期格式为 `YYYY-MM-DD`，班主任数组必填且至少一人、元素不可为空。服务端按人员 ID 去重并保留首次选择顺序，返回相同顺序的班级 ID 数组。名称去除首尾空格，每班独立生成编号，按既有租户机制保存。服务端先校验全部人员资格与直接部门，再在一个事务内创建；任一校验或保存失败，整批不落库。失败时工作台保留表单便于处理后重试，保存中禁用表单与关闭操作。

原单条 `/create` 及编辑接口保持原请求和返回类型，Admin 继续调用原单条接口。此功能无表结构、角色授权或依赖变更；部署应先更新后端，再更新工作台。验证入口为 `DeliveryClassBatchCreateTest`（隔离 H2/JDBC 事务回滚和人员校验）、既有创建/日期测试以及工作台 `test/delivery-class-batch-browser.py`。浏览器测试使用合成接口响应，真实账号验收需另行执行。

编辑班级时，Admin 和 Workbench 在日期未变化、只修改名称或班主任时发送 `preserveExamDate=true`，服务端保留原考期关联和冻结日期快照。用户补填或修改日期时提交 `startDate`，切换为自主日期并清除旧关联；主动清空日期时同时清空关联和日期快照。旧客户端省略该字段，继续按提交的日期或考期 ID 处理。

Admin 和 Workbench 的班级表单均只保留一个“考期日期”选择框。“选择已有考期”打开参考月历，按日期查看并点击已有考期，填入当前所选的日历日期，多日参考考期也只填入所选当天，填入后仍可修改。参考数据仅在打开弹窗时加载；加载失败、无权限或无候选不阻止返回手动填写。

正式班编号为 `BJyyyyMMddHHmmss####`，由服务生成并依赖租户级唯一约束及冲突重试。
班级名称 `className` 必须手工填写（非空白，最多 100 字）。单条创建及编辑提交 `className/homeroomUserId` 和可选 `startDate`，编辑附带 `version`；工作台批量及分组创建提交 `className/homeroomUserIds` 和可选 `startDate`。日期使用 `YYYY-MM-DD`；考期非必选，可先创建普通班，后续通过编辑班级补填；无日期不转换为系统“未确定考期”班。未选日期或旧考期 ID 时，考期关联和快照均为空。前端不提供或提交结束日期。后端保留历史区间和旧客户端 `endDate` 的兼容校验，填写结束日期时必须有开始日期且不得倒置；仅有开始日期按单日保存。自主日期不受考期日历是否存在、发布状态或是否结束限制。不关联产品、SKU 或分类，旧客户端提交的目录字段忽略。数据库列已允许空值，本次无需迁移或历史回填。

班级日期独立存入既有 `exam_schedule_snapshot`，格式为单日 `YYYY-MM-DD` 或区间 `YYYY-MM-DD~YYYY-MM-DD`，无需改表。只要提交自主日期，`examScheduleId` 即不参与校验或保存；编辑时显式清空旧关联。日历参考名称和关联 ID 不成为班级日期的事实来源。旧客户端仅提交 `examScheduleId` 的路径保持兼容，仍校验已发布、未结束并冻结其名称与日期快照；两种路径均受原有权限、部门、班主任资格和版本校验约束。

响应增加 `startDate/endDate`，并兼容 `scheduleType/exactDate`。旧班级从既有日期快照或“名称 · 日期”快照解析，不读取后来被修改的日历日期；无法解析的旧快照保留原文，日期留空，编辑时由用户明确选择。工作台班级管理卡片与表格的“考期”仅展示响应中的实际日期：优先 `startDate`，兼容 `exactDate`；单日展示 `YYYY-MM-DD`，不同结束日期展示 `YYYY-MM-DD ~ YYYY-MM-DD`。普通班缺少日期显示“未设置”；系统班及系统父组卡片隐藏考期，表格考期单元格留空，不回退展示完整考期名称。历史数据不批量改写。新前端依赖新增日期字段，部署顺序为后端在先、前端随后。
历史班级原产品/规格快照保留仅供历史读取，不再作为编辑、报名分班和调班的匹配或锁定条件。
结课只关闭新学员入口，不修改已有服务关系、接收状态或服务阶段。

班主任必须属于当前交付主管的直接部门、账号启用并拥有启用的 `study_planner` 角色。该角色
资格是写命令的实时前置条件，而不只是候选列表过滤条件。班级创建/编辑、主管直调、
BPM 调班通过、报名分班保存和报名完成都会重新确认账号启用且持有启用的学习规划师角色。

班主任变更在一个事务中更新班级及其 `active/paused/completed` 服务关系 owner，并转派首联、
学习计划、督学和协助类未完成业务待办。已完成待办、接收状态、联系/计划/督学历史和协作者
不变。System 通知场景 `zsjos_delivery_class_owner_changed` 按班级、服务关系及变更前版本组成的
事件键逐服务关系幂等通知原、新规划师；待分班
转正式班时没有原规划师则只通知新规划师。

## 主管直接调班

具有 `query-managed` 配置权限的主管可读取当前租户真实系统待分班中的 active/paused/completed 课程服务，包括无负责人新记录和保留历史负责人的记录；不能将所有 owner 为空的记录视为待分班。正式班继续沿用现有部门/负责人范围。课程服务分页、旧学员分页、详情及详情子资源使用一致的待分班授权边界；同一学员的其他范围外课程仍不可读。显式 SELF/USER 查询继续限制在指定人员，不自动附加待分班。

工作台具有主管查询及直调权限时，从管理班级分页加载全部服务中正式班作为候选，排除当前班，加载失败可重试。其他调班申请消费者保持原有候选契约。读取待分班不会授予接收、联系、修改资料等 owner 操作。

`POST /zsjos/delivery-class/service/{serviceRelationId}/direct-transfer` 需要独立权限
`zsjos:delivery-class:direct-transfer`，请求包含 `targetClassId`、服务关系 `version` 和原因。
主管必须同时覆盖源正式班（待分班除外）与目标班的部门数据范围。目标必须是服务中、非当前班的
普通班或未确定考期班，且班主任仍启用并具备规划师能力。命令原子更新班级、owner 与未完成待办执行人，不重置
接收状态或历史。

## 规划师 BPM 调班

- `POST /zsjos/class-transfer/service/{serviceRelationId}`：当前服务 owner 发起普通班和未确定考期班之间调班。
- `GET /zsjos/class-transfer/my-page`、`GET /zsjos/class-transfer/{id}`：查看本人申请及 BPM 引用。

调班申请和审批通过不要求源班与目标班产品分类一致；双端目标选项使用不带分类的正式班候选接口。
权限、部门范围、服务版本、源班归属、目标状态和班主任资格仍按原契约校验。

流程定义 key 为 `zsjos_class_transfer`，business key 为 `class-transfer:{requestId}`，审批节点
key 为 `originalSupervisorReview`。审核人取申请人当前部门 `leaderUserId`，必须启用、不能是
申请人本人，并持有 `bpm:task:update`。流程未部署或主管无效时事务回滚，不残留业务申请。

同一服务关系最多一个 `pending` 申请。审批通过事件重新锁定服务关系和目标班，并核对源班、
源班主任、服务版本、目标班状态及目标班主任快照；发生变化时申请转为 `invalidated`，不强行
调班。通过复用主管调班的原子迁移核心；拒绝为 `rejected`，其他终止/撤销为 `cancelled`。
监听器仅处理 `pending` 记录，因此重复终态事件不会重复迁移待办或发送通知。审批动作和历史
继续由 BPM 统一审批中心承载，ZSJOS 不创建平行任务表。

V188 只交付业务表、API 引用与菜单权限。真实 BPM 流程定义仍需在目标环境单独部署并验收。

## 2026-10-21：规划师异常结业系统班

班型增加 NORMAL/PENDING/EXCEPTION，每位有效规划师默认拥有唯一异常结业班，个人班列表同时展示本人异常结业班，主管按配置管理范围读取。待分班仍为全租户唯一，不以 systemClass=true 泛化待分班权限。异常结业班显示实际班主任和已关闭学员人数，报名分班和普通调班不接受此类目标；仅关闭／恢复命令转入转出。详见 [教学服务关闭恢复](teaching-service-close-restore.md)。

班级列表默认在服务端分页前按“待分班、普通班、异常结业班”排序；各组内部保留创建时间倒序、ID倒序。主管和个人班级列表、Workbench 与 Admin 共用此顺序，筛选及可见范围不变。

## 2026-10-21：规划师未确定考期默认班

班型新增 `UNSCHEDULED`：租户1每位有效学习规划师拥有唯一的“未确定考期”系统班，固定本人为班主任，无考期日期。启动及每60秒通过 System 公开资格接口补齐；新报名直接选规划师时也幂等确保该班存在。姓名/部门随 System 更新，停用保留班级与历史，禁止新分配。默认班不可手工改名、改班主任或结课。

报名按订单商品选班和直接选规划师两条路径均支持该班，生成的 `serviceRelationId` 独立不变、owner 为该班规划师。只有 `PENDING` 无固定班主任并保留全局待分班特殊授权；`systemClass` 仅表示系统维护，不能用于推断待分班或免除部门校验。`UNSCHEDULED` 读取使用本人/主管原有部门范围，普通直调、BPM 调班和教学服务恢复均允许 NORMAL/UNSCHEDULED，继续校验服务生命周期、版本、目标状态和规划师资格，沿用历史和待办转派规则。

`options(includePending=false)` 只排除 PENDING，仍返回有效规划师的 UNSCHEDULED；EXCEPTION 不返回。管理分页增加 `assignableOnly=true` 筛选 NORMAL/UNSCHEDULED，旧 `excludeSystemClass` 语义不变。列表分页前按 PENDING、UNSCHEDULED、NORMAL、EXCEPTION 排序，各组创建时间/ID倒序。双端报名选项显示“未确定考期 · 规划师姓名”，班级页显示实际班主任，考期不造假；筛选指定考期时无日期默认班自然不匹配。项目来自班内服务订单商品快照。

部署：先执行 V343（依赖 V339 双版本账本；不依赖 V340-V342）再部署后端，最后更新 Admin/Workbench。迁移将 pending_guard 收紧到 PENDING，新增租户/规划师默认班唯一约束，不写 System 用户/角色或角色权限，不创建猜测的规划师班级，不搬迁任何历史服务。新库使用同步 canonical 声明及完整迁移链；DDL 隐式提交，失败检查真实结构和双账本后重放。已有引用时不得直接删除默认班或回滚其结构。历史“已分配规划师但仍在待分班”的服务保持原状，整理须另行确认。
