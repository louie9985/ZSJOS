# 客资销售阶段与高级筛选

销售阶段属于客资主体，与有效性、任务完成和成交审批相互独立。“有效沟通”不会自动判有效，“意向客户”不会自动成交。

## 字典与写入

System 字典类型为 `zsjos_lead_sales_stage`。已批准的独立初始化文件为 `script/sql/mysql/dictionary-data/lead-sales-stage.sql`，初始顺序如下；之后名称、排序、启停由管理员维护。

| 字典值 | 初始名称 |
| --- | --- |
| pending_contact | 待触达 |
| contacted | 已触达 |
| effective_communication | 有效沟通 |
| needs_identified | 明确需求 |
| intent_customer | 意向客户 |

所有客资创建路径通过现有提交服务初始化 `pending_contact`，同时保存字典标签。默认项缺失或停用返回 `1900091001` 配置错误，不选取其他选项。列表和详情只读；基本资料编辑不支持阶段修改。

现有新增跟进请求增量接受可选字符串 `salesStage`，客户端只传值。阶段变化时服务端校验启用字典项，非法值返回 `1900091002`。不传或与主体相同则继承原值及原标签，不重新解析改名后的字典。允许回退；客资跟进和机会跟进都在原事务、客资行锁和幂等机制内保存跟进及主体。已成功请求的重复提交直接返回原记录，不覆盖之后的阶段。

## 响应与快照

主体响应新增 `salesStage`、`salesStageLabelSnapshot`。统一跟进响应新增 `salesStageBefore`、`salesStageBeforeLabelSnapshot`、`salesStageAfter`、`salesStageAfterLabelSnapshot`。标签均来自持久化快照，字典后续改名、停用或删除不改变历史。

缺失历史阶段显示“未记录”，不从当前主体回填历史跟进。成交时保留最后阶段，成交后可通过新增跟进继续修改销售阶段，但不改变客资、商机及订单成交状态；上线前已成交且没有阶段的客资继续显示“未记录”。工作台列表、详情、两种跟进入口及时间线适配；管理端已有客资页面适配列表、详情与跟进历史，不新增跟进编辑页面。

## 高级筛选契约

复用现有能力目录、条件组、AND/OR 和保存方案。条件始终与原租户、对象可见范围和页面状态取交集。

| 字段 | 口径与选项来源 |
| --- | --- |
| `lead.salesStage` | 当前主体阶段，System 字典；支持多选、排除、为空、非空 |
| `lead.ownerDeptId` | 当前负责人当前 System 组织及下级；支持包含、排除 |
| `lead.qualificationStatus` | 后端投影 pending / valid / invalid；won 投影为 valid |
| `lead.dealStatus` | won / not_won，仅主体 status=won 视为成交 |
| `lead.qualifiedAt` | 有效性判定时间 |
| `lead.convertedAt` | 首次转化机会（initial_conversion）的 won_at；不是主体转机会时间，不包含复购成交时间 |

原客资分类、来源、负责人及提交、最近跟进、下次跟进、持有起点日期继续可组合使用。日期沿用北京时间解释；最近跟进只看主体最新一次跟进投影。

组织选项由 System DeptApi、AdminUserApi 构建，展示可见负责人组织及其祖先的完整路径，使用既有多选控件。不会从名称推断“中心”或“部门”层级，也不直接读取 System 数据表。选中父节点会展开子节点并转为负责人条件；有效组织没有人员时返回空结果，包含和排除都不会退化成不筛选。已删除或不存在的组织返回筛选无效错误。保存方案校验条件结构，执行时重新解析当前组织及人员归属。

## 初始化和发布边界

新增三张表的可空阶段字段；仅对固定初始化 ID/时间范围内、未删除、未成交且阶段为空的主体补齐 `contacted` 及初始化时字典标签，包含无效、挂起、关闭的未成交记录。已有阶段与已成交记录不覆盖，不修改历史跟进、业务事件、活跃时间、操作人或提醒。

范围标记 `lead_sales_stage_scope_v1` 在首次执行时冻结范围；字典标记 `lead_sales_stage_dictionary_v1` 避免重复种子覆盖管理员维护；完成版本标记避免重放初始化。DDL 隐式提交，失败后可重复执行。恢复应保留可空列，必要时基于受控备份逐行核对后恢复，不得清空后续真实阶段。

升级脚本为 `V275__lead_sales_stage.sql`，前置版本 V274。迁移统一使用连续编号，不再保留奇偶号。不会新增空占位版本、改写已部署历史校验和或调整角色授权。执行受控验证及本地同步：`python script/sql/mysql/tools/test_lead_sales_stage.py --sync-local`；只跑隔离验证时省略参数。工具不含共享测试或生产写入。

已完成的浏览器验证使用真实 Chrome 和隔离 HTTP 测试数据，不代表已更新的运行中后端验收。生产发布还需完整 fresh/upgrade 链检查、运行中 API 联调及真实事务并发验证。
