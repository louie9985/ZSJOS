# 媒体账号删除审批

## 审批展示与删除处理（2026-10-22）

审批业务卡展示申请快照中的账号名称、账号业务编号、平台、申请原因和中文状态，人员展示真实姓名，不将内部账号/用户 ID 作为名称。新申请额外冻结申请人、所属编导姓名；已有申请未保存姓名时，仅根据已存用户 ID 查询 System 用户名称，人员不可用时明确提示，不伪造历史姓名。审批业务内容按已授权任务的确切流程实例读取本轮删除快照，不能以账号最新申请覆盖旧轮次。申请人、冻结审批人或具有账号读取对象权限者可读取相应业务卡。账号删除页隐藏内部流程路由变量 `assignee`、`coll_userList` 等补充字段；该集合不是抄送人。

关联工单和内容审批清理使用带租户约束、行锁和版本检查的普通查询/更新，避免租户 SQL 解析器不支持的 JSON_TABLE 子查询。仅移除 JSON 数组中的目标数字账号 ID，保留其他账号及原有快照；没有剩余账号的活动拍剪工单取消，已完成/取消工单、已终态内容审批及其他租户不变。数据库修改仍由既有事务边界管理。

审批结果处理用嵌套事务保存点包裹全部关联清理、账号删除状态和申请完成状态。任一清理失败先撤销该轮关联修改，再保留 `approved_pending` 与账号冻结状态，后续通过原重试接口完成处理；错误摘要仅保存异常类别和固定重试提示，不写完整 SQL 或驱动异常。`last_error` 在 Mapper 边界按最多 1000 个 Unicode 字符限长，防止再次超长导致 BPM 审批整体失败。本次不改表结构、历史申请或已部署 BPM 模型。

本机独立 MySQL 8 验证入口：`python -B script/sql/mysql/tools/verify_account_delete_approval.py`。只从本机 Docker 数据库复制表定义，在新建 `account_delete_verify_*` 测试库运行真实 MyBatis 租户拦截器与 Spring 事务，不连接应用配置的共享数据源，不修改真实审批、账号或角色权限。

运营申请删除使用 `zsjos_media_account_delete` BPM 流程。申请接口为
`POST /admin-api/zsjos/media-account/{id}/request-delete`，请求体为 `{ "reason": "删除原因" }`。
申请需要 `zsjos:media-account:delete` 与 `media-account / delete-request` 对象权限，仅当前责任运营可以申请。运营同时为所属编导时走编导直接删除路径，不发起自审。

新申请的审批人为账号所属编导，必须启用且具有 `zsjos:media-account:delete-approve` 权限。无有效编导时拒绝提交并返回专用错误，不转交部门主管。申请期间账号冻结；驳回或撤回恢复使用。
申请人通过 `POST /admin-api/zsjos/media-account/{id}/withdraw-delete` 撤回。

所属编导通过 `POST /admin-api/zsjos/media-account/{id}/delete` 直接删除，请求体同样为 `{ "reason": "删除原因" }`。累计要求 `zsjos:media-account:delete` 和 `media-account / delete-direct` 对象权限；无需新建 BPM 实例或额外审批权限。Workbench 显示“删除账号”，填写原因并点击“确认删除”后，再显示最终确认弹窗；只有点击“仍然删除”才调用删除接口，取消不提交且保留原因。运营显示“申请删除账号”，沿用提交审批流程。前端只消费服务端 availableActions，不根据角色名判断。

我的学员列表与详情接口不返回 `runStatus=deleted` 的账号，账号卡片、标签页及详情内的关联内容不再显示该账号。`delete_pending` 仍可见，以便跟踪审批状态。当前账号删除成功后，工作台刷新左侧账号列表并回到学员“概览”，清除已失效账号的路由参数；删除最后一个账号也保留学员。外部无效账号链接仍显示不可访问提示。过滤仅作用于媒体学员投影，账号历史、审批快照及通用历史查询保留，不物理删除记录。

若刷新期间切到其他工作台页签，后台刷新只更新学员页自身数据，不强行切回；再次打开原地址时清除失效账号参数，新的跳转目标不被覆盖。

有 `createServiceRelationId` 的账号只认该确切服务关系的当前运营、编导，要求同租户、同学员、active 且 accepted；不使用账号历史责任人快照或其他服务推断。无来源关系的历史账号保留明确存储的责任运营、编导。全量查看权限不授予删除权。删除审批中或已删除的账号不能再次申请或直接删除。

直接删除将账号运行状态置为 `deleted`，记录原因、操作编导及版本，并产生业务审计事件；不物理删除历史记录、不伪造审批实例或审批快照。账号更新和关联业务处理在同一事务内，失败回滚后可重试。审批通过仍沿用原有删除结果处理及补偿重试。
