# 我的学员服务期归类

工作台新媒体学员页面用「服务期 / 非服务期 / 全部」替换内容区标题，默认服务期。顶部导航不变。
这是人工列表归类，不代表合同期限，不自动判断日期，不改变课程、订单、账号或工作流状态。

## 数据与接口

- `zsjos_person.in_service_period`：非空布尔值，数据库默认 true；同一租户同一学员共用，既有及新增档案默认服务期。不要给 PersonDO 设置 Java 默认值，避免其他档案更新意外覆盖归类。
- `GET /zsjos/media-students/page` 新增可选 `inServicePeriod=true|false`；不传表示全部。过滤在数据库分页前完成，并与搜索、原有授权范围取交集，不扩展可见性。
- 学员响应新增 `inServicePeriod`；新媒体详情新增 `canUpdateServicePeriod`。旧客户端不传筛选参数，保持原有列表行为。管理端不消费此新媒体页面接口，公共学员响应为兼容性加字段。
- `PUT /zsjos/media-students/{personId}/service-period`，JSON `{ "inServicePeriod": false }`；字段必填，标准响应 `data` 为保存后的布尔值。
- 功能权限 `zsjos:media-student:update-service-period` 与后端 `student / update-service-period` 对象检查累积执行。只允许当前租户中仍有未删除服务关系指派的责任运营或编导修改；学习规划师、账号参与者、全量查看者不因此获得修改权。不按角色名称判断。
- 并发修改以最后成功写入为准；只更新开关及标准审计字段，不覆盖学员其他资料。没有权限、不存在、请求字段缺失按现有错误契约返回。

## 交互与兼容

切换标签保留搜索词、重置分页、选择首位结果；空结果清空详情。修改失败保留原值，保存期间禁用重复修改和标签切换。
修改成功后刷新当前列表；不符合标签的学员移出，优先选择下一位仍在重新加载结果中的学员，否则首位。全部标签保留当前详情，即使学员不在第一页。
既有业务通知深链接继续允许直接打开有权限的学员详情，不因列表默认筛选阻断；用户切换标签后按筛选结果选择。
不要求原因、审批或字典配置；这是固定的布尔筛选协议，不是管理员维护的业务枚举。

## 数据库交付

V280 在云端 V279 后执行，现有部署通过该增量升级；历史 migration 不改。新环境的 core schema / bootstrap schema 同步包含字段，然后执行完整迁移链。
脚本只增加字段、按钮元数据和版本记录，重复执行保留手工设置及管理员菜单配置，不改 `system_role_menu`。
管理员通过系统角色管理分配「调整学员服务期」，责任关系仍由后端独立校验。
使用 utf8mb4 客户端验证字段默认值、已设置 false 的重放保留、租户隔离、菜单父子关系和中文 HEX；回退应用时保留字段与配置，不丢弃人工归类。
