# 公告文章来源、发布人和接收范围

中世健公告在管理端与员工工作台共用 System 公告接口。文章来源选择系统维护的启用部门，默认当前操作人所属部门，允许代其他部门发布。没有所属部门时必须手动选择有效来源部门才能发布。

## 保存与发布

- `POST /admin-api/system/notice/create`、`PUT /admin-api/system/notice/update` 增加可选 `sourceDeptId`。新客户端要求选择来源部门；旧客户端省略时，更新保留原来源，新建默认操作人的当前部门。服务端校验所属租户内部门存在且启用。
- `GET /admin-api/system/notice/recipient-options` 在原有部门、用户选项之外增加 `defaultSourceDeptId`。默认部门须在本次可选部门列表内。加载失败保留错误并提供重试，不生成静态部门选项。
- `POST /admin-api/system/notice/publish` 的 HTTP 契约不变。Controller 将登录用户交给发布服务；发布人是实际执行发布的账号，不是草稿创建者或客户端填写的姓名。
- 草稿保存来源部门名称和接收范围说明；发布时重新校验来源，并冻结来源名称、实际发布人姓名和范围说明。发布状态、人员快照和这些字段在同一事务内提交。已发布记录不重新解析当前部门或用户名称。
- 复制草稿保留来源选择和范围，清空实际发布人；副本发布时重新记录。既有公告发布、下线、复制权限及接收人可见性不变。

## 返回与展示

管理 `get/page`、员工 `my-get/my-page/my-cursor` 及未读摘要中的公告增加：

| 字段 | 含义 |
| --- | --- |
| `sourceDeptId` | 来源部门内部编号 |
| `sourceDeptName` | 来源部门名称快照 |
| `publisherId` | 实际发布人内部编号 |
| `publisherName` | 实际发布人姓名快照 |
| `audienceSummary` | 接收部门及指定用户范围说明快照 |
| `audienceType` | 原有 ALL/TARGET 接收契约，员工返回也携带以解释历史空值 |

ALL 显示“全体员工”；TARGET 显示勾选部门名称并注明“含子部门”，额外指定用户显示人数。该说明展示配置范围，不取代发布时按启用状态、阅读权限计算的实际收件人名单，不向普通读者公开收件人姓名清单。阅读统计继续使用[现有快照契约](notice-read-statistics.md)。

首页公告卡片、员工公告列表/表格/详情、两端管理列表和详情均展示来源、发布人及接收部门/人员。编辑预览展示所选来源和范围，发布人提示“发布时自动记录”。草稿列表显示“待发布”。

管理查询参数 `title` 保持兼容，语义扩展为标题、来源部门名称或发布人姓名的模糊搜索；员工的 `keyword` 同样搜索这三个字段，两种分页方式一致。关键词 OR 条件单独分组，仍受已发布状态、接收人、租户和原有其他筛选条件限制。

历史记录不补造来源和发布人，空值展示“未记录”。历史 ALL 可根据既有范围准确显示“全体员工”；没有新范围快照的历史 TARGET 显示“指定部门/用户（历史名称未记录）”，不使用当前组织推断历史来源或范围名称。

## 数据库与部署

`V291__notice_origin.sql` 增加 `system_notice` 的五个可空字段：`source_dept_id`、`source_dept_name`、`publisher_id`、`publisher_name`、`audience_summary`。前置条件为两本 core 版本账本均存在 V287；与 V288–V290 的业务能力无耦合。生产升级仍按仓库 manifest 顺序应用全部适用迁移，再部署后端和两个前端。

两份 core schema 镜像包含相同最终结构，供全新环境的 bootstrap 和结构比较使用；现有部署通过 V291 升级，不重写已部署历史迁移。范围为所有租户共用公告表的新增列，无历史回填、字典业务选项、权限分配或业务行删除。重复执行和部分 DDL 后恢复均检查实际结构，成功后才同事务登记两个版本；已有版本标记不能掩盖缺列。MySQL DDL 会隐式提交，失败后须检查实际列和双账本；回滚应用时保留新增列和已记录数据。

本地验证入口：`python script/sql/mysql/tools/test_notice_origin.py --fresh`。该脚本在已有本地 MySQL 容器中保留独立验证库，覆盖初次、重复、部分应用、失败恢复、中文 HEX、历史数据保留和完整 fresh 链。`--sync-development` 仅对检查后的本地 `ruoyi-vue-pro` 执行上述新增列迁移，不授权共享测试或生产数据库写入。浏览器验证使用两端 `test/notice-origin.html` 与工作台 `test/notice-origin-browser.py`，模拟传输不替代部署后的真实账号接口验收。
