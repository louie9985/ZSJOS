# 学员直接新增

React 工作台及 Vue 管理端支持无订单学员录入，租户为 1。接口使用 ADMIN 认证、租户上下文和
`CommonResult`，统一要求 `zsjos:student:create`（添加学员）。学员录入菜单承载此权限，其他
页面添加按钮复用它；实际角色授权由管理员配置。

## 入口与业务结果

工作台编导运营页提供编导新增，班级管理提供教学新增，班级操作预选当前班级。两端支持
`/zsjos/student-entry`，组件标识 `zsjos/studentEntry/index`；Vue 使用原生录入页，不扩建完整
编导管理页。每次提交创建一条独立服务，复用人员不覆盖旧服务。
工作台桌面及移动端均将该公开路径纳入可渲染范围；入口仍必须由服务端授权菜单返回，不凭组件注册生成菜单。

| 类型 | 编导 | 教学 |
| --- | --- | --- |
| media，不勾教学 | 必选责任编导，立即预审，运营后派 | 不挂班级、不进入教学列表 |
| media，勾教学 | 同上 | 同一服务加入系统待分班，无负责人、无首联待办 |
| teaching，正式班 | 不安排，后续沿用已有指派 | 班主任为负责人，待接收 |
| teaching，待分班 | 不安排 | 后续分班、班主任接收 |

教学接收仍创建现有首联任务，后续沿用学习计划、跟进及交付阶段。录入不创建报名履约任务、
客资、订单、收款、销售业绩、兼职账号、定位卡或工单，不要求资料收集链接，不提供后续补开教学。

## 接口

- `GET /zsjos/student-entry/options` 返回 `directors[{id,name}]`、`classes`（既有班级选项结构）、
  `courses[{skuRef,name}]`。可选择租户内全部有效编导和可入班班级，不增加既有学员读取权。
  编导读取 System 已启用的 `content_director` 岗位及有效人员；正式班重验服务状态与班主任资格，
  异常结业班不可选。缺失候选不能用静态数据补足。
- `POST /zsjos/student-entry/check` 接收 `mobile/wechatId`，至少一项非空。
  返回 `status=new|reuse|occupied|conflict`。只有 `reuse` 返回 `personId/personNo/name/services`，
  服务摘要仅含当前操作者可读的服务及服务姓名、状态与显示标签。无读取资格不返回身份内容。
- `POST /zsjos/student-entry/create` 接收下表，事务内重新校验候选、身份和复用授权。
  返回 `personId/personNo/serviceRelationId/canRead`；无对象读取权时不提供详情入口。

| 字段 | 约束 |
| --- | --- |
| entryType | `media` 或 `teaching`，业务命令类型 |
| name | 必填，最多100字，保存为新服务姓名快照 |
| mobile / wechatId | 至少一项，沿用手机号格式和联系方式占用机制 |
| skuRef | 可空；最多一个目录内 SKU，服务端验证并冻结商品快照 |
| directorUserId | media 必填，teaching 不传 |
| teachingDelivery | media 默认 false；teaching 由服务端强制参与教学 |
| classId | teaching 必填；media 不传，勾教学时服务端选择唯一系统待分班 |
| reusePersonId / confirmReuse | check 返回可复用后明确确认；不自动合并姓名或修改联系方式 |
| idempotencyKey | 必填，最多64字；同一请求重试沿用同一 key |

手机号与微信匹配不同人员时拒绝，不按姓名合并。复用必须具有既有服务读取资格，或持有客资查询
权限且可读取该人员已有客资的未脱敏身份；班级查询者还必须能读取当前班级。仅有添加权限不扩权。人员资料、
旧服务姓名保持原值。提交的联系方式必须属于该人员，补充联系方式使用原资料维护流程。
缺失课程保留为空，不借用同 Person 其他服务。

稳定失败码 `1900010100..1900010105` 分别表示联系方式无效、联系方式冲突、需重新确认复用、
候选失效、幂等请求冲突、录入参数不匹配；无权复用沿用学生权限拒绝错误。

## 状态、事务与兼容

新服务订单、明细、履约关联为空，姓名来源 `independent_entry`，教学接收状态 `pending`。
可空 `media_ready`：直接编导录入为 true、教学录入为 false；正常服务指派编导时置 true。
历史 null 沿用原“已接收”判断，不回填。媒体列表、对象权限、预审访谈、账号、定位卡和运营
指派使用媒体就绪条件；教学命令继续检查教学接收。分班、教学关闭恢复不覆盖媒体状态。

每条新服务创建自己的协作组。幂等命令按租户、操作者、key 唯一，预留后持有行锁；同请求
返回原结果，不同请求拒绝。身份占用、服务、协作组、命令结果及 `student_independent_entry`
事件同事务提交，不将完整联系方式写入业务事件。正式班与编导发布既有分配通知，待分班
不通知班主任；System 仍负责规则和投递。

两端在第一次创建前冻结本次请求及幂等键。用户输入未变时，超时或丢响应后的重试直接重放该请求，
不先重新分类联系方式：原请求可能已成功，此时重新检查会把新人员判为可复用或已占用。
明确的业务拒绝允许重新校验和修正输入；成功结果恢复后才完成当前录入。浏览器回归模拟服务已创建后丢响应，
并验证重试不增加服务、不重新执行联系方式检查。

## 部署与验证

执行 V345（依赖 V344 双账本），然后部署后端、两端前端，管理员配置添加学员权限。
不同步角色授权，不修改历史版本记录。受控执行入口 `script/sql/mysql/tools/test_student_entry.py`，
测试库保留，应用库只读。回退应用时保留字段、命令和录入事实；DDL 无整段事务回滚保证。

验收包含四条新增路径、空课程/SKU、重复请求与显式新增、身份冲突、只读复用、候选失效、
跨部门代录但不扩权、编导立即工作而教学待接收、原订单履约与联系回归、双端桌面及手机布局。
