## 业务契约

- 考试资料收集任务详情顶部使用任务名称区分任务，正文和描述仅用于公开填写及相关预览。任务管理详情展示名称、状态、收集统计和操作入口。

- 独立 Workbench 菜单；权限由 System 配置，菜单内可读租户 1 全部学员、班级、档案，其他菜单权限不变。菜单迁移不分配角色权限。
- 先生成统一链接，再选服务中班级通知；通知时固定应收服务名单及规划师归属。班级成员后续变化不自动改变名单；显式调整留审计。
- 首次通知前已通过人工关联归档的学员，加入固定名单时沿用已归档进度，不再误计缺交；仍只统计名单内学员。
- 姓名、手机号、身份证号码固定必填。考试收集不再收集微信号。已发布材料配置中选择本次字段，勾选必填，未勾选不生成、不校验、不清空档案；礼品邮寄地址不提供。任务冻结字段配置。

2026-11-06 按用户修改要求取消考试微信号字段。新任务不生成该字段，已发出链接通过当前运行时投影同样移除；旧客户端仍传来的 wechat 被忽略，不参与新校验和新归档写入。已有原始提交、任务快照和档案历史保留，当前档案已有微信号不被清空。旧已提交请求仍可按原指纹幂等重试。下文实施阶段“四项固定必填”等记录描述当时行为，以本段当前契约为准。
- 身份证规范化并校验，只以身份证自动匹配固定名单；姓名、手机号差异不阻止归档。不唯一或无匹配进入异常。
- 每次正式提交独立保存；请求重试幂等。同任务同身份证重复提交自动更新已确定归属的档案，保留所有提交与附件历史；重复本身不是异常。
- 人工可关联全部学员中的具体服务；班级外关联列为额外收集人员，不改变应收人数及规划师完成比例。同任务后续同身份证提交沿用人工确认归属。
- 同步现有学员档案的本次收集字段，不修改 Person 主档或原订单快照。保留学员原始提交及档案修改两类历史。不新增多版本字段合并界面。
- 多份未匹配记录确认归属后，最新有效提交生效，历史完整保留；并发、延迟处理不能倒序覆盖。人工变更采用版本冲突检查。
- 查看收集情况复用学员汇总页面，携带任务上下文及班级；统计依据固定名单和本任务归档记录，不将已有报名资料计为本次提交。
- 规划师主页其他待办醒目展示，并弹窗提醒。关闭弹窗仅已读；负责名单全收齐自动移除待办。重复提交不重复计人数、不恢复已完成待办。
- 考务标记任务完成移除全部待办，公开链接显示结束并停止提交；剩余缺交/异常保留实际状态，记录结束原因。重新开启恢复收集及缺交待办。
- 公开入口不得因身份证输入而返回已有资料；上传会话相互隔离，附件受绑定与访问检查保护。

## 匹配与归档内核（已实现，尚未接入接口）

`ExamCollectionPolicy` 是无数据库副作用的业务决策层。调用方必须先按租户、逻辑删除及固定名单筛选候选服务，并通过现有身份证格式/校验码验证；该类不取代这些授权与校验边界。

- 确认绑定优先于自动候选；绑定对象失效时返回单独异常，不静默改绑其他服务。
- 同一服务的多条候选数据去重；同一身份证对应不同服务进入归属不唯一异常。
- 提交顺序必须由服务端任务锁内分配，不采信浏览器时间；延迟归档和同一提交重试不覆盖更晚的已归档提交。
- 统计按固定服务名单去重，排除额外人员和重复提交；没有剩余应收对象的规划师待办可以完成。
- 字段合并只接受本任务完整字段集合，保留未收集字段，且不原地修改原始档案对象。

验证：`python -B script/exam-collection/verify_policy.py`，复用本地已有 JUnit 依赖，无新增依赖。当前 7 项纯逻辑测试通过；尚不能证明数据库并发、接口授权或端到端归档通过。

## 已接入的管理 API（2026-11-04，尚未运行 HTTP 验收）

前缀 `/admin-api/zsjos/exam-collection`，统一响应包装、ADMIN 身份与租户上下文；请求/响应正文日志关闭，响应 `Cache-Control: no-store`。

| 接口 | 契约 |
| --- | --- |
| GET /fields | query 权限；返回已发布且启用的可选材料/证书地址定义 |
| POST /create | query + create；title、description、selectedFields、idempotencyKey；生成字段快照和随机统一链接 |
| GET /page | query；标准分页、keyword、OPEN/COMPLETED；任务状态及应收/归档/异常/额外人数 |
| GET /detail?id= | query + 对象校验；任务详情、冻结字段及统一链接 |

统一链接为配置的 H5 基址加 `/exam-collection#token={token}`。凭证放在 fragment，不进入页面 HTTP 请求路径。创建前验证 HTTP(S) 基址和加密配置；H5 已接入匿名公开路由，实际后端 HTTP/存储联调仍待完成。响应使用明确 VO，不返回 token 哈希、加密列、DAL 对象。

创建请求的 `idempotencyKey` 为 16–64 位字母、数字、下划线或连字符，Workbench 使用 UUID。服务端将租户、当前操作人和请求键组成摘要，以任务表唯一索引防止并发重复；同键同内容返回原任务及链接，同键不同内容拒绝。重试不读取新发布的字段配置，不重建快照。并发插入败方使用锁定当前读读取已提交结果，避免可重复读快照看不到胜方记录。开发版 V362 条件添加 `create_request_key`、`create_request_hash` 和唯一索引，历史行保持 NULL，不伪造幂等键。

创建界面在未知结果时保留并锁定原输入，同请求重试；收到明确业务拒绝后允许修改。未保存输入及未确认结果离开前提示，关闭不等于撤销已生成任务。页面刷新后不自动恢复敏感业务输入，离开未知结果后应先核对任务列表。

创建、通知班级、原因填写、人工关联及归属纠正复用工作台导航保护，覆盖标签页关闭、链接跳转、浏览器返回和刷新。请求处理中不允许离开；有未保存内容时需确认。返回监听通过共享的提前注册分发器先于 BrowserRouter 处理，取消离开保留原 URL 与输入，确认后才重放返回。表单失败保留内容；保存成功正常关闭。

保留标签页中，只有当前激活页处理全局返回和链接事件；隐藏页不会干扰其他页面，主动关闭隐藏页仍检查其未保存内容。原始填写历史按倒序标注填写次数及后端 `submissionStatus`；该字段为可选，缺失或未知状态不推测为已归档。

`StudentServiceArchiveStore` 是内部存储适配器，入口服务先完成权限和提交校验。读取优先服务修订，缺少时读取同 Person/订单商品的原报名表最新修订；没有报名表时返回空档案。原报名修订所选的内部补传附件同样保留。写入需要现有事务、锁定服务、核对租户和附件绑定，以提交 ID 幂等追加修订，拒绝不完整必填材料。现有档案详情/编辑/上传/下载/导出 API 已通过 StudentServiceArchiveFacade 接入；真实 HTTP、文件存储及部署验收尚未完成。

## 公开提交与匹配（已实现服务代码，待 HTTP/前端集成验收）

公开 Controller 业务路径 `/zsjos/exam-collection`，由既有 `pub` 包运行时配置挂载前缀。`X-Exam-Token` 为共享任务凭证；每次填写先创建独立会话，后续以 `X-Exam-Session` 持有该会话。租户从 token 定位后验证并恢复严格租户上下文，调用结束恢复原线程上下文。所有响应 no-store，关闭请求/响应内容日志。

| 方法/路径 | 行为 |
| --- | --- |
| GET /detail | 仅任务名称、说明、状态和字段；完成后字段为空；不返回既有学员资料 |
| POST /session | 创建七天有效的独立填写会话；任务完成时拒绝 |
| POST /submit | idempotencyKey、values；同会话相同键及内容重试幂等，不同内容拒绝；再次填写使用新会话 |
| POST /attachments | 携带 X-Exam-Upload-Key；按选中材料字段上传，验证会话、文件格式、数量和身份证正反面；同会话同键同内容重试返回同一附件 |
| GET /attachments/{id} | 仅本会话草稿材料，返回解密字节；提交后公开不可读取历史材料 |
| DELETE /attachments/{id} | 仅移除本会话草稿引用；保留加密存储以供受控清理，不删除历史提交材料 |

会话创建限流为每任务每分钟 600 次、每来源 IP 每分钟 120 次；上传和提交复用每会话每分钟 30 次及来源 IP 限流，避免把整班统一链接当成一个人的上传配额。附件复用已有 AES-GCM 加密和内容验证，独立 Infra 目录 `exam-collection-private/{task}/{submission}`，业务事务失败时补偿删除新上传存储对象。

提交事务依次锁任务、会话、匹配到的服务，分配服务端序号，保存原始提交，执行匹配和档案追加。匹配失败以 EXCEPTION 保存 UNMATCHED、AMBIGUOUS 或 INVALID_BINDING 原因，不丢材料；匹配唯一时以 ARCHIVED 保存关联。已确认人工归属不重新猜测，失效绑定不静默换人。较老序号的延迟处理保留关联历史但不覆盖最新档案。档案/数据库故障导致事务回滚，客户端可保留输入重试；不会把技术故障伪装为提交成功。

当前 34 项 Java 测试通过，包括公开提交、幂等重试、结束拒绝、线程租户恢复、跨会话文件拒绝、未匹配/多候选异常、人工归属重复更新、旧序号保护，以及既有材料加密/篡改检测回归。未完成实际并发事务、HTTP、Infra 存储往返及浏览器验收。固定名单通知入口、人工异常操作界面、任务结束/重开命令及后续通知同步仍待接入，不能将当前代码视为上线交付。

## 班级通知、生命周期和规划师提醒（后续实现进展）

新增管理接口：

- `GET /classes`：query 权限，返回服务中且可正常承接教务的班级，展示班级维护的学习规划师。可空的 `groupId`、`groupName` 来自现有班级组关联；按班级组创建时间及 ID 倒序展示，组内沿用班级 ID 倒序。前端真实班级组展开勾选，未归组班级直接作为顶层可勾选项展示；已选清单对未归组项直接展示班级名和负责人。组与班级使用不同节点标识，通知仅提交叶子班级 `classIds`。
- `POST /{id}/notify`：query + notify，对象校验；`revision`、`classIds`。锁任务与班级后，固定当前有效教务服务及班级负责人，快照已有档案身份证的 HMAC。系统中没有身份证的学员保留在应收名单，提交后走人工关联。初次通知只执行一次，重复请求版本冲突；后续名单修改走显式调整命令（尚待实现）。
- `POST /{id}/complete`：query + complete；`revision`、`reason`。存在未收齐或异常时原因必填；关闭收集，保留实际填写状态并取消未完成催收待办。
- `POST /{id}/reopen`：query + reopen；`revision`、`reason`。恢复提交；重新生成仍有缺交人员的规划师待办。

班级负责人来自 `DeliveryClass.homeroomUserId`，与既有班级分配的学习规划师契约一致，不从角色名称、人员昵称或编导协同字段推断。使用 System 用户 API 验证负责人可用。名单记录不随转班自动变更。任务新增 `class_ids_json`，即使选中的班级暂时为空，也保留其选择记录。

普通催收使用 `BusinessTaskCommandService`，场景 `exam_material_collection`，类型及操作码 `EXAM_MATERIAL_COLLECTION`；每个任务版本、每个规划师一个幂等待办。提交只刷新当前版本进度，全部归档时完成待办；名单/生命周期变化替换待办版本，保留历史。额外关联人员不进入分母。未引入 BPM 审批或独立待办引擎。

规划师接口前缀 `/admin-api/zsjos/exam-collection-planner`，要求现有 `zsjos:business-task:query`，只读本人当前待办与固定名单汇总，不要求也不授予考务全量查询权限：

- `GET /pending`：自己的催收任务、班级名称、应收/已归档人数及共享链接。
- `GET /state`：一次返回本人 `pending` 与 `unreadTodoIds`，供首页可见时每 30 秒及重新聚焦时刷新。
- `GET /{taskId}/members`：本人当前待办的固定名单分页，支持 `keyword`、`filled`；仅返回姓名、联系手机号、通知时班级和填写状态，不包含身份证及原始答案。独立对象权限要求本人仍持有该任务的有效待办，不能越权查看其他规划师名单。
- `GET /reminders`：尚未确认展示的待办；离线期间产生的待办仍返回。
- `POST /acknowledge`：`{ids:[业务待办ID]}`，整批校验本人待办后记录已读；不完成业务任务、不修改收集状态。重新开启产生新待办 ID，因此重新提醒。

首页其他待办使用醒目提示和“跟进收集”操作。弹窗等待既有业务弹窗关闭及其他输入结束；查看单项只确认该项已读。已读与业务完成分离，迟到的旧轮询结果不会恢复已确认提醒；已读响应丢失时重新查询状态判断结果。任务完成后清除名单展示，重开产生新的提醒。通用取消待办接口不支持考试收集任务。

Vue Admin 的既有今日任务页只读今日分桶，本功能待办无到期日，归入其他待办；未为 Admin 复制员工跟进流程。V362 尚未部署，仅用于本分支开发；隔离 MySQL 验证及配置库只读对照记录见 handoff。规划师界面已完成合成数据浏览器验证，真实 HTTP/数据库事务联调仍待完成。

## 工作台菜单与任务汇总

Workbench 原生路由 `/zsjos/exam-material-collection`，任务详情使用 `?taskId=...`。菜单名称、顺序和权限继续由服务端决定；本地只注册支持的页面路径。Vue Admin 过滤不支持的 `zsjos/examCollection/index`，不复制考务工作流。

任务列表、名单、提交记录、异常、候选学员和操作记录统一使用 BusinessTable。创建弹窗从接口加载可选材料，默认不选，允许只生成四个固定字段；生成后展示可复制统一链接，再选择班级通知。详情展示固定名单进度、额外人员及异常数量。异常详情复用 StudentInfoPanel，人工核对当前档案并输入原因；待处理身份证组有多个提交时，引导先查看最新一份，避免不知情地使用另一份内容。

“查看收集情况”进入同一菜单路径下 `?taskId=...&view=summary`，复用 StudentSummaryPage 并自动选择任务班级。该入口使用专属 `/admin-api/zsjos/exam-collection/{id}/summary/{columns,classes,page,coverage,export}`，查询及导出均要求 exam query（2026-11-10 用户确认有收集权限即有导出权限）；原 student-summary 路由和 API 不因此获得新的授权。这样可在考试菜单内使用全量档案能力，不放宽其他菜单。

任务汇总先按固定成员表的 active、班级快照及本任务提交状态分页，再复用现有档案批量投影。转班不改变统计；原报名已填写不计为本次已填写；额外关联人员不进入分母。导出沿用相同筛选、列顺序及 Excel 文本值规则。原全局学员汇总也叠加最新服务档案修订，支持没有原报名表的历史学员，并保持原有查询/导出权限。

关闭的教务服务沿用现有只读约束：新提交保存为 SERVICE_CLOSED 异常，不自动改写档案；人工归属确认同样不能写入已关闭课程。目标档案版本冲突使用独立错误码及“刷新目标档案后重新确认”的提示。提交时间展示学员原始提交时间，不使用晚于提交的人工归档时间。

## H5 与重试边界（后续验收进展）

公开路由 `/exam-collection` 标记 requiresAuth=false，读取 fragment 中的 token；不读取学员主档、不要求合作方登录。使用独立 public-api 客户端，显式移除 Authorization，不进入 Partner 登录/刷新流程。表单只渲染服务端冻结字段，复用已有 CollectionImages 和身份证校验；原报名收集页保持默认附件客户端。

每次填写创建独立会话，答案仅存于当前页面内存。上传中的文件显示进度，失败可重试或移除；会话失效可保留文字重新建立，附件重新上传。提交结果不确定时冻结当前输入，重试使用完全相同的请求键和内容；收到明确校验失败后恢复编辑。成功页面不宣称已匹配入档；“再填写一份”清空上次文字和附件并创建新会话。任务结束时不创建会话、不显示可提交表单。离开未提交表单会提示，提交或上传中避免切换。

附件重试使用 Pending 文件的固定请求键。V362 的附件表增加 request_key/request_hash 与 `(tenant_id,submission_id,request_key)` 唯一索引；相同键和规范化内容返回原附件，不重复写入存储、不重复占身份证正反面名额；同键不同内容拒绝。索引和字段通过 information_schema 条件补齐开发中旧测试表，不修改已部署历史脚本。文件仍以加密字节存储，事务绑定失败补偿本次新对象。

### 接口与设置

接口前缀 `/admin-api/zsjos/exam-collection/{taskId}/material-export`。

| 方法与路径 | 契约 |
| --- | --- |
| GET /settings | 返回任务目录和命名设置，旧任务默认按材料分类 |
| PUT /settings | 保存 layout、groupByClass、naming、overrides，使用独立 revision 冲突检查 |
| POST /preview | 校验范围并返回人员/提交数、附件数、原始字节数、前 80 个路径、缺失提示和 fingerprint |
| POST /download | 携带同一请求及预览 fingerprint，资料或规则变化需重新预览 |

`layout` 使用 MATERIAL、STUDENT、FLAT，`mode` 使用 ARCHIVE、SUBMISSIONS。这些是导出协议中的技术命令。命名数组按顺序组合 name、mobile、idCard、material、side、sequence、original、submittedAt 或 `text:固定文字`，每项材料可覆盖默认规则。材料标签使用任务冻结配置。变量使用所选资料版本中的答案。submittedAt 显示为 yyyy_MM_dd HH_mm_ss，原始提交使用该次 submittedAt，当前有效资料使用本任务该服务最近提交序号对应的 submittedAt，缺失显示“未记录”。sequence 在同一服务/提交及材料内计数。扩展名取保存的已校验内容类型，原文件名变量去扩展名。文件名过滤控制字符、路径及 Windows 禁用字符/保留名，长度限制为 100 Unicode 字符，ZIP 路径重名按大小写不敏感追加序号。原始加密存储对象继续通过 Infra 公共 API 和已有归属校验解密读取。

导出范围由任务有效固定名单决定，支持 classIds、serviceIds、keyword、filled、fieldKeys。留空导出全部筛选结果。serviceIds 必须属于任务当前有效名单或显式包含的额外归档服务，越界请求整体拒绝。关键词在所选版本的答案文本中匹配。filled 表示固定名单的本任务填写状态。班级使用任务成员快照。includeAdditional 显式加入额外归档服务，原始模式同时加入未匹配提交；班级/指定人员筛选仍累计生效。指定学员候选来自任务成员 API，搜索每次最多显示 100 条。

ARCHIVE 读取当前服务档案修订，兼容原报名附件，只导出任务材料范围；当前有效资料与本次填写状态分别展示。SUBMISSIONS 保留每次正式提交的独立目录、顺序和状态，包含异常/已标无效历史；预览中的 people 在该模式表示提交份数。未正式提交的上传会话不进入导出。额外人员单独归组。

设置以 `zsjos_exam_collection_task.export_settings_json` 持久化，只保存目录及命名偏好，筛选为本次临时参数。任务行锁与设置独立 revision 防止并发覆盖，不变更收集任务生命周期 revision。预览和生成各使用可重复读事务，下载重建清单并核对 fingerprint。读取失败整体失败，完成前不向 HTTP 输出 ZIP。解密后的 ZIP 使用随机临时文件，在失败或响应结束后删除；响应及预览禁止缓存，访问日志不记录命名和敏感路径。

单次限制 2000 个附件、512 MB 原始字节，任务扫描保护上限 10000 条。超限必须缩小范围。通过现有异步导出任务生成，保留上述单次上限。考试 ZIP 产物加密保存，通过受鉴权业务接口下载。
