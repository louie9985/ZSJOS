# 考试资料收集（开发设计）

状态：已确认业务方案，尚未实现。环境为 local，独立分支 codex/exam-material-collection。

## 业务契约

- 独立 Workbench 菜单；权限由 System 配置，菜单内可读租户 1 全部学员、班级、档案，其他菜单权限不变。菜单迁移不分配角色权限。
- 先生成统一链接，再选服务中班级通知；通知时固定应收服务名单及规划师归属。班级成员后续变化不自动改变名单；显式调整留审计。
- 姓名、手机号、微信号、身份证号码固定必填。已发布材料配置中选择本次字段，勾选必填，未勾选不生成、不校验、不清空档案；礼品邮寄地址不提供。任务冻结字段配置。
- 身份证规范化并校验，只以身份证自动匹配固定名单；姓名、手机号差异不阻止归档。不唯一或无匹配进入异常。
- 每次正式提交独立保存；请求重试幂等。同任务同身份证重复提交自动更新已确定归属的档案，保留所有提交与附件历史；重复本身不是异常。
- 人工可关联全部学员中的具体服务；班级外关联列为额外收集人员，不改变应收人数及规划师完成比例。同任务后续同身份证提交沿用人工确认归属。
- 同步现有学员档案的本次收集字段，不修改 Person 主档或原订单快照。保留学员原始提交及档案修改两类历史。不新增多版本字段合并界面。
- 多份未匹配记录确认归属后，最新有效提交生效，历史完整保留；并发、延迟处理不能倒序覆盖。人工变更采用版本冲突检查。
- 查看收集情况复用学员汇总页面，携带任务上下文及班级；统计依据固定名单和本任务归档记录，不将已有报名资料计为本次提交。
- 规划师主页其他待办醒目展示，并弹窗提醒。关闭弹窗仅已读；负责名单全收齐自动移除待办。重复提交不重复计人数、不恢复已完成待办。
- 考务标记任务完成移除全部待办，公开链接显示结束并停止提交；剩余缺交/异常保留实际状态，记录结束原因。重新开启恢复收集及缺交待办。
- 公开入口不得因身份证输入而返回已有资料；上传会话相互隔离，附件受绑定与访问检查保护。

## 实现边界与待落实技术契约

业务属于 yudao-module-zsjos，遵循 Controller/VO → Service → DAL；System 提供权限、字典、通知，Infra 提供存储，普通催收待办复用现有业务任务场景。不得复制 BPM 审批能力。

现有报名表绑定订单商品/人员，不能直接将个人 token 改成共享 token。新增考试任务、固定名单、独立提交、人工身份绑定与审计模型，复用配置、校验、附件及档案修订机制。实现前核实无原表单服务的档案写入、跨任务修改排序、附件历史可读性和错误归属纠正机制。

## 匹配与归档内核（已实现，尚未接入接口）

`ExamCollectionPolicy` 是无数据库副作用的业务决策层。调用方必须先按租户、逻辑删除及固定名单筛选候选服务，并通过现有身份证格式/校验码验证；该类不取代这些授权与校验边界。

- 确认绑定优先于自动候选；绑定对象失效时返回单独异常，不静默改绑其他服务。
- 同一服务的多条候选数据去重；同一身份证对应不同服务进入归属不唯一异常。
- 提交顺序必须由服务端任务锁内分配，不采信浏览器时间；延迟归档和同一提交重试不覆盖更晚的已归档提交。
- 统计按固定服务名单去重，排除额外人员和重复提交；没有剩余应收对象的规划师待办可以完成。
- 字段合并只接受本任务完整字段集合，保留未收集字段，且不原地修改原始档案对象。

验证：`python -B script/exam-collection/verify_policy.py`，复用本地已有 JUnit 依赖，无新增依赖。当前 7 项纯逻辑测试通过；尚不能证明数据库并发、接口授权或端到端归档通过。

## 持久化结构与配置快照（基础层已实现）

V362 前置为两本台账的 V361。新增以下表，均含租户、逻辑删除和审计字段：

| 表 | 所有权与用途 |
| --- | --- |
| zsjos_exam_collection_task | 任务字段快照、公开 token 哈希及加密原文、状态、版本和服务端提交序号 |
| zsjos_exam_collection_member | 固定应收服务、班级名称快照、规划师、身份证匹配摘要及收齐记录 |
| zsjos_exam_collection_submission | 独立填写会话、请求幂等、提交顺序、加密原始答案和匹配结果 |

| zsjos_exam_collection_event | 人工关联、任务状态及名单调整的操作记录 |

服务档案修订保存完整字段与答案投影、来源、附件引用及修订序号；附件引用必须区分原报名材料和考试提交材料的来源，读取端分别验证绑定。该表的读写接入仍待实现，当前不改变旧档案行为。

身份证匹配摘要应由服务端密钥生成，不能把身份证明文写入索引或日志；token 使用随机高熵值，答案、token 原文及操作详情使用现有加密类型处理器。加密实际往返及公开入口尚待集成验证。

`ExamCollectionFields` 从发布配置复制可选材料和证书邮寄地址；固定生成姓名、手机、微信、身份证，其余仅包含选中字段。选择过程不修改原配置。未勾选身份证正反面不会自动生成该附件字段；身份证号码始终必填。

## 已接入的管理 API（2026-11-04，尚未运行 HTTP 验收）

前缀 `/admin-api/zsjos/exam-collection`，统一响应包装、ADMIN 身份与租户上下文；请求/响应正文日志关闭，响应 `Cache-Control: no-store`。

| 接口 | 契约 |
| --- | --- |
| GET /fields | query 权限；返回已发布且启用的可选材料/证书地址定义 |
| POST /create | query + create；title、description、selectedFields；生成字段快照和随机统一链接 |
| GET /page | query；标准分页、keyword、OPEN/COMPLETED；任务状态及应收/归档/异常/额外人数 |
| GET /detail?id= | query + 对象校验；任务详情、冻结字段及统一链接 |

统一链接路径为配置的 H5 基址加 `/exam-collection/{token}`。创建前验证 HTTP(S) 基址和加密配置；该公开路由尚未接入，不能作为当前可用的端到端能力交付。响应使用明确 VO，不返回 token 哈希、加密列、DAL 对象。

`StudentServiceArchiveStore` 是内部存储适配器，入口服务先完成权限和提交校验。读取优先服务修订，缺少时读取同 Person/订单商品的原报名表最新修订；没有报名表时返回空档案。原报名修订所选的内部补传附件同样保留。写入需要现有事务、锁定服务、核对租户和附件绑定，以提交 ID 幂等追加修订，拒绝不完整必填材料。旧档案详情/维护 API 尚未切换到该适配器，后续必须完成后才能宣称“已同步展示”。

身份证索引使用现有加密密钥派生的 HMAC-SHA256，采用独立用途前缀；更换密钥会影响索引匹配，沿用现有加密密钥持久化与备份要求。公开链接为 32 字节安全随机值的 URL-safe 编码，查询使用 SHA-256 摘要。
