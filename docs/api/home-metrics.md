# 首页动态指标

## 使用流程

Vue 管理端在系统管理下提供 `/system/home-metric`，服务端菜单组件为 `zsjos/homeMetric/index`，Workbench 呈现模式明确为 `admin_only`。管理员配置草稿、按本人业务权限预览、发布、停用、复制或回退已发布版本。草稿编辑不改变线上版本；回退产生新版本。角色管理分别授权 `zsjos:home-metric:query`、`:update`、`:publish`，SQL 不授予角色权限。

Workbench `/zsjos/tasks/today` 按用户 2026-10-30 明确决定保留三张固定待办卡：业务待办（逾期、今日、未来之和及分项）、其他待办（无截止时间）、审批待办（点击进入原审批待办页面）。固定展示不依赖指标配置，数据和权限仍来自既有业务/BPM接口，不硬编码数量或授权。其他指标继续由已发布配置驱动，下方原有任务面板不改变。内置待办来源能力保留，但无需另配同口径指标来恢复固定卡。

2026-10-30 用户明确限制：只支持既有桌面六列两行，最多启用 12 个指标，不扩展动态行数。兼容旧开发配置超过 12 项时，先授权过滤、排序，再取前 12 项展示，不自动停用或删除记录。明细使用覆盖层，不占用卡片网格。原窄屏样式保持。

卡片配置包括名称、说明、显示单位、排序、查看权限、指定人员/部门、点击模式、操作数、筛选、聚合、时间字段、周期及计算公式。人员与部门限制均为交集，空集合不追加限制。配置查看权限不授予来源数据权限。

## 来源及计算

| 来源 | 默认计数身份 | 数值聚合字段 | 周期 |
| --- | --- | --- | --- |
| 客资管理 | lead.id | 跟进次数 | 提交时间 |
| 订单管理 | order.id | 订单总金额 | 提交/生效时间 |
| 我的学员 | person.id，先按课程服务授权和筛选 | 无 | 服务激活时间 |
| 返现 | cashback.id | 返现金额、计算基数 | 生成/可用/结算时间 |
| 提现 | withdrawal.id | 申请/批准金额 | 提交/审核/打款时间 |
| 个人待处理申诉、查重审核、报名履约、媒体学员、下属销售、教务团队 | 原业务分页的实体身份和授权 total | 无 | 来源高级筛选目录声明的日期字段；没有日期字段则仅不限时间 |
| 我的业务待办、我的审批待办 | 原业务/BPM 当前用户待办 | 无 | 当前待办，不提供自定义筛选/周期 |

没有安全数值字段的来源只支持计数/去重计数。其他来源支持 SUM/AVG/MIN/MAX；先按业务身份去重，再聚合，不能使用 `SUM(DISTINCT 金额)`。业务分页来源只查询一条并使用原服务总数，不在指标代码中遍历所有分页。财务筛选仍依赖原有来源对象授权解析，受既有查询成本影响。

公式支持具名操作数、十进制常量、括号、正负号和加减乘除。比率及跨来源计算通过操作数组合表达；同比/环比使用独立比较期操作数，例如 `(本期-同期)/同期`。使用 BigDecimal，除法 DECIMAL128，HTTP 数值为十进制字符串。加减必须单位兼容，百分比只用于无量纲结果。空集 COUNT/SUM 为 0，AVG/MIN/MAX 为 EMPTY；除零不显示 0 或 100%。

业务时间统一 Asia/Shanghai，区间左闭右开。自然周期、截至当前、固定自定义区间、不限时间分别处理。一次求值的周期与相对筛选使用同一时间基准；相对筛选冻结为 `relativeBaseDate`，保持原 AND/OR 树。明细沿用已冻结时间；数据本身仍是实时读取，不承诺事务快照跨请求保持不变。

## 权限、版本与深链

统计为当前查看者业务可读集合与来源基础视图、指标条件的交集。所有操作数查询前检查权限，返回前再次检查；任何来源无权限时不返回整项数值或中间值。配置命令有功能权限和对象边界，CAS 在数据库更新条件中执行。

查看权限必须是当前租户已启用菜单树中的有效 permission，不能填写不存在的值或 `*:*:*`。System 的 `PermissionApi.getDefinedPermissions/isPermissionDefined` 仅提供元数据，不授予权限。人员/部门来自 System 公共 API。字典选择存标签快照，未变选择保留原标签；执行时字典失效会拒绝，不能忽略条件变成全量。

`MODAL` 打开指标明细弹窗，`ROUTE` 使用同首页深链 `?metricContext=<opaque-token>` 打开可刷新恢复的明细覆盖层。两种方式都不挤占六列两行网格，不支持管理员填写任意外部网址/脚本。公式先展示各操作数的来源、数值/状态和时间，再选择操作数查看明细。

Redis 上下文有效期 15 分钟，绑定用户、租户、发布版本、冻结筛选和时间。普通用户响应不返回原始敏感筛选值、配置人员/部门范围、内部 actor/tenant。每次打开/翻页都重检权限、启停、版本与字典有效性；停用或新版本发布立即使旧链接失效。业务明细仅返回受控列，不返回联系人字段；内部主键仅用于行身份，不作为客资业务编号。

上下文中的旧数值不能直接复用：每次读取按当前数据范围重新计算所有操作数，但使用已保存的实际 Range，不重新解析“本月”等相对周期。数据范围收窄后不返回原范围金额。新的求值响应同时返回实际发布版本及其展示配置，防止新数值套用旧名称/单位/百分比。运行时只判断当前查看者是否在有效范围内，名单中其他用户停用不会使该指标对所有人失效；保存/发布仍批量校验名单引用。

## API

统一前缀 `/admin-api/zsjos/home-metric`；遵循 ADMIN 认证和租户上下文。

时间区间 `start/end` 在 JSON 中为毫秒时间戳，按明确的 Asia/Shanghai 转换，不依赖部署 JVM 默认时区；内部边界精度同为毫秒。`evaluatedAt/expiresAt` 为 Instant ISO 字符串。自定义区间可提交 ISO 本地北京时间或毫秒时间戳，带 offset 的输入按真实时刻转换至北京时间。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/list`、`/get?id=`、`/versions?id=` | 配置列表、草稿、发布版本历史 |
| GET | `/catalog`、`/options`、`/permissions` | 当前操作者可用来源、技术运算选项、权限元数据 |
| POST | `/save` | `{id?,version?,spec}`，创建或 CAS 更新草稿 |
| POST | `/publish`、`/disable`、`/copy`、`/rollback` | `{id,version,targetVersion?}`；回退须提供目标版本 |
| POST | `/preview` | spec，按当前管理员权限预览 |
| GET | `/visible` | 当前查看者可见的已发布指标，已裁剪内部配置 |
| POST | `/evaluate` | `{id}`，返回结果及可用时的上下文 ID |
| GET | `/context?id=` | 已授权的公开上下文 |
| POST | `/details` | `{contextId,operand,pageNo,pageSize}`，明细分页 |

预览、求值和明细 POST 声明 READ_ONLY 审计。配置总量上限 200、同时启用上限 12；写入时检查，不在授权前截断列表。公式最多 16 个操作数、16 层、127 节点、2048 字符；明细最多 100 条/页。前端求值并发 4，后端按租户/用户限 120 次/分钟。SQL 聚合/明细语句超时 5 秒，公式整体单调时钟预算 20 秒；SQL 边界以外的既有授权解析仍需真实环境性能观察。

## 数据库及集成

正式迁移为 `script/sql/mysql/migrations/V358__home_metrics.sql`，要求 V357 两本 core 账本及唯一有效 System 根菜单。执行顺序为 V357 → V358 → 配套后端 → Admin/Workbench。新增空表 `zsjos_home_metric`、`zsjos_home_metric_version` 和菜单元数据；两账本登记 V358，校验值沿用项目标准 SHA2 文件名。Core desired schema 和 fresh baseline 仅追加这两张空表，菜单及 V358 登记仍由迁移负责。不修改角色授权或业务数据；DDL 非原子，重复执行校验结构并恢复缺失项，DML 与账本在统一失败路径中提交。

本次集成已分配正式编号 V358，原未部署的 feature 源文件已替换，不改写 V001–V357。受控专项验证使用合成 V357 前提；完整 fresh/upgrade 链由合并后的主分支统一验证。回退应用时保留两表数据、菜单和账本，不提供破坏性删除回滚。未执行生产或本地业务库迁移。

`python -B script/sql/mysql/tools/test_home_metrics_mysql.py` 在现有本地 MySQL 新建唯一验证 schema，只复制三张基础表结构并插入合成前置数据；不复制业务行，不删除验证库。九组专项检查覆盖首次/重复、fresh baseline 预建两表后升级、重跑保留既有配置和历史、前提失败、部分 DDL、账本失败回滚、已有标记补结构、列类型冲突、菜单身份冲突。同步比较迁移/desired/baseline 的声明与 MySQL 实际 22 列、4 索引，检查账本校验值、Admin-only 菜单及中文 HEX；输出区分源文件字节 SHA256 与实际执行的规范化 SQL 文本 SHA256。该验证不是完整 V001–V358 链验收。

前端浏览器脚本使用明确隔离 fixture，验证界面交互，不代替真实账号/真实后端端到端验收。部署前仍需在目标环境分配权限、迁移、启动新后端并进行真实账号允许/拒绝与性能验收。
