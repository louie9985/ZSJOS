# 周期诊断综合表

UTF-8。2026-10-22。替代账号档案契约中周期诊断同日分别填写、单模板新提交和提交后全部指标固定的旧规则；启动诊断保持原行为。

## 多账号填写（2026-10-25）

- 默认只带入当前账号。明细底部虚线“＋ 添加账号”按需加入账号，右侧红色垃圾桶仅从本次填写中移除，不删除账号、不取消待办；移除再添加保留本次草稿。允许只提交一个账号，也允许移除入口账号后仅提交其他账号，不强制全选。
- 当前阶段、账号状态及本节点需要的 7 天最高点赞逐账号填写，其余人工诊断内容共用填写一次。字典选项来自服务端，各账号独立保存值和标签快照。每个账号可展开完整指标；学员维度的客资/成交/转化率不按媒体账号相加。
- GET `/admin-api/zsjos/media-account/diagnosis/batch-candidates`：参数 accountId（入口账号）、templateType=weekly、nodeKey（入口周节点）。返回同学员课程服务、当前责任编导且有对象读写权限的候选，包含账号标识、名称/平台快照、version/configVersionId、当前阶段/状态、目标 nodeKey、eligible/reason。只开放同定位轮次、同原定截止时间的未完成周节点；已填、未启动等账号显示不可选原因，无对象权限不暴露账号。
- POST `/admin-api/zsjos/media-account/diagnosis/batch`：accountId/templateType/nodeKey/idempotencyKey/accounts；每个 accounts 项含 accountId 和原有 weekly 提交体，1–100 个不同账号。复用已配置 edit/maintenance 操作权限，对入口和每个目标分别校验对象权限、责任编导、学员课程服务、定位轮次、节点、版本、指标与待办。前端不推断授权范围。
- 按账号 ID 顺序锁定全部目标，复用原周诊断服务，在同一事务内全部提交或全部回滚。每个账号独立追加历史、更新自身阶段/状态、完成自身任务；主诊断记录增加 diagnosisBatchKey/diagnosisBatchFingerprint/diagnosisBatchAccountIds 追溯元数据，无新增表。
- 网络失败保留精确请求及幂等键，原请求重试不重复写入；修改选择或输入后使用新键。同键不同内容拒绝。指标/版本冲突刷新账号与指标但保留人工内容，核对后再次提交。候选及各账号指标分别支持失败重试；移除或切换上下文后的迟到响应不恢复旧账号。关闭未提交草稿需要确认；历史修订仍走单账号路径，不混入新批量。
- 启动诊断复用相同布局，但单独使用 templateType=diagnosis_initial；每项传 initial（原 DiagnosisRequest），不得混入 weekly、周节点或点赞。各账号仍须未启动且已应用有效定位卡；不改变启动诊断的业务前置、定位计时或 S0–S6 行为。
- 新错误 1900011027 表示学员课程服务/定位轮次/节点不一致；1900011028 表示空、重复或超限选择。其余沿用权限、版本、幂等、启动前置和统计变化错误。旧单账号接口保持兼容；Vue Admin 无员工诊断表单消费者。本次不新增依赖、SQL 或角色授权。

## 节点与窗口

使用同一学员课程服务下统一定位轮次锚点的北京时间自然日零点，固定每 7 天一个节点。所有账号包含晚创建账号使用相同定位卡完成时间；实际内容变化的新版定位卡完成学员确认和确认凭证后统一重置。诊断表选“是”、发起修订、无内容变化重复完成及补充凭证不重置；新版完成前保留旧轮诊断计时和填写资格，不按 S6 重新定位状态提前关闭。详见 [账号档案计时契约](media-account-profile.md)。第 1/3 周含 7 天，第 2 周含 7/14 天，第 4 周含 7/14/28 天，后续循环。节点身份为账号、定位轮次、固定截止日期。窗口左闭右开；14/28 天分别向截止前回溯 14/28 天。提前提交不移动日期，原截止前剩余数据仍归原表；逾期填写原表。内部任务继续各自保存，对外待办与数量按周节点聚合，内部命令仍读取全部任务。

仅暴露已经开始的周节点；既有调度提前生成的远期 14/28 天任务不提前开放。旧 taskId 可定位到所属周节点。部分模板已完成时，只完成其余任务，不覆盖已完成旧记录。

## 接口

以下接口位于 `/admin-api/zsjos/media-account/diagnosis`，ADMIN 认证、租户 1，继续使用服务器配置的账号维护/编辑权限和对象权限；统计不是额外的客资明细权限。

| 方法/路径 | 参数与结果 |
| --- | --- |
| GET `/overview` | accountId；返回 `{tasks, nodes}`。tasks 保留当前账号未完成任务及原定截止时间，nodes 仅包含已开放周节点；不计算统计，节点 parts.metric 为空 |
| GET `/nodes` | accountId；返回 Node[]，包含 key/roundKey/week/dueAt/parts/taskIds |
| GET `/preview` | accountId/nodeKey，可选 highestLikes；返回 node 与 metricToken |
| POST `/weekly` | accountId；请求含 nodeKey、common、changeDirection、directionSummary、trafficNormal、highestLikes、metricToken；返回账号新版本 |
| GET `/entry-metrics` | accountId/entryId；返回历史节点的结算及当前成交进展、metricToken |

common 沿用周期诊断字段、version/configVersionId/idempotencyKey；服务端确定模板和周期，不信任客户端关联。修订传 common.previousEntryId，整张综合表追加版本，仅最新节点允许修改账号当前状态。新增三个通用字段必填，方向概况不超过 200 字，字典为现有 infra_boolean_string 并冻结标签；7 天最高点赞为非负整数，0 有效。无 7 天待填部分时无需重复输入点赞。

同节点提交锁定账号及所有任务，复用现有诊断校验，一次更新账号状态；附属模板记录、完成任务与统计同事务。幂等重放不重新更新账号。统计预览变化返回 1900011026，前端刷新指标、保留输入，由用户核对后再次提交。旧 profile/diagnosis 仅接受启动诊断和旧格式历史修订，不能绕过综合表新增必填项。

### 截止时间与填写入口加载

账号任务在数据库查询阶段限定当前受派用户、诊断业务类型、账号及未完成状态，并保留原受派范围、对象编辑权限、责任编导和当前已完成定位轮次校验。单账号读取不再先遍历该用户所有待办；同账号任务复用一次账号及定位计划校验。

Workbench 使用 `/overview` 一次取得截止时间和可填写节点，复用同账号进行中的请求；统计仅在打开所选节点时通过 `/preview` 加载。既有 `/tasks`、`/nodes` 和 `/preview` 保持兼容，`/nodes` 的统计返回不变。Vue Admin 没有员工诊断接口消费者。

点击填写立即显示弹窗及加载状态，加载中提交不可用，重复点击不会创建多条请求链。读取失败在弹窗内保留原因和重试入口；关闭弹窗、切换账号后忽略迟到响应。任务存在但节点未开放时保留原截止时间，明确显示尚未开放并禁用该栏目填写入口，不再统一显示“可提前填写”。已开放节点仍支持截止前填写和逾期补填；开放资格由服务端返回，不由浏览器时间推算。保存、定位来源变更及手动刷新后重新获取当前任务。

加载回归使用 `frontend/workbench/test/diagnosis-loading.py`，既有提交回归使用 `frontend/workbench/test/weekly-account-diagnosis.py`；两者通过实际组件和隔离合成传输验证，不写入真实业务数据，也不代表部署环境耗时。

## 指标与结算

- Metric 包含 state（OPEN/SETTLED/UNAVAILABLE）、reason、asOf、settledAt、发布数量、缺失预计时间数量、有效客资、成交、转化率和点赞汇总覆盖数。自动指标不接受客户端覆盖。
- 发布量按正式提交的作品版本预计发布时间归期，按 contentId 去重，选截止时最新提交版本，排除草稿、撤销/作废；使用批次明确关联账号集合，旧单账号批次兼容主账号。截止后提交/改期不改变历史期间。缺失预计发布时间单独提示，不猜测。
- 有效客资为绑定兼职主体在窗口内提交、在周期结束时 valid/converted/won 的客资；仅使用可靠历史状态事件，不用当前状态反推。历史证据不足则整项为空，不显示部分数量为完整统计。
- 成交为固定有效集合中当前具有生效非复购成交订单证据的去重客资；不套用业绩金额门槛，不以 convertedAt 当成交时间。转化率四位小数，显示两位百分数；零分母或无法统计显示“—”。
- 学员绑定兼职维度，不按媒体账号拆分。无绑定与绑定失效分别提示，均不伪装为零；允许保存人工诊断。尚未结算且未取得绑定时可取得新绑定；已取得来源不自动换成另一兼职，结算后集合固定。
- 提前提交时保留提交快照和 OPEN 统计，原周期结束后由五分钟调度幂等结算。结算失败保存原因并重试；证据不足记 UNAVAILABLE。历史展示分为提交快照与周期结算/当前成交进展，当前进展支持手动及每分钟刷新。
- 28 天最高点赞按同轮次对应四次 7 天诊断取最新修订，加入本次输入；缺失不当零，显示覆盖次数。提交/修订时保存，其他周记录修订不静默改写已结算汇总。

2026-10-22：14/28 天统计按最多 500 个客资 ID 一批读取截止前状态及成交证据，旧事件快照仅对缺少完整状态的客资批量回查。单次提交的预览校验与持久化共用请求内的固定统计时点和读取缓存，重叠窗口复用已读取证据；缓存不跨请求或改写已结算集合。截止后缺少任何客资历史证据仍整项不可用，成交仍按原非复购生效订单口径。固定成员批量幂等插入。
