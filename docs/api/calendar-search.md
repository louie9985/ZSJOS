# 中视简工作台日历跨月份搜索

五类日历分别提供跨月份搜索；默认不限日期。仅 React 员工工作台增加入口，Vue 管理端原有月历接口、请求及响应保持兼容。无需数据库迁移、依赖安装或新增角色授权。

## 接口与数据范围

下表路径均为 `GET /admin-api` 下的业务路径，响应为 `CommonResult<PageResult<原业务记录VO>>`。

| 路径 | 匹配字段 | 继承条件 |
| --- | --- | --- |
| `/zsjos/personal-calendar/search` | 标题、说明 | `readScope=SELF/ALL/USER`、`targetUserId`；默认本人，其他范围复用 System 全量读取校验 |
| `/zsjos/course-calendar/search` | 课程名称、备注 | 当前租户及课程查询权限 |
| `/zsjos/exam-calendar/search` | 考期名称、备注 | 可选 `recordStatus`；单日、多日合并后排序分页 |
| `/zsjos/media-account/calendar/search` | 账号编号、昵称 | `currentStatusValue`、`stageValue`、`directorUserId`、`operatorUserId`；仅日期完整的授权账号 |
| `/zsjos/lead-follow-up-calendar/search` | `leadNo`、姓名、手机号、微信 | 本人负责、本人执行的未完成跟进待办；沿用日历查询和客资查询两项权限 |

所有接口沿用原日历查询权限、租户和逻辑删除约束。个人全量读取不授予编辑权限；账号复用 `MediaAccountCalendarScopeService`；考期普通用户仅见已发布，管理者额外可见草稿及未领取重新编辑、撤销未满五分钟的记录。客资列表仍通过原授权及脱敏投影返回，搜索结果不加载上次跟进，定位后由原日历按权限读取。内部客资 ID 仅用于定位，不作为客资编号展示。

考期搜索的历史名称含 JSON 规格拼接，当前 SQL 解析器不能处理该表达式。仅该搜索的 Mapper 调用使用显式 `tenant_id`（取自服务端上下文）、`deleted=0` 条件替代 SQL 拦截器注入，复用原 `base()` 可见性条件；计数和分页均必须携带相同约束。其他考期接口保持原拦截机制。单语句 `SET_VAR(group_concat_max_len=1048576)` 提示防止较长历史名称被默认聚合长度截断，不修改连接或服务配置。

共同参数：`keyword` 去除首尾空格后必填，最长 100 字；`pageNo` 从 1 开始；`pageSize` 默认 20、最大 100；`sort=nearest|asc|desc`，默认 `nearest`。可选 `rangeStart/rangeEnd` 为 `YYYY-MM-DD`，开始不得晚于结束，未填的一端不限制。

关键词按完整文本包含匹配，多个字段为“或”。使用参数化 `LOCATE`，`%`、`_`、反斜杠均为普通字符，不提供拼音、分词、正则或附件全文检索。旧考期的名称来自原记录的分类、产品及规格标签快照，不查询当前目录标签。

查询、计数、排序和分页在数据库执行。时间按北京时间自然日解释，日期范围包含首尾；跨日记录按区间相交，个人/课程时间段保持结束时刻不包含、零时长归属其所在日的原契约。客资先取每个客资全部未完成跟进任务的最早截止时间，再应用日期过滤；已完成、取消、转移和其他任务类型不进入结果。

`nearest` 按今天到安排区间的最小自然日距离升序，今天占用中的安排距离为零；时间段恰好在午夜结束时，末个占用日为前一日。再按开始日期/时间及内部 ID 升序稳定排序。`asc/desc` 按开始时间升降序，同开始时间按 ID 升序。

## 搜索与定位交互

- 页面顶部“跨月份搜索”打开抽屉；手机适配可用宽度。默认每页 20 条，显示名称、日期、标签、匹配附近的说明摘要和定位按钮。
- 回车或搜索按钮提交关键词及日期条件；排序切换立即查询。显示当前结果实际使用的关键词、日期和页面业务范围。清空关键词清除结果；加载、空结果、错误重试、无权限分别展示。
- 抽屉关闭后在本次页面生命周期内保留条件和页码。业务范围改变清除结果；登录过期、租户/会话存储变化及借视图切换清理搜索状态。旧请求及已取消定位不得覆盖新状态。
- 点击定位重新请求目标日或月份的授权记录，确认目标仍存在；必要时继续读取目标范围后续分页。个人、课程、考期和跟进日历打开当天安排并突出目标，账号日历定位账号行。正在进行的跨日安排定位今天，否则定位开始日。
- 多日考期定位会打开“显示多日考期”；账号定位清空原月内关键词以免隐藏目标，保留其他筛选。客资保留当前卡片排序并打开目标所在页。定位不存在或不再符合条件的结果时保留抽屉，提示失效并刷新搜索第一页；网络错误可再次点击定位重试。

## 验证入口

- `python -X utf8 script/sql/mysql/tools/test_calendar_search.py`：创建独立、保留的本地 MySQL 测试库，实际运行 Mapper 的筛选、分页、排序和隔离测试及相关服务测试。仅写合成测试数据，不修改现有开发数据或删除测试库；输出日志位置，不输出凭据。
- Workbench：`npm test -- src/services/calendarSearch.test.ts src/pages/ExamCalendarRequests.test.ts src/pages/CalendarNavigationRequests.test.ts`，并运行 `npm run typecheck`。
- 隔离 Vite 端口 5241 的 `/test/calendar-search.html` 配合 `python -X utf8 frontend/workbench/test/calendar-search-browser.py` 验证实际组件的桌面、手机、分页定位、失效、重试和请求竞态。测试替换传输，不等同于部署后登录验收。

先发布后端新增接口，再发布工作台；旧客户端不受新增接口影响。共享服务启动、重启或部署须另按仓库授权流程执行。
