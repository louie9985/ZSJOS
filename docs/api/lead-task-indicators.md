# 客资管理逐条待办提示

工作台客资管理主从视图的左侧卡片用流动红色边框标记当前用户待处理的客资，卡片内显示具体任务原因；表格在姓名前显示红点，悬停或键盘聚焦可查看全部任务、截止时间和逾期状态。收起为头像栏仍保留红框和姓名提示中的待办原因。减少动态效果设置下使用静态红框。

## 数据与处理范围

现有 Lead 列表、游标和详情响应增加可选 `pendingTasks` 数组，成员为 `{ id, taskType, title, dueAt, overdue }`。`id` 为内部任务关联标识，不作客资编号展示；客资展示继续使用 `leadNo`。每页批量查询当前用户任务，再与已授权返回的 Lead ID 取交集；详情在既有对象读取授权后查询。Partner 投影不加入 ADMIN 任务。仅用户拥有某客资的读取权限，不代表该客资需要其本人处理。

`MenuTaskSummaryService.getMyLeadReminders` 与菜单摘要共用任务来源、有效处理人和提醒时机：只返回 pending 任务，常规跟进及客资判定须有截止时间且早于北京时间次日零点；首次跟进和协助等其他类型沿用菜单即时提醒规则。同一客资有多项任务时全部保留。显示任务标题快照，缺失时按任务协议类型给出业务名称，不展示内部 ID 兜底。

查看详情、自动选中、切换视图不会完成任务或清除提醒。本地“新客资”未读状态继续独立运行。操作成功、任务失效事件、归属变化、窗口恢复及可见页面每分钟复查后端列表，保持正在编辑的详情和草稿；列表读取失败显示原有错误/重试状态，不将失败当作没有任务。任务完成或取消、处理人变化后的结果以新响应为准。

## 兼容与交付

这是现有 Lead API 的附加只读字段，不新增权限、字典、表、迁移或任务规则。Workbench 使用该字段；Vue Admin 和 H5 忽略未知字段，原操作契约不变。本次不为 Admin 新增视觉提示。后端和工作台需一同部署；旧后端不返回该字段时前端无法显示逐条任务提示。已有历史任务真实性不在本次修复范围，提示忠实反映现有待办记录。

验证入口：`MenuTaskSummaryServiceImplTest`、`LeadManagementServiceImplTest`；`frontend/workbench/test/lead-task-indicators-browser.py` 使用真实页面与隔离传输适配，覆盖桌面/手机、主从/表格、多任务、选中/未读/头像栏、完成/恢复/读取错误、动画与减少动画设置，不写真实业务数据。

## 待办提示与默认排序

工作台不再默认请求 `pendingTasksFirst=true`，也不按本地未读状态重排。全部普通客资列表按 `submittedAt DESC, id DESC`，显式排序继续使用原有字段与方向。待办红框、红点、任务原因和未读标记继续保留。服务端显式待办优先参数保留兼容，游标接口忽略该参数并使用提交时间＋ID协议。

## 红框动画连续性

红色基础边框保持静态，边框遮罩中的光带只通过 transform 连续旋转，每轮 0 到 360 度，首尾同相。遮罩不随帧移动，不再逐帧改变大渐变的 background-position；头像栏使用同一实现。减少动态效果时隐藏光带并释放动画合成提示，保留静态红框。动画调整不改变待办判定或任何业务请求。
