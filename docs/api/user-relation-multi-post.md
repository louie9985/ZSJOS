# 用户关系场景多岗位配置

中视简管理端和员工工作台的用户关系场景，在岗位资格模式下均支持来源岗位、目标岗位多选。候选岗位来自 System `/system/post/simple-list`；工作台不再手输岗位编码。

场景创建、更新、详情、分页及简单列表使用 `sourcePostCodes: string[]` 和 `targetPostCodes: string[]`。每一侧命中任一启用岗位即可进入该侧候选范围；同一用户持有多个岗位时仅出现一次。来源管理仍受原部门范围限制，目标仍要求启用账号；保存关系、实际可分配人员继续使用同一候选规则。岗位配置不会新建、删除或转移已有人员关系，也不授予功能权限。

后端逐项校验岗位存在性并去重；岗位模式不接受空数组或未知岗位。兼容旧单值 `sourcePostCode`、`targetPostCode`：请求省略数组时读取单值，返回数组；已有数据库数组为 NULL 时读取旧单值，显式空数组不回退。新保存保留数组首项作为旧字段兼容值，旧客户端只能理解首项，因此上线必须同步更新两端，不支持旧客户端继续编辑多岗位场景。

功能权限模式维持原目标权限校验，不添加岗位限制。“兼职客资指定分配”的来源仍是 Partner，后端固定按既有接单权限筛选目标；来源不适用岗位，目标仍保留权限模式。这一例外不改成岗位授权。通用工单场景不在本次范围内。

## 数据库与上线

执行 `script/sql/mysql/migrations/V267__user_relation_multi_post.sql` 后再部署后端及两端前端。前置为 V266 后的场景表及两张版本表；仅新增可空 JSON 列 `source_post_codes`、`target_post_codes`，不回填历史业务数据，不修改角色菜单授权。脚本逐列检测并在成功后登记 V267，可重复执行。

回滚保留新增列。已有多岗位配置时，旧程序只能理解首个岗位，不能直接回滚应用；需先评审配置回滚影响。共享测试库执行和服务部署需单独授权。

`schema/core.sql` 和 `00-bootstrap-schema.sql` 同步包含这两列：前者用于迁移漂移检查，后者用于空库初始化，随后仍按原顺序执行待处理迁移。已有数据库由 V267 增列；初始化定义不会修改已有表或业务行，重复迁移跳过已存在列。若 V267 已登记却报告这两列为 unexpected column，应检查运行迁移工具所携带的 schema 是否同步；不能删除业务列或绕过漂移保护。本次同步不改变 V267 文件、版本顺序或已应用校验和，回滚限制与 V267 相同。

验证范围：以共享测试库只读导出的三张相关表结构在独立 MySQL 8.4 建立前置状态，插入隔离验证数据；执行迁移及重复执行，检查两列类型和可空性、两张版本表记录、旧单岗位数据和中文 HEX 保留。该检查不代表已将迁移应用到共享测试库，也不替代整体发布验收。
