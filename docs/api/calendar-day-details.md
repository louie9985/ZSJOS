# 我的日历与课程日历：单日课程详情

2026-10-13：两类工作台日历的单日弹窗统一使用 `CalendarDayTimeline`。
日/周/月导航仍由各页面负责，原有数据范围、只读规则及课程附件权限保持不变。

## 展示与操作

- 当天相关记录完整显示标题和起止时间；跨日记录显示真实跨日日期时间，不用当天裁剪时间替代。
- 桌面按时间轴排列，重叠记录分列；短时记录和长标题可撑高时间格，标题自然换行不省略。
  时间轴按 15 分钟格定位，格高自适应内容，因此卡片像素高度不代表严格时长比例。
  多个重叠课程超出宽度时只在时间轴内横向滚动。
- 手机按时间顺序纵向展示，不按课程时长裁剪名称。
- 点击卡片展开详情，再次点击或使用关闭按钮收起。桌面使用自动调整位置的弹层，
  手机使用详情弹窗。卡片内容变化或删除后，详情从当前服务器响应派生，不保留过期对象副本。
- 修改、删除、发送通知仅出现在详情面板，沿用原有权限。月历格子和单日卡片不再显示这些操作。
  顶部新建入口不属于已有记录操作，仍然保留。
- 课程详情显示创建人、课程形式历史快照、备注、附件；个人日程显示创建人、所属员工和说明。
  链接复用 `LinkedText` 的备注模式，附件复用 `CourseDayAttachments` 和 `AttachmentCard`，
  保留签名地址读取、错误重试、图片/文件预览及下载。附件只在展开对应课程时加载。

## 服务端响应

个人及课程列表/搜索响应新增可空 `creatorName`，课程详情查询同样返回。
服务端仅把已有记录的 audit `creator` 中合法正整数作为 ADMIN 用户身份，通过 System
公共 API 批量读取当前姓名，不从当前登录人、所属员工、角色或数字巧合推断。
无记录、非用户审计标记、溢出编号、用户已不可用时不伪造姓名，前端显示“未记录或账号不可用”。
这不是历史姓名快照，也不修改历史数据或通知快照。

既有字段、查询权限、租户过滤和请求契约不变。Vue Admin 继续消费原字段并忽略新增响应字段，
本次不改变其页面交互；Workbench 消费新增字段。后端须部署或重启后才会在真实响应中出现创建人。

## 验证边界

专项 Java 测试覆盖创建人批量读取、未知值、创建人与所属员工分离，以及课程附件/既有字段保留。
浏览器用真实 React 组件和合成接口检查桌面、手机长标题、短课重叠、只读按钮、链接、附件。
这些验证不代表真实账号、存储或企业微信投递验收；没有修改数据库或触发课程通知。

## 课程通知跳转

课程场景额外允许 `business_detail`，考期场景保持 `none`。新站内信及企业微信票据统一
定位 `/calendar/course-calendar?courseId=<id>`。路由仍受菜单授权保护，页面通过既有
`GET /zsjos/course-calendar/{id}` 按当前身份和租户查询；不从通知时间猜测当前日期。
查询成功切到课程当前所在月和日期，自动展开详情，跨月和改期同样适用。
无效编号、课程已删除、无权限、临时失败分别显示提示并提供重试；切换链接后忽略旧请求。
企业微信保留既有一次性、限时票据和登录回跳，不授予额外数据权限。

旧消息保存的 none 动作不回填；已发企业微信消息不重新发送。新代码需要部署，规则配置
不等于部署完成；企业微信工作台基址必须配置且员工可访问，否则适配器只能发普通文本。
