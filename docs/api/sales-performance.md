# 销售业绩设置与统计

## 页面与授权

仅 React 员工工作台提供 `/zsjos/sales-performance` 和 `/zsjos/sales-performance-target`。
Vue Admin 过滤两个无法在 Vue 渲染的组件，仍维护服务端菜单、角色及数据权限。
左侧树来自 System 部门及稳定销售岗位，通过业绩组织配置明确关联销售中心、部门。
组织层级与名称不能推导权限或中心类型。祖先导航节点不授予查询能力。

两页人员树、个人目标设置行及经营分析的个人贡献行仅展示 System 当前启用账号。
贡献列表包含历史订单补入的人员时，也按当前账号状态过滤；停用或不存在的账号不作为人员行返回。
保存个人目标再次检查账号状态，批次内任一人员已停用则整批拒绝，提示刷新后重新设置。
刷新页面数据同时刷新人员树，失效选中项回退到可用节点，失效对象的未保存编辑被清除。
账号重新启用后，在岗位及原有数据权限满足时重新显示。

上述过滤不追溯删除历史事实、目标或修订：部门/中心业绩仍按冻结归属包含历史人员，
已保存个人目标仍纳入所属周期组织汇总；停用且未设置目标的人员不新增目标缺失项。
个人贡献占比以完整部门/中心业绩为分母，已显示行的金额及占比之和可能小于总计。
历史明细和原有授权个人历史查询保持原有口径，当前账号状态不替代历史归属或数据权限。

统计页面需要 `zsjos:sales-performance:query`，本人、部门、中心分别累计
`:self`、`:department`、`:center` 权限，统计基础明细另需 `:detail`。
目标页面需要 `zsjos:sales-performance-target:query`，保存和恢复汇总需要 `:update`，
组织关联需要 `:configure`。写入不继承管理员 tenant-read-all 只读例外。
后端独立执行租户、功能和数据范围检查，历史个人记录进一步检查冻结部门，
避免当前部门授权泄露其调岗前其他部门的记录。
个人查询中，拥有 System 全量数据范围或租户全量只读授权的读者可查看组织归属缺失的历史记录；
功能权限和租户过滤仍生效，此例外不用于将缺失记录分配到部门或中心。完整订单/客资入口保留原授权。
迁移不配置任何 `system_role_menu`，也不修改套餐或真实账号权限。

## 页面时间

总览固定展示五周期目标（上周、本周、本月、本季度、本年）、十一周期业绩
（今日、本周、上周、本月、上月、本季度、本年、近7/30/60/90日）、七周期成交率
（上周、本月、上月、近7/30/60/90日）。分析日期不改变总览。
历史柱状图独立选年，月度漏斗及日历独立选月；工作量默认今日。
所有业务统计使用 Asia/Shanghai，自然周从周一开始。近N日包含今日。
接口日期含首尾日，内部使用左闭右开时间窗，当前周期截止查询时刻。
`periodKey` 固定周期优先于日期；自定义日期清除它。`cumulative=true` 从范围内
可读订单/接收事实的最早时间开始，不使用虚构业务起点。

## 计算

- 两组卡片均提供 `lastWeek`：上周一00:00（含）至本周一00:00（不含），复用上周目标实际指标和自然周期成交率规则。明细传入同一周期；上周接收、本周提交成交不计上周成交。历史期间按当前状态查询，不是周末封存快照。

- 多周期业绩增加“上月”自然月窗口：上月 1 日 00:00（含）至本月 1 日 00:00（不含），按订单提交时间归属；订单状态和人员、部门、中心权限沿用其他业绩周期。
- 订单仅 `effective`，按 `submittedAt` 归属，金额为录单明细实际成交金额合计
  `totalAmount`。驳回、待审、终止及替代旧单排除。退款不回扣该成交金额指标。
- 客单价分子、分母同时排除整单0和0.01，其他金额/订单指标保留它们。
  `Metric.averageAmount/averageOrders` 是实际参与除法的金额和笔数，不能用未剔除的 `amount/orders` 代替；零分母返回 null。
- 产品按明细 `payableAmount` 汇总；单产品内订单去重；产品下钻金额仅为所选产品金额。
- 成交率按统一来源解释：明确无新媒体引流的销售、教务自拓均从所有周期分子、分母和明细排除。
  新媒体引流由销售/教务代录仍归新媒体；关联必须明确记录且正式提供方一致，不依据相等编号或当前岗位猜测。
  原生新媒体、兼职的 recorded=0 不属自拓关联异常。历史未确认或字段冲突仅在满足原有周期候选条件时阻断相关范围。
  Metric 和成交率 Summary 新增 sourceStatus=ready|review_required、sourceReviewCount；后者发生时 converted/denominator/rate 为 null，明细返回空名单和明确状态。
  旧 details 成交率入口报稳定错误码 1900093002；产品/渠道/搜索不得掩盖整体来源异常。财务金额、订单数、客单价继续显示。
  这些状态是业务事实解析结果，不是可编辑字典，也不新增静态权限。历史数据纠正另见 [修复流程](../operations/lead-source-conversion-repair.md)。
- 成交率的成交判定新增单笔首购订单总金额 total_amount >= 1280（元，含1280）；金额为空或不足1280不计成交，不跨订单累计。
  期间新接有效客资仍计入分母；往期接收客资只有满足金额及原有效期条件，才补入月度分子和分母。
  卡片、各周期及成交率下钻共用此规则；成交金额、订单笔数和客单价保持原口径。
- 成交率只使用客资**当前有效归属对应的接收轮次**：当前负责人必须是统计销售，接收记录必须属于当前轮次。
  转给他人、回收后无人接手的客资，同时从原销售分母与分子排除；已成交后再转出也如此，首购订单和往期成交补入不得绕过归属检查。
  新销售按自己的本轮接收时间判断周期；转回原销售时只使用转回轮次，旧轮次不重复计入。同一客资在一个统计集合中去重。
  当前接收关联存在时核对该历史记录、接收人和事件类型；关联缺失时只使用全体销售的真实历史中最新归属变更事件，
  包含回收、释放等无人归属事件，不能只从原销售历史取最近一次接收。不存在或不匹配的记录不猜测归属。
  订单优先核对冻结接收关联；关联缺失时核对订单提交时已发生的最近归属事件，并匹配本轮接收时间。
  个人、部门、中心沿用现有冻结组织及权限范围，再执行上述归属检查；跨部门转派不会让旧轮次留在原部门成交率中。
  来源异常检查在归属、周期及金额候选判断之后执行，已转出客资不再阻断原销售。
- 历史月份成交率随当前归属动态重算，并非月末封存：例如9月接收、10月转出的客资，在10月查询9月时也从原销售分子和分母排除。
  本次仅修正归属判断，接收月份仍按接收时间，未改为客资提交时间；两个口径偶然得到相同数量不代表等价。
  订单成交金额、订单笔数继续按订单正式归属计算。共享接收事实、工作量和接收历史保留真实发生过的旧接收记录。
- 本月/上月成交率分母为当月新接有效客资与往期接收、60日内当月首购成交客资的并集；
  分子为当月新接且当月成交与上述往期成交的并集。60日从对应销售接收时刻开始、截止不含，转派后重新起算。
- 近7/30/60/90日成交率仅观察期间接收的有效客资：截至查询时已首购成交数 / 该批次有效客资数。
  不补入窗口外接收客资、不限制60日成交期限。订单须匹配对应销售与接收时刻，后续转派不能代替原接收记录。
  各周期按客资去重、只计生效首购，以订单提交时间判断成交；复购不增加成交人数。
  有效分母沿用客资当前 valid/converted/won 状态，未构造历史有效性快照。卡片和明细共用人口集合。
- 复购仍计业绩、订单数和客单价，在本页统一归入非引流（含来源汇总、来源下钻及客单价）。
  客单价仅整体、线上引流、非引流三项；不改订单本身的复购类型，也不重写历史归属快照。
  提交客资来源 `internal_new_media/partner` 为引流，`sales_self_sourced` 与 `education_self_sourced` 为非引流；
  V302 把导入时分错来源的员工提交客资订正为 `internal_new_media`，两者同属引流，分组不变。
  其他来源单列未知，不能从名字推断。渠道/产品/分类名称使用业务快照。
- 周目标和月目标独立；季度/年累加3/12个月目标。部门累加个人，中心累加部门。
  人工值与实时自动汇总分开展示；恢复自动汇总不删除修订历史。
  目标不完整或为零时不计算完成率。任意日期区间不擅自分摊目标。
- 跟进按计划到期时间统计，跟单记录按发生时间，漏接来自明确 `timeout` 派单事件，
  不把拒绝或一般任务取消算作漏接。
- 漏斗按所选月接收批次观察截至当前状态；不能混入往期接收本月成交客资。

### 引流/非引流分组的重算范围

`zsjos_performance_attribution.source_group` 在业务事实发生时按当时的 `lead.source_type` 写入。
2026-09-29 之前的历史回填写入时，教务自拓客资仍读作 `internal_new_media`，因此把 331 行归入了
引流。V301 按同一口径用客资当前值重算了这些行，范围有两条硬边界：

- `org_source='frozen'` 的行是事实发生当时的组织快照，属于契约保护的证据，**不重算**；
- 客资已不存在或已软删的行无法判定来源，**不匹配**，不凭猜测补值。

重算只改 `source_group`，不动 `dept_id`/`center_id`、人员、金额与事实时间。

## 历史与快照

新增 `zsjos_performance_org`、`zsjos_performance_target`、`zsjos_performance_revision`、
`zsjos_performance_attribution` 四张租户表。订单、接收、派单、跟进和任务在业务事务内
固化人员、部门、中心等归属；快照写入失败会使所在业务事务失败，不降级到当前组织。
目标记录保留周期所属组织，修改检查版本并记录原因、前后值和操作者。

既有订单不补造组织快照。个人历史可用订单正式销售和当时真实接收历史计算；
部门/中心历史只使用可证明的冻结组织。页面显示归属快照可用起点，个人可读的缺失
组织订单同时显示数量及金额。无快照不代表该团队过去业绩为零。

### 组织来源标注 `org_source`

快照的 `dept_id`/`center_id` 由 `PerformanceSnapshotService.base()` 按「写入当时的用户归属」
填充，并非「业务事实发生当时」的组织。为避免事后补写的历史快照被误当作历史组织证据，
快照新增 `org_source` 列区分两类来源：

- `frozen` — 事实发生时即写入（写入时间与 `received_at` 相距 ≤ 60 分钟），可作为当时组织；
- `current` — 事后批量补写，组织为补写时点的当前归属，不是历史证据。

写入路径（`PerformanceSnapshotService.base()`）统一写 `frozen`；离线补写脚本必须显式写
`current`。既有行由 V279 按同一规则回填。本列只描述来源，不改变任何既有 `dept_id`/
`center_id` 值。旧库不存在组织主数据（`org_department` 仅 4 行且无层级），因此
`current` 行无法进一步还原真实历史组织。

判定任务继续使用已保存的规则期限，本功能不修改业务期限。
保存各判定轮次的有效、无效、逾期和结束结果；恢复后使用该接收轮次最早期限
判断是否迟判。原任务超时取消仍为红色，转派终止责任单列，迟到补判保留迟判数量。
缺失历史过程独立显示浅灰，不能显示为判定成功。圆环分项之和必须等于接收数量。

所有接口在 `/admin-api` 下，返回 CommonResult，列表分页使用 PageResult。

### 报表拆分与十分钟缓存（2026-10-08）

- `lead-workload` 返回 `{asOf,start,end,workload,categories,stages,followUp,categoryTrend}`。
  `lead-calendar` 返回 `{asOf,start,end,calendar,funnel}`，使用月度 start/end，无需传 `calendar=true`；
  保留原日历跨度限制。两个接口沿用统计查询、本人/部门/中心权限、租户和冻结部门范围，不新增权限标识。
- 原 `leads` 保留参数和响应结构，由上述共享计算方法组合；`calendar=false` 仍返回漏斗，日历数组为空。
  新工作台分别请求工作量和月历，切换月份仅重算月历，月历不再加载工作量事实。
  后端须先提供新增接口，再发布消费它们的工作台；旧客户端可以继续调用 `leads`。
- 每个接口请求固定一次 Asia/Shanghai 截止时刻，返回 `asOf`；各接口可独立成功和刷新，时间可能不同。
  历史月业绩保留原数组契约，页面显示该响应成功时间，其余报表显示服务端数据截至时间。
- 缓存仅属于当前挂载的业绩统计页面，离开页面即释放。认证身份和排序后的权限集合隔离缓存实例，
  实例内按接口、统计范围及去除 undefined、排序后的筛选参数建立键，不写 localStorage 或服务端。
  最多保存 32 个成功结果，超限淘汰最久未使用项；空数据也算成功。
- 有效期从响应成功起算 **600 秒**，命中不续期。同条件在途请求去重；取消和失败不缓存；
  迟到响应不能覆盖当前条件或刷新后的结果。有效期内切回直接显示，不发请求、不出现加载占位；
  过期后再次访问查询，页面不设自动轮询。业务变更可通过手动刷新获取。
- 手动刷新清除全部页面报表缓存和在途请求，重新获取组织树；树成功后按有效选中范围加载当前页签。
  保留当前页签和日期筛选，已失效对象由组织树选择规则回退。明细和目标缺失抽屉始终实时请求。
- 账号、租户、模拟身份或已知权限集合变化时释放原缓存。通过既有身份事件、storage/focus 和请求响应检测身份变化；
  收到 401、403 或业绩范围拒绝错误时清除旧结果并展示拒绝状态，避免切页继续显示旧授权数据。
  未收到任何身份/权限更新时，不宣称能即时感知服务端撤权；下次请求仍由后端独立授权。
  本缓存及组织树刷新保留行为仅用于统计页面，不改变目标设置页的加载策略。

### 查询与计算边界

- 报表入口调用 `authorize`，一次解析 `historicalScope`，租户、统计对象及冻结部门条件进入事实 SQL。
  不再针对每条订单、接收或任务调用历史权限服务；本人及可读个人历史归属缺失例外保持不变。
- 金额、笔数、客单价分子分母、来源、产品、贡献金额及历史月份在数据库聚合；待处理和工作量按状态、时间聚合。
  累计区间通过数据库读取授权订单/接收的最早时间，不加载全部事实寻找起点。
- 成交率只读取期间订单、期间接收及候选订单关联的历史接收，在请求内按“客资＋销售＋接收时间”索引，
  并复用相同窗口结果。保留单笔首购金额 1280 元门槛、提供方排除、转派、60 日边界和滚动口径。
  月历只读取对应接收批次的完整判定轮次，继续识别自动来源、迟判、转出及历史过程缺失。

非订单类指标继续使用原通用明细，路由离开时同样关闭，避免抽屉遮挡目标页面。订单类入口采用下述订单专用明细。

## 订单专用明细（2026-10-10）

`GET /admin-api/zsjos/sales-performance/order-details` 返回 `CommonResult<OrderDetailVO.Response>`。
工作台十一周期业绩、经营分析来源/产品项目、个人期间订单及销售个人贡献金额入口统一调用。
历史业绩图与趋势图未新增点击行为；非订单明细和成交率接口保持兼容。Vue Admin 不消费本接口。
无需数据库字段、迁移、依赖或角色授权变更。

### 范围与筛选

沿用 `scopeType/scopeId`、`periodKey` 或 `start/end`、`cumulative`、`pageNo/pageSize`。
`dimension/groupKey` 必须同时提供或同时省略，订单入口仅接受 `source/product/contributor`；
保留原接口的来源键、商品引用与名称快照组合键、贡献人员内部 ID 键。
这些参数是入口的基础限制，附加筛选与其取交集；前端重置筛选不得清除基础限制。
日期优先级、业务时区及左闭右开边界沿用本页契约。

| 附加参数 | 含义 |
| --- | --- |
| sourceKey | 服务端 `options.sources` 中的业绩来源键；复购始终归非引流 |
| orderTypeKey | `options.orderTypes` 中的订单业务类型键，首购/复购沿用订单业务契约 |
| categoryKey | 客资现存选择时分类标签快照键，不声明重建订单发生时的分类 |
| channelKey | ORDER 业绩归属中冻结的渠道标签快照键，不替换为客资当前渠道 |
| productKey | 订单商品引用与名称快照组合键；同引用不同历史名称分别匹配 |
| keyword | 客资 `leadNo` 或订单编号包含匹配，去首尾空白、忽略大小写，最长100字符 |

五个选项维度均为单选可清空，关键词与选项之间为 AND。选项键为服务端不透明键（最长4096字符），
客户端原样回传；未知键得到空结果，不解释为放宽范围。关键词的 `%`、`_` 作为普通字符处理。
历史快照为空的分类、渠道及已有商品行的空名称均单列缺失标签；无商品行的订单保留空商品列表。
所有选项和各选项订单数均来自未附加筛选的完整授权入口范围，不随页码或附加筛选变化。
一个订单多个商品可分别计入多个商品选项，同商品重复明细只计一笔订单。

### 金额、分页与授权

订单范围复用 `PerformanceFactSql.ORDERS` 及原 `PerformanceDetailSql` 的入口下钻条件：仅生效订单、
按提交时间、保留冻结部门/中心授权和历史归属缺失例外。包含首购、复购、0及0.01元订单，
不应用成交率的最低金额、客资来源排除或有效期规则。

普通入口行 `amount=totalAmount`，商品筛选只筛选包含商品的订单，不改变整单金额。
`dimension=product` 时 `amount` 继续为入口原选定产品的 `payableAmount` 合计；`totalAmount` 保留整单金额。
此时追加其他商品筛选只缩小订单集合，不替换原先产品的金额口径。工作台明确显示“所选产品金额”。

数据库完成入口限制、全部附加筛选、总数/金额汇总和分页；商品通过 EXISTS 匹配，避免连接放大金额。
当前页商品批量读取，无逐订单请求。提交时间倒序、订单内部 ID 倒序稳定分页，默认20条、最大100条；
超过末页返回空列表，保留筛选总数和金额。多次查询处于统计 Service 的只读事务内。

Controller 继续要求 `zsjos:sales-performance:query`；Service 累计校验 `:detail` 与本人/人员/部门/中心范围。
所有数据及补充关联查询保留当前租户与逻辑删除限制；租户1是当前业务环境，不移除租户谓词。
分类/渠道/商品选项不会突破授权范围。不存在或已删除的关联客资返回 `leadId/leadNo=null`，不显示详情入口。

### 返回与交互

- `list`：`id/number/leadId/leadNo/sourceLabel/orderTypeLabel/categoryLabel/channelLabel/submittedAt/amount/totalAmount/products`。
  内部 ID 只用于技术关联；客资编号缺失不以 ID 替代。商品返回 `key/ref/label`。
- `total`：附加筛选后的订单数；`filteredSummary={orders,amount}`：整个筛选集合的笔数和金额，不是当前页小计。
- `summary={orders,amount}`：本次查询完整入口范围的汇总。
- `options={sources,orderTypes,categories,channels,products}`：各项为 `{key,label,count}`。
- `asOf/start/end`：实时查询时刻与实际窗口；`amountKind=order|product` 指明金额口径。

顶部始终保留点击入口的原统计金额及订单数，筛选汇总另行展示。完整入口实时汇总与原缓存统计不同时提示刷新，
不承诺跨请求的固定数据库快照；原统计页十分钟缓存机制不变。
入口标题显示原周期或来源/商品/贡献人员，实际范围时间由服务端返回。

订单和客资详情复用成交率的只读渲染器，在同一抽屉切换。入口分别要求订单管理查询权限、客资查询权限，
并经原业务 API 校验对象权限；统计可见不意味着完整业务对象可见。失败提供错误与重试，不跳转或绕过权限。
返回保留列表DOM、筛选、页码和横纵滚动位置；新筛选回到第一页。桌面宽度沿用成交率抽屉，手机占满视口。
路由离开、保留页失活、组织/人员范围切换、页签或权限变化时清理抽屉。

回归入口：`OrderDetailTest`（H2查询、筛选/汇总/授权范围及生产SQL解析器）、`OrderDetailAccessTest`、
`OrderDetailMySqlTest`（已有MySQL数据只读对照，需 `PERFORMANCE_TEST_MYSQL_URL/USER/PASSWORD` 环境变量）；
工作台 `orderDetails.test.ts`、`test/order-details-browser.py` 及成交率浏览器回归。
浏览器脚本使用隔离合成 GET 适配器，不代表部署后认证接口验收。


### 汇总 SQL 解析兼容（2026-10-14）

金额汇总的来源、贡献人及商品分组使用 `CAST(... AS BINARY)` 保留大小写敏感的历史口径，避免一元 `BINARY` 表达式在租户 SQL 解析器中失败。金额、平均金额的零值/0.01 排除规则、部门可见范围、时间窗口及复购来源语义保持不变。

`PerformanceReportParserTest` 用实际 MyBatis 动态绑定和租户拦截器验证五类金额分组及全部/指定/空部门范围，并验证主管分页的普通 offset 参数。设置 `EXCEPTION_QUERY_EXPORT_DIR`（必须位于系统临时目录）可导出拦截后 SQL 与有序参数，供隔离 MySQL 执行；不向业务库写入或导出真实业务数据。运行环境仍需部署后验证分析请求。
