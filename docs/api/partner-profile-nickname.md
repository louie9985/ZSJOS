# 兼职姓名与昵称

`zsjos_partner.name` 是业务姓名；新增 `nickname`（varchar(100)，可空）仅用于 H5 排行榜展示。
历史数据不从姓名补造昵称；未填写昵称的榜单成员统一显示“未设置昵称”，不回退姓名，不再把姓名打码当昵称。
排行榜列表、前三名、本人排名和附近排名使用同一昵称投影。员工参榜仍使用 System 账号昵称，未改变员工身份契约。

## 个人资料与新用户

- `GET /part-api/zsjos/profile/get` 分别返回 `name`、`nickname`；历史 nickname 可为 null。
- `PUT /part-api/zsjos/profile/update` 要求 `name`、`nickname` 均非空且不超过 100 字符，分别去除首尾空白并保存。
- 只能通过已认证 Partner account 定位本人的 Partner；请求不接受目标 Partner ID。
- H5 邀请码激活成功后进入“完善个人信息”。现有激活事务已把邀请码姓名写入 Partner，资料接口将其预填，用户可修改并填写昵称。
- 姓名提示：“请使用真实姓名，方便后续返现财务审核”。保存成功后进入原目标页。加载失败提供重试，未加载成功不能提交。
- 资料页不显示“头像地址”输入框；保留已有头像数据。
- 激活后的补充步骤复用认证后的资料接口，不新增匿名邀请码姓名查询。账号在激活事务成功时已建立；此引导不是后端业务封锁，关闭页面不会撤销激活。
- 个人中心、首页、兼职管理等身份展示继续使用姓名。认证响应旧字段 `user.nickname` 仍表示既有账号显示名（Partner 姓名），不是新增排行榜昵称。

## 媒体、销售与财务边界

媒体大屏继续使用提供方姓名快照；修改昵称不会改变大屏或归属统计。业务记录、通知、返现等既有姓名/姓名快照来源不切换为昵称。
销售负责人查看兼职客资时，提交人姓名、提供方姓名快照和复用同一策略的流转记录均脱敏（例如“张三”→“张*”），指定派单也不豁免兼职姓名。
沿用既有完整身份授权（全局客资查询/负责人部门管理）；其他业务读者仍遵循既有关系策略，不根据角色名称推断权限。
脱敏仅发生在返回投影，绝不改写 Partner 姓名和持久化提供方快照，财务等授权业务仍可使用原始姓名追溯提交方。
Vue Admin 和 React Workbench 的客资列表/详情均消费相同后台字段，不能在客户端反查还原。

旧系统曾允许“昵称”覆盖 `name`，无法仅凭现有字段判断历史值是否真实姓名。本变更不猜测、不批量修复历史姓名；本人可在资料页校正。

## 数据库执行与验证

新增能力使用 `V262__partner_nickname.sql`，按既有迁移发现机制在 V261 后执行；不修改 baseline、旧迁移或顺序。
前提：已有 `zsjos_partner` 及两张 schema version 表。先执行 SQL，再部署后端和 H5。
范围：所有租户的表结构增加一列，无业务行回填、删除或权限修改；新建记录未设置昵称时仍为 NULL。
脚本可重复执行，已有用户设置的昵称保留。回滚应用时保留新增列；删列会损失昵称，不作为回滚步骤。

验证入口：`python script/sql/mysql/tools/test_partner_nickname.py` 创建并保留独立合成数据验证库，检查字段、两张版本表、重复执行、跨租户原姓名保留及中文 HEX。
`--sync-local` 仅适用于经核实的本地 Docker `yudao-mysql/ruoyi-vue-pro`，会执行增量同步、重复执行和字段比较，不可用于远程或共享数据库。
浏览器验证：`python script/verify-partner-nickname-ui.py` 使用现有 H5 开发服务和独立 Chromium 合成接口，覆盖激活引导、资料保存、昵称未设置、重试及 390/1280 宽度；不写真实账号。
