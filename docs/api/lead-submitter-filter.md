# 中视简客资提交人筛选

客资管理的员工与兼职提交人使用独立的筛选字段，账号数字相同不能代表同一身份。
工作台和管理后台共用 `/zsjos/advanced-filter/catalog?scene=lead` 返回的字段及选项。

| 入口 | 员工提交人 | 兼职提交人 |
| --- | --- | --- |
| 高级筛选字段 | `lead.sourceUserId` | `lead.partnerSubmitterId` |
| 普通客资查询参数 | `sourceUserId` | `partnerSubmitterId` |
| 值的来源 | System 可见员工账号编号 | 可见客资关联的兼职主体编号 `zsjos_partner.id` |

工作台的通用高级筛选自动显示两个字段。管理后台的普通查询另提供“员工提交人”和
“兼职提交人”两个下拉框，并保留通用高级筛选。兼职选项为实体业务数据，不属于字典；
前端不能维护静态兼职列表，也不能把兼职主体编号当成账号编号或内部员工编号。
选项加载提供加载、空列表和错误重试状态。

员工高级筛选保留原 fieldKey 和数字值，历史个人及系统筛选模板无需改写。员工身份
以客资已记录的 `provider_owner_type` 区分：兼职类型、有兼职主体的记录、未知身份
类型和身份不明的旧兼职来源记录不会参与员工账号匹配。旧记录未保存提供方类型、
没有兼职主体且来源不是兼职时，仍按已有员工提交账号兼容。
历史 `source_type='partner'`、`provider_owner_type='system_user'` 的员工提交记录
仍属于员工筛选，不能仅凭来源类型排除。V302 已把这批导入客资的 `source_type` 订正为
`internal_new_media`，与 `provider_owner_type` 一致；上述兼容分支保留，用于未升级
环境及任何残留的历史形态。

销售/教务自拓的员工高级筛选保留既有口径：明确记录新媒体提供方时使用
`source_provider_user_id`，否则使用 `source_user_id`。普通 `sourceUserId` 查询
保留原来直接匹配 `source_user_id` 的口径，并增加员工身份边界。

兼职筛选只匹配 `provider_owner_type='partner'` 的兼职主体 `partner_id`。
使用兼职主体而不是多态账号列，避免编号碰撞，并可查询缺失历史提交账号但已明确
兼职主体的记录。高级筛选支持属于、不属于、为空、不为空；不属于仍遵循现有 SQL
空值语义，不把另一身份的记录自动视为该身份下“不属于”。两个普通参数同时传入时
取交集，不会把它们合并成一个无身份的数字列表；高级筛选仍可用 OR 组合两类字段。

`visible-lead-partners` 由后端在目录响应中解析，`optionSourceType=business_api`，
`declaredOptionSource` 保留来源，解析后 `optionSource=null`，空选项为 `empty`。
候选只来自当前租户、未删除且位于现有客资管理可见范围中的兼职身份客资；配置的
全量读取能力按既有规则生效，没有可见范围时返回空列表。兼职主体读取保留租户和
逻辑删除边界；名称沿用 `LeadIdentityMaskingService`，销售负责人不能通过选项
读取本应脱敏的兼职姓名。

筛选仅缩小查询结果，不扩大客资、详情或导出权限。分页总数由相同查询产生；游标
搜索复用分页查询；客资导出通过 `LeadExportTypeProvider` 复用客资管理服务。
`status-counts` 是现有关系范围概览，不接收普通或高级筛选参数，本次不改变其口径。

同号回归例：员工账号 50 与兼职账号 50 分属不同身份空间。选择员工提交人时不能
匹配兼职客资；选择对应兼职主体时仍可查询其客资。LD202609070088 等已正确关联的
客资不需要改号。本次为源码修改，需要单独部署后才能改变测试服务的页面与查询。

V303 把六批历史客资与订单上仍指向已停用重复账号的提交人/提供方（232 陈薇、259 莫才巧、
54 钟茂源、415 汪雅琪、418 梁颖、524 汪雅琪2）改指到接收同一人的在职账号（20、19、27、
51、400、30），因此这些记录重新可以被员工提交人筛选和提交人范围的订单查询命中，列表也
不再显示“未知账号”。同号兼职客资（`source_user_id=54` 且 `provider_owner_type='partner'`，
那里 54 是兼职账号编号）未被改动，同号边界不变。


2026-10-10：新媒体代录的新建客资使用 internal_new_media 和所选员工 source_user_id；
高级筛选和普通 sourceUserId 因而一致匹配该员工。V309 固定名单纠正 16 条原销售提交人，
其余历史自拓兼容筛选保留，不能按提供方非空扩大迁移范围。
