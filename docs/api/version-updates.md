# 版本更新通知

版本更新通知是中世健独立业务功能，归属 `yudao-module-zsjos`。工作台提供发布管理、右上角更新记录及自动弹窗。用户、部门、权限通过 System 公共 API 获取，文件通过 Infra 公共 API 存储。

## 页面和权限

| 用途 | 工作台路径 | 权限 |
| --- | --- | --- |
| 发布管理 | `/zsjos/version-updates` | `zsjos:version-update:query` |
| 更新记录与右上角入口 | `/zsjos/version-update-history` | `zsjos:version-update:read` |
| 新建、编辑、发布、下线 | 发布管理中的按钮 | 前缀加 `create`、`update`、`publish`、`offline` |
| 知悉 | 接收弹窗中的按钮 | `zsjos:version-update:acknowledge` |

V369 创建两个页面菜单和五个按钮权限。两个页面使用 `zsjos-workbench` 组件标记，Vue Admin 现有路由过滤器会过滤这些工作台页面。更新记录页面菜单默认隐藏，接收入口在工作台设置旁。角色授权由系统角色管理配置。接收候选人员需同时具备更新记录和知悉权限。

管理查询权限覆盖当前租户本功能的管理记录，命令同时校验对应按钮权限。Service 对对象命令执行 `@ZsjosPermission` 检查。员工查询和知悉操作同时检查当前租户、登录用户及发布时的接收关系。部署租户为 1。

## 生命周期与存储

`zsjos_version_update` 保存草稿正文、附件及正文图片的文件编号、选择的人员编号和发布人快照。`zsjos_version_update_recipient` 保存发布时人员与部门快照、首次知悉时间。唯一键为 `(tenant_id, update_id, user_id)`。

草稿可以编辑。发布在事务中锁定记录、重新校验接收资格、固定名单并保存发布状态。已发布记录再次发布直接返回成功。下线后停止弹窗并从员工更新记录撤下，管理端继续保留记录和知悉统计。已发布及已下线内容保持冻结。

知悉命令与下线共用记录锁。只有发布时间有效且当前用户属于固定名单时才可确认。条件更新仅写入空的知悉时间，重复请求保留首次时间。查看内容不写知悉时间。

正文上传图片保存为内部文件引用，返回详情时重新生成签名地址。文件引用在保存时校验上传人和独立业务目录，编辑时允许沿用原已绑定文件。文件存储短暂不可用时保留正文与知悉功能。

## 接口

所有接口使用 ADMIN 认证和标准响应包装，前缀为 `/admin-api/zsjos/version-update`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/page` | 管理分页，支持 keyword、status |
| GET | `/recipient-options` | 部门树与员工选择项 |
| POST | `/create` | 保存草稿 |
| GET / PUT | `/{id}` | 管理详情、编辑草稿 |
| POST | `/{id}/publish` | 发布并固定接收名单 |
| POST | `/{id}/offline` | 下线 |
| GET | `/{id}/recipients` | 接收及知悉明细，pending=true 筛选待知悉 |
| POST | `/attachment` | multipart file 上传，最多 100 MB，保存时附件最多 10 个 |
| GET | `/my-page` | 当前人员已发布更新记录，pending=true 筛选待知悉 |
| GET | `/my/{id}` | 当前人员详情 |
| POST | `/my/{id}/acknowledge` | 确认知悉 |

分页参数为 pageNo、pageSize。保存正文包含 title、content、targetUserIds、attachmentIds 和 inlineFiles。inlineFiles 是编辑器本次上传的图片编号与临时地址映射，服务端会转换为已校验的文件引用。人员选择的父节点只负责勾选交互，实际提交去重后的人员编号。

稳定错误码 `1900080001` 至 `1900080006` 分别表示记录不存在、权限不足、状态变化、接收资格失效、文件无效、正文为空。

## 工作台交互

登录、WebSocket 重连、窗口重新获得焦点和可见页面的每分钟检查会查询待知悉记录。事务提交后的 `version-update-changed` 事件触发补查。记录按发布时间倒序呈现，多个待知悉版本依次展示。全局弹窗协调器与现有可见弹窗检测延后自动弹出，强制表单出现时暂停显示版本弹窗。

点击“我已知悉，关闭”后先提交服务器。成功后播放 460ms 缩小移动至右上角更新记录按钮的动画并短暂高亮入口。系统设置减少动态效果时使用 120ms 淡出。失败保留当前内容和重试入口，重新加载详情后允许再次提交。

更新记录按批追加加载，已知悉记录可再次查看。每个用户的知悉状态保存在服务器。每次登录重新查询，账号切换时重建入口状态。

## 迁移与验证

V369 在 V368 后执行，新增两张空表与七条菜单/按钮元数据。DDL 可重复执行，结构和菜单检查通过后才在同一事务中写入两本版本账。DDL 隐式提交，因此回滚运行时需保留新增表和历史知悉数据。

`script/sql/mysql/tools/test_version_updates.py` 在本地 MySQL 8.4 的独立合成数据库验证首次执行、重复、缺少前置版本、部分 DDL 恢复、账本失败恢复、菜单冲突、UTF-8、接收关系唯一键及首次知悉时间。带 `--apply-local` 时仅面向本地容器 `yudao-mysql` 的 `ruoyi-vue-pro`，并比对结构与原角色授权指纹。

本次本地验收完成工作台构建、7 项后端测试、33 项工作台菜单测试及 9 项 Admin 过滤测试。浏览器使用实际组件和合成接口数据完成桌面/手机交互检查。独立空库快照执行至 V369 并通过迁移账本和新表结构比对。真实账号 HTTP、文件存储及 WebSocket 联调需在更新后的后端服务运行时完成。

版本更新弹窗、历史详情和管理详情中的正文图片支持点击或键盘 Enter/空格打开大图预览，可缩放和切换多张图片。关闭图片预览后继续阅读与确认知悉。
