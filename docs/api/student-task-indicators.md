# 学员管理逐条待办提醒

教学学员管理以 serviceRelationId 为行标识。现有服务分页/详情响应增加 pendingTasks（id、taskType、title、dueAt、overdue），只返回当前登录用户、当前租户的 pending 业务任务，并与已授权返回的课程服务取交集。不同课程服务即使属于同一学员，也分别计算；现有 summary.currentTask 可能属于他人，不能代替个人待办来源。支持同服务的多个任务与首联协助。

主从卡片显示流动红框和具体待办原因，收起头像仍有红框及无障碍提示；表格姓名旁显示红点，悬停/聚焦列出全部原因、截止和逾期。复用客资管理的固定遮罩/连续旋转合成层动画；减少动画时只保留静态红框。查看详情不清任务。

工作台分页请求 pendingTasksFirst=true：后端先按当前用户符合提醒时机的待办服务置顶，再按接收时间 `acceptedAt DESC` 与稳定 ID 倒序排序，最后分页；无接收时间的记录在各组内排后。显式列排序保留待办优先，组内使用所选字段和方向，恢复默认排序后回到接收时间倒序；权限、关键词、课程、班级及高级筛选不变。仅有未来任务的服务不因待办置顶。任务完成/取消后下次读取恢复原排序。当前页操作成功刷新列表/详情，任务失效本地事件、页面恢复、可见页每分钟刷新列表并保留正在编辑的详情。管理员查看他人数据不将他人任务算作自己的待办。

2026-10-22 调整：菜单红点、列表红点/卡片红框及待办置顶共用 student_service 提醒口径。有截止时间的任务仅在截止时间早于北京时间次日零点时计入，即今日及逾期待办均提示，未来待办不计入；当日尚未到具体截止时刻的任务也计入。无截止时间的即时待办继续提示。此规则覆盖学员首联、学习计划、跟进、首联协助及交付阶段任务，不改变客资原有的分类型提醒规则。

未来任务仍保留在任务列表及未来待办统计中，到应处理日后的下一次读取自动进入提醒；不修改任务的生成、排期、完成或历史数据。Admin 使用相同服务接口但不消费 pendingTasks，也不默认启用置顶；H5 不接入，媒体学员管理不在本次范围。本次时间口径调整仅需更新后端，现有工作台按后端响应显示；未执行部署、权限授权或历史任务修复。
