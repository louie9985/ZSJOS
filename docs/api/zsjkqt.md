# 中世健考勤通 API 与数据契约

考勤通作为 React 工作台 HRM 下的原生应用运行，公开页面路径为 `/hrm/zsjkqt`。现有 HRM 业务页面和数据不参与考勤计算；考勤通独立持有月报快照、草稿、人员修订资料和部门时段配置。

## 登录与权限

全部接口使用既有 ADMIN 登录、`/admin-api` 前缀和租户上下文；当前业务租户为 `1`。菜单及前后端使用同一个权限 `zsjos:zsjkqt:access`。拥有该权限的用户可访问本租户全部考勤通数据并执行全部考勤通操作，不按创建者或部门切分数据，也不派生其他 HRM 权限。

Controller 和 Service 均校验该权限；草稿对象操作另外检查当前租户下的对象是否存在以及操作是否合法。更新、重命名、删除和导出需要匹配版本，功能权限不能绕过版本冲突。操作账号用于审计，不是草稿归属者。

V347 只定义 HRM 原生子菜单及权限元数据，不写入 `system_role_menu`。管理员通过系统角色管理分配权限。现有 HRM 父菜单可继续保留 `admin_embed`；考勤通子菜单明确配置为 `native`，`component=zsjos-workbench`、`componentName=Zsjkqt`、相对路径 `zsjkqt`。既有 Vue Admin 菜单过滤会排除这个工作台专用组件标记；React 由 `/hrm/zsjkqt` 路径装配页面。两端仍消费同一服务端菜单和权限来源。

## 接口

以下路径均相对于 `/admin-api/zsjos/zsjkqt`。除文件下载外，返回既有 `CommonResult` 包装。

| 方法及路径 | 请求 | 结果与语义 |
| --- | --- | --- |
| `GET /drafts` | `pageNo`、`pageSize`、可选 `keyword/year/month` | 服务端按最近修改时间和 ID 倒序分页；同月允许多个项目 |
| `GET /drafts/{id}` | 草稿 ID | 完整草稿、版本和快照 |
| `POST /drafts` | `clientId/name/version/snapshot` | 创建独立项目；同标识、同名称及同快照的重试幂等返回，否则报告冲突 |
| `PUT /drafts/{id}` | `clientId/name/version/snapshot` | 在指定版本上保存；不覆盖其他人的后续修改 |
| `PUT /drafts/{id}/name` | `name/version` | 重命名并推进版本 |
| `DELETE /drafts/{id}` | 查询参数 `version` | 逻辑删除该草稿；不删除配置和其他项目 |
| `GET /config/schedules` | 无 | 部门时段及配置版本 |
| `GET /config/profiles` | 无 | 考勤通内部人员修订资料及版本 |
| `PUT /config/schedules` | `version/value` | 校验时段结构及冲突后保存公共设置 |
| `PUT /profiles` | `key/name/department/entryDate/enabled` | 按考勤源标识维护内部修订资料；不更新 HRM 员工 |
| `POST /parse/source` | multipart `file` | Java 解析企业微信月报，返回源人员、每日明细和原始汇总 |
| `POST /parse/report` | multipart `file` | Java 解析考勤通正式汇总表，恢复原导出值及月度参数 |
| `GET /drafts/{id}/export/report` | 查询参数 `version` | 从匹配版本的已保存草稿导出正式汇总表 |
| `GET /drafts/{id}/export/issues` | 查询参数 `version` | 从匹配版本的已保存草稿导出异常清单 |

解析只接受 `.xlsx`，单次上传上限为 20MB。请求/响应载荷不进入普通 API 参数日志。上传解析后，源文件名、SHA-256 和解析事实随草稿保存；原始 Excel 字节不作为人员或历史草稿初始化数据导入。

## 草稿快照与并发

`zsjkqt_draft` 保存项目名称、年月、源文件标识、确认进度、版本及完整编辑快照。`clientId` 在租户内唯一，不能以文件哈希或年月作为唯一项目键。同一文件可另存副本，同月不同文件可以独立保存。删除后的历史项目不会因重复保存而复活。修改人展示使用服务端记录的姓名快照 `updaterName`；内部账号标识 `updater` 保持审计用途。

首次创建发生同一 `clientId` 的并发重试时，唯一键冲突后通过当前锁定读取核对已提交草稿；同名称、同快照返回原记录，不同内容或已删除记录仍报冲突。其他唯一约束错误不冒充幂等重试。另存副本为名称后缀预留长度，保留原项目名称，生成名称始终不超过 120 个字符。

快照带有 `schemaVersion`，包含源月报、项目、当前流程阶段、月度参数、部门时段及人工修订状态。每日系统值与最终值、汇总人工覆盖标识、确认状态均需保留；续改参数候选 `recoveredParameters`、当前员工索引、筛选、搜索、休息日编辑类型和源文件显示路径也随编辑状态恢复。可选 `personnelProfiles` 冻结这份草稿建立时使用的人员修订输入，使仍停留在参数阶段的草稿也不会因公共资料后来变化而生成不同人员信息；新导入读取最新公共资料。打开草稿使用保存的快照，不通过重新解析源文件或当前公共配置补造历史计算结果。

客户端对同一草稿串行保存；服务器用版本条件更新。冲突后保留当前页面修改，允许重新加载服务器版本或另存副本。导出前先保存，导出接口再次校验版本，避免下载到并发写入后的另一份结果。导出不会锁定或删除草稿。

源月报的员工行身份包含原始行序号，人员资料仍按原账号、缺账号时按原姓名查找。快照中的可选 `profileKey` 保存这个配置查找键，不能改用界面行键。打开旧草稿时只规范化行键并保留旧配置键、人工值及确认状态，不合并同名员工；参数重建也按独立行保留人工修订。未确认筛选下保存当前员工后，在保存后的列表中定位原下一位员工，不因当前行消失而跳过一人。

## 规则与 Excel 兼容

原 TypeScript 考勤分类、汇总计算、人工覆盖和参数重建逻辑继续在考勤通核心目录维护。Java Excel 引擎负责解析和写出，不重新计算或静默覆盖人工修订值。输入校验属于服务端边界，不能改变已经确认的业务公式。

正式表保留年月工作表名、日期列、列顺序、人员分组排序、状态文字/颜色、汇总字段以及 `_attendance_metadata` 隐藏元数据。旧元数据格式保持读取兼容；元数据缺失或无效时沿用原候选推断和提示流程。无年份的旧工作表名仍按原规则拒绝。源文件名缺少完整日期、仅含旧统计区间时的年份处理沿用桌面基准，不自行推断当前年份。

休息日元数据必须落在表内实际年月；例如二月的 31 日视为无效元数据，提示后改用原有候选推断，不将不可见日期带进草稿，也不重算导入的员工汇总。核心原已产生的“陪产假”“产检假”状态在编辑、保存和正式表回读中一致保留，不合并假别或变更计算公式。

Excel 文本单元格最多 32767 个字符。编辑汇总时提示超限，保存检查原始文本及异常导出的合并备注；历史草稿导出也返回明确错误，均不静默截断人工内容。续改月度参数仍按原规则更新每位员工的应出勤日、计薪日及对应人工覆盖标记，其他汇总保持原值；页面提示明确这两个字段的变化。

原始测试和 Java 对应用例见 [测试迁移清单](../testing/zsjkqt/README.md)。

## 数据迁移与上线

新环境 baseline 与 core desired schema 同步包含 `zsjkqt_draft` 和 `zsjkqt_config`，V347 为升级环境补建同结构，并负责配置、菜单和版本记录。草稿从空开始；人员资料从空开始，等待用户后续提供初始数据。部门时段取自桌面应用实际读取的配置，保存为后端资源并由迁移脚本初始化；默认时段、自定义时段和继承模式一起保留。重复执行不覆盖已经维护的配置。

迁移依赖 System 菜单表、两本版本账本以及唯一启用的 HRM 根目录，按现有 core 编号迁移顺序执行。脚本在写入成功版本前检查前置条件、表结构和配置；DDL 会隐式提交，失败后应检查实际对象及两本账本，再修复原因并重放。应用回退保留数据表和草稿，不提供破坏性回滚。

V347 的开发阶段校验修正核对两个唯一索引的准确列、顺序及完整列长度，并要求初始化配置未逻辑删除。发现既有配置被删除时明确失败，保留管理员意图，不自动复活配置。此源文件修正不更新已登记的迁移 checksum；本地已有结构的只读核对、受控恢复验证及后续部署兼容范围须分别记录，不以重写历史账本消除差异。

部署需同时包含 Java 后端、React 工作台及 V347。源代码测试、隔离数据库验证、本地开发库同步、角色授权和真实账号验收是不同步骤，具体执行状态以 [迁移工作记录](../../handoff/local-zsjkqt-migration-20261022.md) 为准。

2026-10-22 的 V347 限定验证及本地开发库同步已通过，现有角色授权保持不变。全链交付仍有仓库其他改动的阻塞：静态检查缺少 `zsjos_account_diagnosis_metric`、`zsjos_student_entry_command` 的 core schema 映射；独立执行的完整 fresh 链到 PMS V002 时提示 `PMS V002 requires PMS V001`。已通过的 V019→V021 升级检查仅证明其限定范围，不代表完整升级链通过。详见 [验证边界](../testing/zsjkqt/README.md#2026-10-22-验证边界)。

## 从首页导入休息日

首次月度参数和正式表续改参数页可按当前考勤年月读取 `GET /zsjos/calendar-rest-day/list`，沿用其 `zsjos:business-task:query` 权限（未授权显示说明并禁用）。只读取当月 `rest=true` 的日期，不按周末推测，不回写首页。首页未区分带薪与普通；操作人可选择导入类型，默认普通。导入仅补充两类均未设置的日期，已有分类优先；重复导入不重复添加、不清空已有值。空数据、失败与重试均在入口提示。导入后仍可逐日调整，结果随当前项目快照保存，并沿用原有生成/续改参数生效流程。

月度参数页在宽面板下将参数及导入控件放左侧、休息日日历放右侧；窄面板按上下排列。原生输入框样式排除 Ant Design Select 内部输入元素，避免选中类型文字被裁切。
