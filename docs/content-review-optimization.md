# 内容审核流程说明

本文件旧版“解冻历史版本后退回”以及“混合结论终审通过”示例已作废。
当前契约以 [生产内容批审 API](api/content-review-batch.md) 为准。

编导与终审均必须逐条审完；全部通过才允许整批通过，有不通过项只能整批退回运营。
工作台提供明确的通过和退回按钮，BPM 通用入口执行相同业务校验。
运营从原记录回填修改，同一作品建立新版本、每次退回仅建立一个修订草稿；后续保存更新同一草稿，重新提交直接从编导开始。旧轮次进入历史，不再占用待修改列表。
历史提交保持冻结；取消与拒绝分别落地；退回不生成素材，通过才生成待发布与所选素材。

运行版本与源码版本必须区分：完成本地编译和测试不代表测试站点已更新。
发布前须验证目标站点的流程定义、候选人、授权及运营→编导→终审→退回重提全链路。
