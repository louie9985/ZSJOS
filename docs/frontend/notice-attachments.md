# 公告附件

员工工作台的公告编辑、管理详情/预览及「我的公告」详情统一复用 `AttachmentCard`，公告适配层为 `NoticeAttachments`。

- 图片显示缩略图和大图预览，PDF 使用通用内嵌预览；Office、ZIP 沿用通用组件的类型图标和下载，不承诺在线预览。
- 用户详情通过现有公告阅读 API 刷新附件地址；管理详情通过管理查询 API 刷新。预览、下载、失败重试均重新获取服务端授权后的地址。文件被移除或地址不可用时显示错误，不回退到旧地址。
- 编辑器和未保存的公告预览使用当前上传响应中的附件地址，避免重新读取服务端草稿而丢失未保存附件。长时间编辑导致地址过期时需重新打开已保存草稿，未保存附件需重新上传。
- 上传继续使用公告专用接口，即时上传，支持通用剪贴板截图入口。单个附件上限 100 MB（100 × 1024 × 1024 字节），保留最多 10 个、现有文件格式白名单、上传中禁止保存/关闭、失败项处理及创建/修改权限控制。
- 无附件时详情不展示空附件区。不修改后端、权限、存储及 Vue 管理端契约。

草稿附件保存由 System 公告服务在事务中处理，React 工作台与 Vue 管理端沿用同一创建、修改和发布 API。再次保存或发布前保存草稿时，仍被保留的附件复用原关联并更新排序；仅对移除的附件关联执行逻辑删除，不删除 Infra 文件。合法的同一上传文件移除后再添加时，恢复原关联，避免逻辑删除记录继续占用唯一键而导致保存失败。已删除的关联不作为文件使用权限依据，重新添加仍须通过现有上传归属校验。

复制已发布公告时，副本持有独立的附件关联，并继续引用同一 Infra 文件。有公告编辑权限的其他编辑人可保留副本中已有的附件，连续保存后发布；原公告的正文、发布状态和附件关联不变。`NoticeServiceImplTest.shouldSaveAndPublishCopiedAttachmentsWithoutChangingPublishedSource` 覆盖此路径；被移除的他人附件仍不能借历史关联重新添加。

排查“复制草稿后保存、发布均显示系统异常”时，需检查后端运行版本是否包含附件关联复用修复（`d2f836006f`）。两个编辑器的发布流程都会先保存，旧版本的附件唯一键冲突会同时阻断这两个入口。该修复不需要清空草稿、删除附件或修改数据库唯一键；源码合并与本地测试通过不表示目标环境已经部署生效。
