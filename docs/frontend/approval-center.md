# 中世健审批中心同页审批

审批中心保留待办／已办切换，详情内部不再使用页签。业务字段、理由、附件位于左侧；右侧按服务端节点顺序连续展示处理人、时间、结果、意见、签名、附件和流程评论。任务 ID 用于归并，名称不用于去重；加签子任务按父任务归属，未覆盖任务保留在补充流转记录中。需求审批使用任务所属轮次业务快照。

## 布局

桌面详情为 9:3 分栏，正文和右侧历史独立滚动，操作区在右栏底部。以详情容器 1100px 为切换边界；窄容器按业务、流程、评论依次展示，通过“处理审批”展开操作区。同一任务只有一个详情实例，表格和移动场景使用现有详情抽屉。样式仅作用于审批中心，内容审核等其他 BPM 消费者保持原布局。

## 操作与草稿

通过／拒绝直接填写意见，沿用节点 reasonRequire、signEnable 及 500 字限制，校验后确认提交。转办、委派、加签、减签、退回、抄送保留原弹窗和接口。节点配置、任务匹配、任务状态及 bpm:task:update 权限共同决定可处理性；已办只读。评论输入保留在流程评论区域，独立于审批意见。

草稿仅存在于当前任务的页面内存。任务切换、搜索、关闭抽屉、工作台关闭守卫、浏览器返回和同源链接离开均检查未提交输入；提交中阻止离开。刷新保留草稿，失败保留输入及明确错误。终结或移交任务的动作成功后保留当前结果，提供下一条待办；抄送、加减签等非终结操作仅刷新，不自动切换下一条。

## 数据与验证

详情、业务卡、流转记录和评论独立加载、重试，请求序号防止旧响应覆盖最新数据；失败不展示为正常空列表。业务卡不支持时仍保留既有表单兜底，业务读取失败明确提示。无新增接口、依赖、SQL、角色授权或 Admin 修改。

验证入口：npm run typecheck；定向 Vitest approvalHistoryModel、bpm-approval-labels.guard 和 bpm-approval-actions.guard；python test/approval-center-layout-browser.py（使用既有本地 Vite 5174，全部请求在 fixture adapter 内终止）。浏览器覆盖 1920/1440/1024/768/390、表格抽屉、需求审批、签名必需、草稿保护、失败重试、评论、已办和深色主题。fixture 是隔离组件证据，不代表已登录运行环境或生产审批验收。
