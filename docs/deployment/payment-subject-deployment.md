# 中世健支付主体路由部署说明

更新日期：2026-09-21。本版替换原“未配置及冲突均读取管理员默认主体”的规则。接口及页面归属见[支付主体 API](../api/payment-subject.md)。

## 变更范围

- 未配置产品使用当前租户 `school`；相同主体按配置；任何不同主体的组合整笔使用当前租户 `company`。
- 使用现有 `zsjos_payment_subject`、`zsjos_product_payment_subject.payment_subject_id` 和支付单 `subject_snapshot_json`。不改表、不补写产品关联、不重跑 V239–V242、不新增依赖、不改菜单或角色授权。
- `isDefault` 保留兼容，不影响本支付路由。主体候选来自后台业务 API；权限由管理员通过系统角色管理分配，不能由部署 SQL 写入角色授权。
- Vue Admin 提供配置页面，Workbench 通过既有 admin_embed 使用；本次发布后端和更新后的 Admin。

## 发布前检查与顺序

1. 只读检查目标租户 `school/company` 编码、启用状态、商户及签名配置。只依赖单一其他主体的支付不要求学校/公司存在；要完整支持默认和冲突场景，应保证两者有效。更改显示名称不影响编码路由，更改编码会影响新链接。
2. 通过 UTF-8 客户端执行 `script/sql/mysql/tools/payment_subject_audit.sql`。前置条件为现有主体、产品关联、支付单及网关事件表；默认租户 1，其他租户先在同一会话设置 `@payment_audit_tenant`。脚本仅 SELECT 和会话设置，可重复执行，无需回滚。
3. 审计分别输出学校/公司存在、启用和凭据完整性的计数，以及失效关联和历史快照检查。SQL 不验证 RSA 格式和真实通联授权，不输出密钥、令牌或完整快照；本地审计不能替代目标环境审计。
4. 完成后端定向测试、Admin 类型检查及构建，再通过受控发布流程加载后端并交付 Admin。仅刷新页面不会加载后端改动。服务重启、远程部署及真实账户配置变更需有对应目标和影响的授权。
5. 核对真实目标环境新生成链接的商户及通联授权、回调地址、实际密钥匹配；分别验收学校、公司、主体冲突转公司和原路退款。

## 支付主体路由修复发布说明（2026-09-18）

本节保留历史链接锚点；当前选路规则以上述 2026-09-21 约定为准，历史交易仍遵守快照边界。

### 存量订单处理

- 已生成的 `created/waiting/paid` 链接继续使用原主体快照，不批量切换。
- 未向通联下单且为 `created`：需要切换时通过现有取消链接操作作废，再按新规则生成；不要直接修改快照或删除订单。
- 已有通联请求号、状态等待确认：按冻结的原商户查单，确认未付款并关闭交易后才能重建；状态不确定或关单失败时保持锁定。
- 已付款：保留真实收款事实，原路退款继续沿用原商户；修改产品配置不会转移已收资金。
- 快照缺失、损坏或与实际商户不符：明确报错；核对网关和平台记录，备份并另行确认具体修复范围、证据和恢复方式。禁止用当前配置批量覆盖历史快照。
- 密钥轮换或平台撤销旧密钥需独立评审，不自动改写历史凭据。

### 验证与回退边界

后端运行 `PaymentSubject*Test`、`PublicPaymentDetailTest`、`PurchaseIntentCancelPaymentTest`，覆盖规则矩阵、异常、租户隔离、快照冻结/复用/取消重建、网关支付/查单/关单/退款和回调。网关自动测试只使用本机合成数据，不请求真实通联。

Admin 运行 `node --test tests/paymentSubjectApi.test.ts`、`pnpm ts:check` 和 `pnpm build:local`；浏览器检查原生页面及 Workbench 嵌入入口的规则提示、配置/未配置/异常、权限、失败重试。隔离夹具仅用于 UI 验证，不能替代真实账号和支付通道验收。

无需 schema 回滚。回退到本次变更前版本会恢复“冲突走管理员默认主体”的新单行为，但已有支付单仍必须使用冻结快照；禁止回退到不支持主体快照的旧实现。回退不修改已收资金归属，也不作为异常快照的数据修复方式。
