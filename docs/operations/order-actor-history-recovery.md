# 中视界历史订单人员恢复

本修复恢复旧系统已有的人员展示证据，不改变成交归属、提交人 ID、金额、订单生命周期、权限或 BPM 记录。适用范围为核对后的 PartTimeCRM 历史导入单，不涉及普通新建订单、删除订单、其他租户，也不修改已启动流程快照。

## 存储和读取

部署顺序：Core V284 → V285 → 新后端 → 审核回填计划 → 授权执行回填。管理端与工作台继续消费原有 `submitterUserName` 和 `formalSalesUserName` 字段，不需要以当前用户表补全名称。

V285 只为 `zsjos_order` 添加可空 JSON 列 `imported_actor_snapshot`，并在结构验证成功后登记两张版本表。它不回填业务数据，也不修改角色权限。MySQL DDL 隐式提交，因此失败时必须检查实际结构和两个版本表；修复后重跑 V285，即使版本标记已存在也仍校验/补齐结构。应用回滚时保留新增列，不能通过删列撤回历史证据。

JSON 协议版本为 1，包含租户、订单号、来源系统、旧订单 ID、源备份 SHA-256 和备份时点。每个人员项包含订单当前人员引用（用于防止后续归属变动后错误复用）、旧员工引用、姓名及 `nameSource`。`legacy_order_snapshot` 来自旧订单的成交销售姓名快照。`legacy_backup_profile` 来自源备份的员工档案，只有在用户明确确认后才可启用，它不证明提交时的姓名。旧系统原始录单人关系也可能由旧系统兼容逻辑初始化，恢复不会提高其证据等级。

读取优先使用正常审批轮次的姓名。仅姓名缺失时使用有效导入证据；异常轮次 JSON 不由导入证据掩盖。导入证据必须匹配租户、订单号、人员引用和已知来源类型。旧员工引用不成为本系统登录或授权身份。

## 生成计划

工具为 `script/sql/mysql/tools/recover_order_actors.py`，使用现有 PyMySQL。参数必须明确指定容器、数据库、租户、密码文件、源备份和计划文件；密码只从文件读取。`prepare` 对数据库只读，只在指定的私有目录创建 0600 计划文件，包含精确目标、完整原行、变更前后摘要和源证据。不得将计划或原始姓名、联系方式提交到 Git 或写入普通日志。

```bash
python3 script/sql/mysql/tools/recover_order_actors.py prepare \
  --container <已确认容器> --database <已确认数据库> --tenant <租户ID> \
  --password-file <私有密码文件> --source <旧系统备份.sql.gz> \
  --source-captured-at <带时区的备份时间> --plan <私有目录/plan.json>
```

按源备份中唯一订单号匹配，校验金额，限定没有当前审批轮次且尚无导入证据的未删除订单。缺少源订单、金额不一致或人员姓名证据缺失分别计数；有审批轮次的订单不在该工具范围内。每个角色独立恢复，有成交负责人证据不代表有实际提交人姓名证据。

默认只恢复旧订单上已存的姓名快照。经明确确认后才在 `prepare` 添加 `--allow-backup-names`。不得直接修改已审核计划以扩大范围，应重新生成计划并核对差异。

## 授权、执行与恢复

执行前向用户说明实际目标库/租户、行数、恢复字段、来源类别、Schema 变更及后端发布影响。共享测试数据库迁移、数据写入和服务部署遵守仓库单独授权要求。源备份、计划及其 SHA-256 是回填前恢复材料，必须保留。

执行沿用相同目标参数，将模式改为 `apply`，传入 `--plan` 和审核后的 `--expected-plan-sha256`。工具锁定精确目标行，逐列摘要校验原值，使用同一执行器完成回填演练、重复执行校验和回滚，再重新校验后正式提交。只写 `imported_actor_snapshot`，显式保留 `update_time`。姓名通过 UTF-8 连接写入，逐项验证 JSON 中姓名的 `HEX`。执行失败不提交成功标记，不修改两张迁移版本表。重复执行已完成计划为零变更。

撤回需另行确认，使用相同计划和摘要，将模式改为 `restore`。仅当当前整行与计划的回填后状态完全相同时才清空本次导入证据；任何后续业务写入都会阻止自动撤回，不能强行覆盖。撤回不删除订单、字段或版本标记。

## 验证

`python3 script/sql/mysql/tools/test_order_actor_recovery.py` 使用独立 MySQL 8 容器验证迁移初次/重复/部分执行恢复、前置失败不登记版本、结构不符不推进版本、UTF-8、跨租户保护、回填重复执行、回滚和并发变更拒绝。Java `SalesOrderSnapshotTest` 覆盖历史姓名优先、无轮次恢复、身份类型、租户/订单/人员引用隔离及异常证据。

共享库执行前还需对审核计划做隔离实数演练；执行后核对精确目标、保留的人员/金额/状态/轮次以及姓名字节。两个前端必须验证同一姓名字段和缺失状态，不以单端结果代替另一端。
