# 生产内容审核自选编导上线

仅适用于 `zsjos_production_content_review`，不改变爆款素材拆解审核。源码交付不代表生产已启用。

1. 协调部署后端、Admin 和 Workbench；保留旧流程定义与在途实例。不修改数据库授权、用户绑定或历史审批。无 SQL 迁移和新依赖。
2. 在流程设计器编辑该流程。编导节点设为“发起人自选”，在“自选角色范围”选择实际编导角色；保持两个单人审核节点串联、拒绝结束流程。终审配置保持原业务规则。
3. 角色管理中核对编导的内容查询/编导审核、媒体学员查询、账号查询、定位查询、定位访谈查询权限。缺失授权由管理员配置，脚本不授予。角色或成员停用、缺少功能权限时不能成为候选人。
4. 发布新流程版本，核对编导节点真实 ID、策略 35、candidateParam 角色 ID、单人方式、终审及拒绝设置。检查提交上下文的 definitionId 与发布版本一致；未配置角色范围时新提交明确失败。
5. 使用真实运营与非账号责任编导测试：保存草稿、选人提交、待办处理、打开本次学员账号档案/访谈/定位及附件、编导通过进入终审、整轮结束后额外权限失效。退回重提换人，验证旧编导不因新轮次恢复权限。
   界面核对须与普通媒体学员详情对照：学员标题、概览/账号页签、账号档案分栏、右侧摘要、历史及访谈弹窗使用相同组件；审批入口只读并限制本次账号，不应出现另一套简化三栏表单。当前应用版本须与账号实际应用记录一致。
6. 验证越权参数、直接写接口、其他学员/账号/协作组、其他附件及旧在途实例均不获得新授权；原负责人仍可经普通入口使用原有功能。

回退时停止新提交并协调回退客户端与服务端，保留新旧审批实例、业务快照及流程版本；不得将新快照改写成绑定关系或静默变更已发起审批人。本次实现没有执行真实流程发布、角色授权、服务重启或生产数据操作。
