## 执行与验证方法

无损受限备份序列化；连接配置取仓库 db_config('test')，不在脚本中存放凭据。
要求环境解析为 test，MySQL 会话使用 utf8mb4 和 +08:00。无新依赖。

```bash
python3 -B script/sql/mysql/repairs/migrate_registration_mode_20261029.py \
  --evidence-dir /opt/zsjos-runtime/backups/registration-mode-20261029/preview
python3 -B script/sql/mysql/repairs/migrate_registration_mode_20261029.py \
  --evidence-dir /opt/zsjos-runtime/backups/registration-mode-20261029/applied --apply
```

先在会话临时表复制实际三张可变表及索引，验证首次、零写入重复、首次任务更新后／
全部任务更新后／首条清单后／首条路由后／全部写入后的异常回滚，随后恢复执行。
验证迁移后已有业务勾选时拒绝重放。临时表及事务回滚可能消耗临时表自增号，不影响业务表。

正式操作依订单→任务顺序锁定，同事务锁定当前发布配置与目标依赖，重新比较前像。
写入前 fsync before.json 和 intent.json；先更新任务，再插清单，最后插路由。
字段白名单与完整原行比较保护其他任务（包括此前关闭的 40 条）、其他租户、原清单、
原路由、订单商品、审批和依赖。提交前保存 pending-after.json；独立连接回读后保存
verified.json，并对全部新标题及部门标签核验 UTF-8 字符串与 HEX。

同一证据目录只有完整后像一致才接受零写入重复；后续编辑或部分结果拒绝重放。
事务失败时整个 DML 回滚；若连接中断或证据落盘失败，先核对真实数据库与意图、后像，
不能以文件是否存在推断是否提交。旧证据不覆盖，确认已回滚后用新目录重试。
回退须另行授权，核对任务仍等于本次后像且没有后续业务事实，再恢复原字段和处理
本次新增的清单／路由；不得覆盖后续分班、发送、勾选或交付。脚本不自动回退。
