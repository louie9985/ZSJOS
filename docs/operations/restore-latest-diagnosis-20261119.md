以任务原截止日期确定最新节点，不以任务 ID 或最后修改时间替代业务周期。

诊断任务属于媒体账号；同一学员的各账号分别判断，不能任意挑一个账号代表整个学员。

非上次清理导致的取消及已删除账号不恢复。

原任务的受派人不是当前负责人。目标负责人读取当前媒体账号的 `director_user_id`，

用户属于同一租户且启用。没有按姓名、角色名或固定用户 ID 决定负责人。
已只读核对目标当前配置具备账号读取/编辑/维护和业务待办查询权限，不修改任何角色菜单授权。

## 写入、幂等与恢复边界

执行器：[restore_latest_diagnosis_20261119.py](../../script/sql/mysql/repairs/restore_latest_diagnosis_20261119.py)。
复用仓库现有 PyMySQL 安全连接和证据工具，无新依赖。
连接显式使用 `utf8mb4`、`SET NAMES utf8mb4` 和 `+08:00` 会话时区。

只更新冻结任务 ID 的状态为 `pending`、指派人为当前编导，清空本次取消时间和原因，
递增版本与更新审计元数据。保留原任务 ID、账号、截止时间、载荷、幂等键、创建信息。
账号和服务关系本身不改。按账号 ID、服务 ID、用户 ID、任务 ID 顺序加锁并重查完整前镜像；
当前责任人、轮次或任务发生变化即拒绝覆盖。冻结选择时间，不在执行中扩展到新开放节点。

每条更新同事务追加 NULL 人类操作者的 SYSTEM 事件，记录 `cancelled → pending`，
包含原/新受派人、账号、服务及原取消事件键。保留全部 986 条原取消审计。
任务不插入、不删除；没有 DDL、迁移或版本账本写入。异常回滚任务及新事件。

原计划重放依靠恢复事件幂等键，必须为零写入；恢复后有新业务修改则拒绝覆盖。
提交结果不确定时先用原计划复核，不重新生成计划。提交后的再次取消需另行授权，
用私有前镜像和恢复后镜像比较后补偿更新，并追加反向审计；不删除原取消或恢复事件。
执行器只在隔离临时表演练补偿，不开放真实库补偿开关。
