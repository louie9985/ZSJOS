## 执行、幂等与恢复

前置：已授权目标环境为 test；现有 MySQL 8、PyMySQL、Docker 及运行服务环境可读取；
旧库副本和当前表存在。脚本复用已有数据库连接工具，不安装依赖、不增加数据库结构。

```bash
python3 script/sql/mysql/repairs/backfill_lead_owner_identity_20261020.py prepare --plan <私有目录>/plan.json
python3 script/sql/mysql/repairs/test_backfill_lead_owner_identity_20261020.py
python3 script/sql/mysql/repairs/test_backfill_lead_owner_identity_20261020.py --prepared-plan <私有目录>/plan.json <输出的SHA256>
python3 script/sql/mysql/repairs/backfill_lead_owner_identity_20261020.py apply --plan <私有目录>/plan.json --sha256 <SHA256> --group priority --report <私有目录>/priority.json
python3 script/sql/mysql/repairs/backfill_lead_owner_identity_20261020.py apply --plan <私有目录>/plan.json --sha256 <SHA256> --group remaining --report <私有目录>/remaining.json
python3 script/sql/mysql/repairs/backfill_lead_owner_identity_20261020.py verify --plan <私有目录>/plan.json --sha256 <SHA256> --report <私有目录>/verified.json
```

计划为权限 0600 的技术字段原值/目标值、历史哈希、完整行保护哈希、逐条依据与待核实原因。
不包含客户资料、姓名、联系方式、令牌或完整请求。目录权限 0700。原始事件和映射摘要
以及 MySQL 实例标识需与计划一致；执行时重新校验环境、目标库和运行进程的数据源。

每条客资在独立事务内锁定主记录与历史，重新计算证据；只接受完全一致的原值，或已经
完全达到目标态的零写入重试。更新使用租户、负责人、状态、空身份及版本条件。事务内
核对允许字段及其余列的哈希，提交后另开事务复读。遇到并发变化记录为拒绝，不覆盖。
优先组先提交，其他组逐条执行；中断后使用原计划重试，已提交记录不重复更新。

全部连接建立 utf8mb4。业务身份是 ASCII 技术值；本次不修改业务中文标签。测试用中文
证据会核对 HEX，确保证据读取/私有 UTF-8 文件边界正常。

单条失败可以事务回滚，跨条执行不声称全批次原子性。后续补偿回滚必须再次获得相应授权，
仅当当前记录和历史仍与目标态一致时，使用计划原值恢复这四个允许字段；已有跟进、转派
或版本变化时不能强行恢复旧版本。脚本内部 `apply_one(..., restore=True)` 已有隔离验证，
默认 CLI 不暴露回滚入口，避免把诊断或重复执行变成撤销。
