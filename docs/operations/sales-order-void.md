# 中世健订单作废

## 业务边界

财务在订单管理或工作台成交审批详情中点击“作废订单”，填写原因并确认。
仅 `effective` 订单可变为 `voided`；不增加作废审批，不删除订单或改写原审批结果。
记录作废原因、时间和实际操作人，旧订单的金额、付款凭证、生效时间和审批快照保留。

作废与退款分别记录。作废使原单不再计入有效订单业绩；它不证明退款到账，也不代表已支付返现被追回。
销售金额、订单数、客单价、目标完成率、产品指标以及依赖有效订单的成交统计按现有查询规则重算。
原业绩页面缓存仍需刷新；历史月份按当前状态查询，因此会减少。新单按自己的提交日期计业绩。

当客户不再有其他有效订单、关联客资没有待审/待补正订单且仍为成交状态时，恢复客资为有效、已成交商机为跟进中。
若历史订单缺少商机，建立当前重新跟进的商机，不补造历史审批事实。保留当前负责人和联系方式，更新本次业务活动时间，不恢复历史跟进任务、不自动转派。
当前暂停、公海、对象权限等既有录单限制仍适用。客户仍有有效订单时不恢复首购入口。
客户型复购无直接客资引用时，通过已有 Person 关联查找客资；无客资的历史客户不凭空创建客资。
销售使用原“录入成交”入口，新单正常审批、生成新的报名履约任务，不建立强制的新旧单承接流程。

## 关联业务

- 报名、班级、学员、服务关系、服务期限和联系延期流程不作自动取消或迁移。
  原未完成报名因订单不再有效而不能继续完成，教务可在公共池结束任务。
  新单产生的重复报名任务也由教务手动结束，避免生成重复服务关系；已开展服务是否结束由交付流程决定。
- 原单关联返现统一变为 `cancelled`，记录原因和取消时间。包括观察中、可提现、冻结、提现中和已提现返现。
  提现历史、金额和凭证不删除。含失效返现的提现单不能登记打款，返回 `1900009015`，财务可驳回并由申请人重新申请其他有效返现。
  撤销/驳回提现时跳过已取消返现，不把它恢复成可提现。
- 礼品采购写入 `voided_at`，默认采购列表排除，勾选“包含已作废”可审计历史。
  现有采购记录并不管理实物退回，不将作废解释为已发礼品被收回。
- 原订单资金分配写入 `voided_at`；真实支付流水、购买意向和退款记录保留。
  不自动转款、不自动退款，不把原线上付款重新标为未支付或重新开放其购买意向。
  重录可通过现有线下已支付入口提供原收款及补退费凭证，由正常财务审批核实最终金额；不要为重录再次生成不必要的线上收款。

## 接口与授权

`PUT /admin-api/zsjos/sales-order/{id}/void`

请求：`{ orderVersion, reason, idempotencyKey }`，原因必填、去除首尾空白、最多1000字。
Controller 需要 `zsjos:sales-order:void`；Service 累计检查订单对象权限以及订单审批配置中的启用财务中心成员资格。
不通过角色名称、账号ID或管理员只读权限绕过写授权。详情 `canVoid` 是相同权限判断的投影。
管理员在角色管理中明确分配按钮权限，迁移不写 `system_role_menu`。

订单、返现、礼品及资金分配失效和客资恢复在同一事务中执行。行锁、版本与命令幂等键防止重复处理。
重复相同请求返回成功，重复键不同参数冲突；过期版本或非有效订单明确拒绝。
历史订单没有 BPM 轮次时仍可独立作废，命令账本的轮次/实例引用允许为空，不伪造流程。
