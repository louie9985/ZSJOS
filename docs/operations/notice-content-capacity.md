# 公告正文容量扩容

Core V313 将中世健公告 `system_notice.content` 从 TEXT（65,535 字节）扩为
MEDIUMTEXT（16,777,215 字节）。容量包含 UTF-8 正文及 HTML 标记。
此次只改数据库容量，保留原内容、非空约束、utf8mb4 字符集、排序规则和注释；
不调整前后端逻辑、校验、权限、附件或其他字段。

已有部署先备份 `system_notice` 和两张版本表，确认两张版本表均有 Core V312，
再通过 UTF-8 MySQL 客户端执行
`script/sql/mysql/migrations/V313__notice_content_capacity.sql`。
新环境使用 `bootstrap.sql` 后按既有顺序执行全部迁移；两份结构源已同步。
不修改历史迁移和已应用版本的 checksum，不对已有环境重跑 bootstrap。

脚本仅扩大这一列并登记 V313，不写公告业务行。重复执行检查实际结构；
已有 V313 标记不会掩盖未完成的扩容。两张版本表仅在结构验证成功后一起提交。
DDL 隐式提交，失败后应检查列和两张版本表并重放修复，不能依赖事务回滚 DDL。
回退应用时保留扩大后的字段，不能直接缩回 TEXT，以免截断新增的较长正文。

单独扩容不需要重启应用。DDL 可能短暂等待锁或阻塞该表写入；完成后，
仍保留编辑页面的用户可以直接重试保存，无需刷新。数据库容量并不代表其他
请求体或代理限制同步扩大。

验证：运行 `python3 script/sql/mysql/tools/test_notice_content_capacity.py --container CONTAINER`
在现有 MySQL 上创建并保留唯一命名的隔离测试库，覆盖首次执行、重复执行、
前置条件失败、结构冲突、版本写入失败、部分执行恢复及超过 64KB 的中文正文。
加 `--fresh` 使用现有 fresh 验证器检查完整初始化链；测试不写业务库、不删除库。
