# 课程日历通知配置

本次配置用于本地开发数据库 `ruoyi-vue-pro` 的租户 1，业务场景为
`zsjos.calendar.course`。2026-10-13（北京时间）新增站内信和企业微信各一套
模板及启用规则；没有修改考期日历、权限、企业微信凭据或员工推送偏好。

## 通知文案与接收人

- 发送人：中世健消息中心。
- 标题：`课程通知：{{calendar.title}}`。
- 摘要：`课程时间：{{calendar.time}}`。
- 正文（两渠道一致）：

```text
课程：{{calendar.title}}
时间：{{calendar.time}}
备注：{{calendar.remark}}
```

变量来自此次日历通知的不可变快照，备注为空时显示空字符串。模板没有使用课程场景
未提供的教师、地点或附件变量，也没有把内部事件枚举显示给员工。
独立发送、新建、修改、删除通知共用此中性文案；当前配置不会在标题中区分这些动作。
点击动作使用 `business_detail`：打开课程日历，查询课程当前日期并自动展开详情。企业微信沿用既有一次性票据与登录回跳。

规则事件角色为 `recipient`，额外指定员工为空。实际接收名单由日历业务的
`FIXED` 接收人快照决定，仅发送给操作时选择的员工，或明确选择的全员范围。
企业微信使用文本消息，实际消息由适配器组合标题、换行和正文；受现有渠道长度限制。
站内信包含在线实时提醒，不新增独立 WebSocket 规则。

## 配置来源及执行

源文件：[course-calendar-notification-config.sql](../../script/sql/mysql/course-calendar-notification-config.sql)。
这是用户明确要求的独立管理员配置脚本，不是版本迁移，不自动加入 bootstrap，
不修改已部署 V282 或任一版本记录。

前提是 System 通知表已具备、V282 已完成、租户 1 启用。执行前备份对应场景的
模板和租户规则，并检查待恢复的课程通知意图；补齐规则可能使既有待恢复意图继续投递。
本次应用前待恢复意图为 0。MySQL 客户端必须指定 `--default-character-set=utf8mb4`，
选择准确数据库，再执行此文件；不要使用 `--force`。

脚本先创建模板，再创建规则，在同一事务内检查配置后提交。精确重复执行不修改现有行；
缺失一部分默认配置可补齐。现有自定义、停用、删除、重复或错配配置会导致失败并回滚，
需要单独审查，不能强行覆盖。临时存储过程的 DDL 不具备事务回滚保证。

恢复时只在审查后停用本脚本新增的规则；不要删除历史消息或修改角色授权。
已经送达的消息不能通过配置回滚撤回。本次未触发真实消息发送。

## 验证与边界

- 控制 MySQL：首次应用、重复执行、仅存在站内信模板时补齐均通过。后续跳转升级验证覆盖首次、重复、原默认规则从 none 升级及管理员修改冲突回滚。
- 已停用模板冲突、非法参数 JSON、缺少 V282：执行失败且新增配置全部回滚。
- 目标库：模板 672 / 673，规则 657 / 658，分别为 `in_app` / `wecom`；状态均启用。
- 目标库已重复执行，行内容保持不变；UTF-8 查询及 `HEX()` 解码与中文源文案一致。
- 企业微信渠道开启，ADMIN 自建应用启用且必要凭据字段存在；未调用企微校验凭据，
  未验证外部投递。员工还须绑定企微且开启个人推送，原有偏好保持不变。
- 配置查询直接读取数据库，无需重启服务。未进行真实登录发送验收。

本地执行证据保存在交付记录指向的临时目录，不含凭据或个人资料。

课程跳转实现见[单日详情契约](../api/calendar-day-details.md)。配置脚本只升级本脚本创建且未被管理员接管的两条课程规则；不重写历史消息动作，旧 none 通知保留原行为。新规则依赖新前后端部署，企业微信还依赖有效的工作台外部访问地址及票据有效期。
