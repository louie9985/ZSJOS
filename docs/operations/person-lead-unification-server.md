## 失败及恢复

- 单组异常由数据库事务完整回滚；已提交的其他组有持久化前后镜像。执行器记录 interrupted 并要求保持维护，不在异常分支自动批量删除新别名/事件。
- 需要撤销已提交组时，先检查实际提交事件和持久化 after-image；按真实提交顺序逆序调用 `restore_group`。只允许恢复本次关系/原主档，并删除本次新增的别名、占用、合并事件；不能删除原业务记录。该恢复删除范围必须包含在明确批准中，或届时单独批准；后镜像变更一律拒绝恢复。
- 全批次恢复已在副本验证。中断若处于“收据已 fsync、提交结果未知”，必须先读实际数据库判断提交/回滚，不能因缺 summary 就重复写入。
- MySQL DDL 不能用事务回滚保证。结构失败时保留现场并核对实际结构与两账本，不伪造版本完成。恢复旧后端前先恢复本次归一数据，再检查是否仍有一档多客资/多商机；不能直接重建旧唯一约束。优先保留兼容结构并完成修复，不覆盖已部署迁移。
- 全库备份用于灾难恢复设计；不授权原库 DROP/重建/覆盖。恢复应先在新隔离库验证，并对具体替换/恢复范围另行批准，保护维护窗口后的任何新写入。
