## 旧公告 V295 恢复顺序

1. 指定数据库、两张版本表和公告列；备份相关表，保存结构与内容摘要。暂停其他迁移操作者。
2. `tools/notice_version_recovery.py` 的 `inspect` 必须确认公告列为 MEDIUMTEXT、原 charset/
   collation/非空约束/中文注释匹配，两条 V295 的描述和旧 filename checksum 精确匹配。
3. 经批准调用 `release_old_version(conn, archive)`，将原始两行归档为权限 0600 的外部 JSON，
   fsync 后在事务内锁定并重新比对两行，再仅删除这两条旧 V295。第二条删除失败会回滚第一条。
   这一步不改变公告行，不创建 V313 成功记录。归档文件已存在则拒绝覆盖。
4. 执行原编号新手池 V295，核对两张新手池表、派单历史字段、按钮元数据和两张版本表。
   不赋予角色权限。失败时检查实际 DDL 和两表版本状态；不要仅看退出码或版本号。
5. 后续 V296–V312 必须根据当前库历史数据和经审查证据执行。V313 在真实 V312 完成后验证
   已有 MEDIUMTEXT 并登记成功；无需再次修改公告内容。

中途恢复：新手池尚未执行时，可按归档的精确行恢复旧版本记录，但这会重新产生待解决的
编号冲突。若新手池 DDL 已部分完成，应按其幂等校验继续恢复，不把旧公告记录写回冒充完成。
已扩大公告列始终保留；缩回 TEXT 会有截断风险。所有真实库写入需新的具体操作授权。
