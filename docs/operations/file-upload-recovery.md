# 众拾间附件上传与覆盖恢复

普通上传和传统预签名上传默认使用 `业务目录/yyyyMMdd/毫秒时间戳加5位随机数/原文件名`，由 Infra 生成并返回完整路径。不得关闭默认防重名开关，否则独立文件记录可能指向同一对象并覆盖历史附件。该机制沿用现有时间戳加随机数算法，不是存储层绝对排他写入保证。独立业务直传继续使用自身会话路径。

Admin 与 Workbench 使用服务端返回的文件标识、路径或 URL，不自行拼装存储路径；原文件名及接口字段不变。旧记录继续读取原路径，代码修正不会恢复已覆盖的内容。修正须部署到后端后才生效。

历史恢复应先保全当前对象与附件关联清单，再从对象备份、磁盘快照或上传者原文件中寻找来源。数据库备份可帮助核对关联，但通常不包含对象内容。文件大小与上传时间仅是候选匹配线索，必须结合内容和上传者确认归属。

恢复时将确认后的原图上传为独立新对象，逐条修正经确认的附件绑定或文件引用，并保留原关联、来源、校验和与回滚记录。不得把恢复图直接覆盖回共用旧路径，否则会再次影响其他客资。涉及通知或流程历史快照时先识别引用，不自动改写历史。

没有可信来源的附件应列为待补传，不用当前共用图片猜测原图。数据库及存储的实际修复、部署和服务操作须另行确认具体目标与影响。
