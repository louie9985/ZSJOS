# 公告对外分享部署与回退

## 前置条件和范围

V288 在 Core V287 之后执行，为 System 增加一张空分享表和现有公告菜单下的分享按钮元数据；不写角色授权、租户套餐、历史公告、阅读记录、历史迁移校验和或业务选项。PMS 不参与依赖或启动。

通过正常迁移器发现并执行 `V288__notice_public_share.sql`。先备份当前受影响结构、菜单元数据及两个版本账本。DDL 隐式提交：部分失败时先核查表、列、唯一索引和版本记录，再修复具体不一致并重放；存在版本标记不等于结构完整。过程中的前置检查、菜单写入、后置检查与版本登记保持失败传播。版本登记与菜单写入使用同一事务。

SQL 首次/重复/部分应用、错误结构和失败恢复验证入口为 `script/sql/mysql/tools/test_notice_public_share.py`。脚本在现有本地 MySQL 容器新建 `notice_share_v288_时间_场景` 数据库，不访问业务库，不删除验证数据，不改变服务状态。使用 `--fresh-through-v288` 在独立的 `ns288_时间_fresh` 库中验证完整基线及截至 V288 的迁移链；短库名避免历史迁移的 MySQL advisory-lock 名称超过 64 字符。两个基线结构文件同步包含空分享表，权限元数据仍由 V288 安装。执行共享数据库迁移仍需单独授权。

## 配置与顺序

后端：
```yaml
system:
  notice-share:
    public-base-url: ${ZSJOS_PUBLIC_H5_BASE_URL:}
```

填写实际外网 H5 基地址；支持基路径，不含用户名密码、查询参数或 fragment。地址缺失/无效时拒绝开启，不能回退到管理端域名。生产部署使用 HTTPS；HTTP 只用于受控本地验证。

部署顺序：V288 → 后端 → H5 → Admin/Workbench → 管理员配置租户套餐（适用时）及角色分享权限 → 外网验收。新增按钮位于现有公告菜单下，同时需要 query 和 share。仅具有 read 的员工不能管理分享。

外部 H5 站点须提供：
- `/notice/share` history 路由刷新时返回 H5 页面，不跳转登录。
- `/public-api/system/notice-share/**` 转发至后端，并保留 X-Notice-Share-Token 请求头。
- 公共接口不缓存；不记录查询参数或专用令牌请求头。Nginx 对该 location 使用不含 $args/$request 的日志格式（只保留 $uri 等必要字段），或关闭该 location 的访问日志。其他代理、APM、WAF 同样不得采集完整令牌。
- 默认配置将 NoticeShareMapper 和 NoticeMapper 的 SQL 日志保持在 INFO，避免 DEBUG/TRACE 打印令牌或正文。部署覆盖配置不得为这些 Mapper 开启 SQL 参数/结果日志。
- 正文图片/视频及 Infra 文件服务地址外网可达，HTTPS 页面不引用 HTTP 混合内容。不为该功能改变所有文件的权限或批量重写历史媒体 URL。

## 上线验收

用实际有权账号分别在 Admin/Workbench 开启一条已发布公告，选一个附件、保留一个未选附件。退出登录后在手机浏览器和微信内置浏览器打开链接及扫描二维码，确认正文中文、图片/视频及选中附件正常，未选附件无法通过公开接口取地址。

检查关闭后旧链接失败、重新开启生成新链接、下线联动、错误重试、无权限账号拒绝、跨租户/跨公告附件拒绝。检查公告内部已读记录未被外部访问写入。通过 UTF-8 MySQL 客户端查询分享按钮名称及 HEX(name)。

重点检查应用和代理日志没有完整令牌、分享地址和正文。线上不可达或微信未验收应明确保留为未验证，不以构建、测试夹具或二维码图片生成成功代替。

## 回退

先在代理关闭新增公开接口、撤销对外分享入口，再回退后端和前端。仅回退前端不能阻止已发出的链接继续访问仍运行的后端。保留新增表、分享记录和版本账本，不删除公告/文件/授权或回改历史迁移。

应用回退不撤回已下载内容；如需重新启用旧版分享数据，先审查当前 active 记录并通过受控方式关闭不应恢复的分享，避免旧链接意外恢复。服务配置、重启、共享库执行和发布不包含在源码实施的自动授权内。
