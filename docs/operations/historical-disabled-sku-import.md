# 历史停用规格配置与限定学员导入

本流程对应 2026-10-27 明确确认的五类历史规格。先准备配置，再导入仅有规格异常的
33 条源记录。不是全量八表导入，不处理身份争议、其他报读规格冲突或待分班记录。
租户固定为 1，产品、属性、SKU、班级和人员 ID 均从目标库解析，不能复用开发库 ID。

## 范围与配置前提

| 所属课程 | 按原填写保留的 SKU 名称 |
| --- | --- |
| 公共营养师 | 公共营养师｜人社部技能等级｜一级｜超值精品班 |
| 心理咨询师 | 中国心理卫生协会｜中国心理学会｜初级 |
| 心理咨询师 | 中国心理卫生协会｜中国心理学会｜助理 |
| 心理咨询师 | 中国心理卫生协会｜中国心理学会｜无级别 |
| 执业中药师 | 执业中药师｜金牌押题班｜单科 |

保留历史原文不代表核实或纠正了机构/等级含义，不能映射成相似的在售规格。
配置工具位于 `script/sql/mysql/tools/historical_disabled_skus.py`。
要求对应课程唯一、启用且已有唯一启用的 `sales_spec` 属性；不创建产品或猜测属性结构。
缺失时仅新增这五个规格所需的属性值及 SKU，SKU 从创建起 `status=1`。属性值保持启用，
以便历史快照保留完整标签；业务选项必须依据启用 SKU 集合过滤，不能仅按属性值状态展示。
停用选项过滤的后端/Workbench 修复属于独立工作流，部署时应核验实际运行版本。

已有匹配 SKU 必须处于停用状态、名称和属性准确、技术占位价格为零并有历史价格未核实说明。
符合则原样复用，包括原 ID、引用、排序和创建信息；同名/同属性重复、已启用、被逻辑删除后
引用冲突、属性/价格说明不符等情况停止，不能擅自禁用现有在售产品或覆盖其他配置。
零元仅用于必填目录字段，不代表学员实际付款；不创建订单、付款或财务记录。

本工具是已审阅的业务配置同步，不是 schema migration：无 DDL，无版本账本、角色权限写入。
前置校验、补齐、后置校验在一个 InnoDB 事务内完成，并锁定产品/属性/匹配项；失败回滚。
完成后重跑不写入。部分环境已经有其中几项时，重新预检后只补缺项。
已提交的配置可能被后续教学服务引用，不能以删除配置作为通用回滚方式；保留停用，按关联
证据另行审查。工具不提供 DROP/DELETE 或自动清理。

## 配置执行顺序

仅运行 `prepare` 不修改数据库。输出文件须保存在仓库外，使用新的文件名，勿覆盖旧证据。
在服务器执行时，使用受控的 MySQL `[client]` 配置文件传入连接参数；文件应仅允许操作者读取，
不得提交仓库或复制凭据到命令行。未传 `--connection-file` 时仅使用现有本地 Docker 连接。
连接统一 `utf8mb4` 和北京时间，写入后检查中文 HEX。

```text
python script/sql/mysql/tools/historical_disabled_skus.py prepare --database <目标数据库> --connection-file <受控client配置文件> --plan <仓库外配置计划.json>
python script/sql/mysql/tools/historical_disabled_skus.py apply --database <目标数据库> --connection-file <受控client配置文件> --plan <仓库外配置计划.json> --sha256 <预检输出摘要> --result <新的配置结果.json>
```

计划绑定目标数据库、服务器 UUID、MySQL 版本及当前配置摘要。不能拿本地计划在生产执行，
也不能用源文件相同代替目标库核验。执行生产命令属于独立受控操作，本次脚本交付未执行生产写入。
如果提交后结果文件写失败，先重新只读预检核对五项状态；不能仅凭结果文件缺失判断事务未提交。

## 限定导入

入口 `script/historical-student-import/import_disabled_skus.py` 只接受以下原始坐标，
并要求异常表仍将该行标记为“课程规格无法匹配系统”且姓名、联系方式、规格、班级、规划师一致：

- 人社公共营养师第 99 行。
- 心理咨询师第 45–47、49–68、77–84 行。
- 执业中西药师第 85 行。

合计 33 行；心理咨询师第 48 行有报读冲突，不在范围内。不得重新排列源表行号或提前清除
异常表记录。预检绑定完整源文件和异常表 SHA256、各行内容及五项规格授权。原始姓名/手机号
不写入代码；计划包含个人信息，只保存于受控仓库外目录。

预检和实际提交使用同一规格选择逻辑。仅允许本入口的已审核坐标使用精确匹配且仍停用的五项
规格，其他停用规格及普通导入入口仍拒绝。快照记录 `historicalSku`、`skuDisabledAtImport`、
`catalogPriceIsPlaceholder`，避免把占位目录价格当成历史实付金额。

当前班级契约允许服务中的 `NORMAL` 和 `UNSCHEDULED` 班。新入口可复用源表指定规划师的
已有未确定考期班，并校验当前账号、规划师角色和部门；不改班级、不伪造考期，不接受
`PENDING`/`EXCEPTION` 或已结课班。本批要求复用已有班级，缺失则列异常，不自动创建同名普通班。
旧三表入口默认规则不变。

身份匹配、已存在服务判断和旧记录保护沿用 `import_students.py`。本入口不会绕过多档案或
姓名冲突，也不包含此前私有同人指定目标试验的授权。若预检出现其他异常，停止提交并单独处理。
已有合格服务保持不变；缺少时新增教学服务、空协作组、历史首联/学习计划记录和来源事件。
必要时提升目标 Person 的身份状态为 student；不修改姓名、原订单/客资/负责人/服务阶段。
学生身份筛选、服务统计和服务负责人可见范围随新增教学服务正常变化，不能宣称零行为影响。

```text
python script/historical-student-import/import_disabled_skus.py prepare --source <当前导入总表.xlsx> --exceptions <当前待确认学员.xlsx> --database <目标数据库> --connection-file <受控client配置文件> --actor-username <有效审计账号> --plan <新的导入计划.json>
python script/historical-student-import/import_disabled_skus.py apply --source <当前导入总表.xlsx> --exceptions <当前待确认学员.xlsx> --database <目标数据库> --connection-file <受控client配置文件> --actor-username <有效审计账号> --plan <导入计划.json> --sha256 <预检输出摘要> --result <新的导入结果.json>
python script/historical-student-import/import_disabled_skus.py verify --source <当前导入总表.xlsx> --exceptions <当前待确认学员.xlsx> --database <目标数据库> --connection-file <受控client配置文件> --actor-username <有效审计账号> --plan <原导入计划.json>
```

先完成配置再生成导入计划；导入计划仍有异常则 apply 拒绝。提交前再次核对服务器、文件、配置、
人员和班级。原计划重放以业务事件校验并零新增；事务失败整体回滚。旧三表计划新增了授权上下文字段，
必须重新预检，不可复用此前保存的旧计划。数据库成功后更新异常表是后续独立动作，本工具不自动改 Excel。

## 验证

```text
python script/historical-student-import/test_disabled_skus.py --source <当前导入总表.xlsx> --exceptions <当前待确认学员.xlsx> --output <新的仓库外验证结果.json>
```

验证仅连接本地源库并创建保留的独立 MySQL 验证库。通过复制时排除五项配置构造缺失场景，
不在业务库删除配置。覆盖缺失创建、重复执行、部分配置恢复、冲突拒绝、事务回滚、未授权行/规格
拒绝、未确定考期班边界、导入重放、旧行保护和中文 HEX。生产环境仍需针对最新数据重新预检，
真实账号/API/页面验收不能由数据库测试替代。

2026-10-27 本地验证：当前 33 条全部通过预检，独立库新增 33 条教学服务，23 条复用已有
未确定考期班，其余复用普通班，零新增班级。配置创建/重复/部分恢复、失败回滚、原业务行保护、
导入重放和 verify 命令的“未执行拒绝/已执行通过”检查均通过。开发业务库和生产均未执行本批导入。
