# 返现与提现管理页面重构设计

日期：2026-09-11
范围：管理端 `/zsjos/cashback` 与 `/zsjos/withdrawal`

## 目标

参考销售侧客资管理页面，统一两页的列表布局、状态表达、筛选方式和详情承载方式，并保留现有权限、数据范围、导出、审批和打款能力。

## 页面结构

两页均采用顶部筛选区与列表区的双 ContentWrap 结构。筛选区提供初级筛选和高级筛选；列表区提供错误重试、条纹表格、溢出提示、分页和空状态。工具栏提供刷新、密度和列显隐设置，列设置使用项目现有 `ant-pro-table-list-toolbar-setting-items` 同类能力，不新增第三方依赖。

详情统一使用右侧抽屉，支持加载、错误重试、空数据和销毁重建。关键编号和可进入详情的业务字段使用主色链接；状态使用 `el-tag` 并按业务语义配色。

## 返现管理

初级筛选：返现类型、返现状态、返现编号/客资编号关键词。

高级筛选：订单号、课程/商品、受益人、金额区间、生成时间区间、可提现时间区间、结算时间区间。现有分页接口缺少这些参数时，先扩展后端请求 VO、Mapper 条件和 API 类型，禁止前端拉全量后本地过滤。

默认列：返现编号、类型、客资编号、订单号、课程/商品、返现基数、返现比例、返现金额、状态、生成时间、可提现时间、操作。操作至少包含详情；取消或其他动作必须同时满足服务端权限与记录状态。

详情抽屉分为返现基本信息、关联客资/订单、规则快照、结算与取消信息，展示 `observationDaysSnapshot`、`settledAt`、`cancelledAt` 与取消原因等现有字段。

## 提现管理

初级筛选：提现单号、申请人、提现状态。

高级筛选：申请金额区间、申请时间区间、审核时间区间、打款时间区间、银行流水号、申请人/合作方。

默认列：提现单号、申请人、申请金额、状态、开户名、脱敏银行卡、开户行、申请时间、审核时间、打款时间、操作。操作按现有权限和状态显示详情、撤销、驳回、登记打款；导出继续使用异步导出任务并保留当前条件。

详情抽屉分为提现信息、银行卡快照、审批信息、关联返现明细、打款信息。财务详情接口仅在具备 `finance-query` 时调用，继续遵守卡号脱敏和数据范围约束。

## 权限与数据状态

页面只依据服务端返回菜单/按钮权限展示入口，后端继续独立校验。返现数据范围沿用 `finance-query` / `my-query`；提现沿用 `finance-query` / `admin-query` / `my-query`。任何状态转换操作保持现有接口，不由前端推断权限或角色。

## 错误与验证

列表和详情分别处理加载、成功、空、错误、重试和未授权状态。验证包括前端类型检查、生产构建、桌面与移动宽度浏览器检查，以及后端分页查询条件的聚焦测试。

## 非目标

不修改 H5 返现/提现页面，不引入新的前端或后端依赖，不改变提现业务状态机、BPM 流程或银行卡隐私规则。

## 2026-09-21 登记打款调整

财务可多选当前页待打款记录，使用现有登记打款权限执行“批量登记打款”。单笔及批量表单取消银行流水号和付款凭证输入，仅保留选填的打款时间、备注；批量统一应用，打款时间留空则保存为空。后端逐条授权并整批事务提交，任一记录失败全部回滚。现有历史记录不重写，数据库可空字段直接复用。接口和数据边界见 [提现与线下打款](../../api/withdrawal-and-offline-payout.md)。
