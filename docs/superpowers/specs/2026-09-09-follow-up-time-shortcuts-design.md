# 跟进与联系时间快捷项设计

## 目标

员工工作台的客资跟进弹窗、客资详情跟进面板和学员联系表单统一增加“+30 分钟”和“+25 天”快捷项，同时保留现有“+1、2、3、5、7、14、30 天”。

## 设计

- 在 `frontend/workbench/src/services/leadFollowUp.ts` 定义共享快捷项类型、列表和纯时间计算函数。
- 快捷项由稳定标识、展示文本、数值和单位组成；单位仅支持 `minute` 与 `day`。
- 客资表单渲染共享列表；学员联系表单按联系阶段选择专用列表（见下文）。点击后以用户点击时的本地当前时间为基准，通过 dayjs 增加对应分钟或日历天数，并写入各自的日期时间字段。
- 客资详情面板点击快捷项后继续标记表单为已修改；其他既有校验、提交载荷和延期审批判断保持不变。

## 边界

- 不新增后台接口、数据库字段、管理员字典、权限或第三方依赖。
- 不改变快捷备注及其他业务枚举的数据来源。
- 不改变后端对下一次跟进或联系时间的校验和存储协议。

## 工作台跟进表单统一（2026-09-24）

客资跟进弹窗与详情内联表单现由共享字段组件渲染时间快捷项。点击后显示选中态，手工修改日期或重置时取消高亮，计算规则与共享快捷项列表不变；学员联系表单保持原有呈现。布局、字典加载重试、备注上限及附件提交行为见 [工作台跟进表单说明](../../../frontend/workbench/docs/follow-up-form.md)。

## 学员联系快捷项（2026-10-27）

- 学习规划师填写联系记录时，完整列表为 +30 分钟、+1 小时、+1 天、+2 天、+3 天、+7 天、+30 天。
- 首联未成功、下一任务仍为首联时，仅显示 +30 分钟和 +1 小时；下一任务为制定学习计划或普通跟进时显示完整列表。
- +7 天和 +30 天均从点击时的当前时间增加日历天数；超过配置时限仍按现有规则要求延期原因并发起审批，普通跟进仍允许不填下次联系时间。

## 验证

- 单元测试覆盖分钟和天两种快捷时间计算，以及共享列表包含新增项。
- 运行 Workbench 聚焦测试、完整测试、TypeScript 类型检查和生产构建。
- 在可用运行环境中检查桌面和移动宽度下三个入口的按钮换行、文本和点击结果。
