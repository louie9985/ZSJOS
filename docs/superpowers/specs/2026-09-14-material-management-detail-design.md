# 素材管理详情与审批设计

## 背景

当前 Workbench 的“素材浏览”和“素材管理”都渲染 MaterialLibraryPage，管理菜单没有落实既定的 Admin Vue 嵌入职责。Admin 素材管理页已有列表、动态表单和素材生命周期操作，但详情展示尚未达到 Workbench“查看布局”的四栏效果，审批操作也未完整落在管理详情中。

## 目标

1. “素材管理”菜单使用 Admin Vue 页面。
2. 点击详情打开大尺寸详情抽屉，采用 Workbench“查看爆款拆解”的四栏布局：封面、账号详情、编导拆解、搭建建议。
3. 抽屉左下角提供当前素材可用操作，包括编辑、提交审批、审批通过、驳回、停用、恢复。
4. 审批只处理当前素材；通过/驳回要求填写审批意见，并沿用现有 BPM 与后端权限校验。
5. 操作成功后刷新详情和列表，失败时保留当前上下文并显示可识别错误。

## 非目标

不增加独立审批待办列表、审批历史页面、React iframe 嵌入、审批流程模型重构或新的业务权限体系。

## 页面与数据设计

Admin 素材列表继续负责关键词、类型、状态、来源筛选和分页。详情抽屉打开后加载素材详情及当前版本，按服务端模板字段分组渲染四栏内容；历史快照使用素材版本返回的数据，不重新推导业务字段。左侧封面区域展示素材封面、编号和基础元数据；中间与右侧区域使用与 Workbench 查看布局一致的分组、折叠、滚动和动态字段展示规则。

操作区固定在抽屉左下角，按钮由 `vailableActions 与页面权限共同决定。审批通过和驳回打开意见输入弹窗；驳回意见必填，通过操作沿用后端要求的审批意见契约。提交审批、停用、恢复继续使用现有 API 和确认交互。任何操作成功后重新加载详情和列表，避免状态标签与可用操作过期。

## 路由与权限

Workbench 的 /zsjos/material-library/manage 菜单按菜单覆盖契约切换为 `dmin_embed，不再渲染 React MaterialLibraryPage。Workbench 的“素材浏览”保持原生页面。Admin 页面只依赖服务端下发的菜单/按钮权限；后端继续独立校验查询、编辑、提交、审批、停用和恢复权限及对象范围。

## 错误与状态

详情加载、动态字段加载、审批提交分别展示独立 loading、empty、error 和 retry 状态。审批处理中锁定相关按钮，关闭弹窗不丢失详情；操作失败不清空当前素材。无审批任务或无审批权限时不显示审批按钮。

## 验证

运行 Admin typecheck、lint、构建；运行 Workbench typecheck、构建；检查素材详情、版本、动态字段、审批通过/驳回、提交/停用/恢复和权限隐藏；在桌面及窄屏宽度确认抽屉滚动与左下角操作区可用。
