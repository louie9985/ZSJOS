# 回归测试用例

本文整理自本项目相关 Codex 会话中，用户明确提出“有问题”“不应该”“应该是”或要求确认计算口径的样例。用途是每次修改后，按本文用例补充或核对本地自动化测试。

> 说明：这里只整理当前本机 Codex 可读取到的项目相关会话。若历史会话未同步到本机，后续可以继续补充。

## 基础口径

- 默认全天标准工时：8 小时。
- 默认上午工时：3.5 小时。
- 默认下午工时：4.5 小时。
- 实出勤日按小时折算，除特别注明外按两位小数输出。
- 事假会影响实际出勤日，不应被 `正常` 或底层出勤字段直接覆盖。
- 调休按实际请假/调休小时折算；例如调休 3 小时，实出勤日为 `(8 - 3) / 8 = 0.625`，保留三位小数。
- 正常打卡叠加审批外出/外勤时，外出/外勤属于工作时间，不应压低实际出勤日。
- 用户修改后的最终日历状态应优先于源表原始异常/旷工状态，用于界面当前状态、异常计数和汇总重算。

## 会话问题记录

### 2026-07-01 正常请假事假被算为全天出勤

- 用户反馈样例：`正常(请假)- 08:20;` + `事假6.0小时（6/25 12:00 - 6/25 18:00）` 被算成全天出勤。
- 原因：系统先从 `正常` 识别出底层出勤，再由事假覆盖下午显示状态；汇总时曾允许底层 `attendanceAfternoon=出勤` 覆盖最终 `事假` 状态，导致事假半天仍计入实出勤。
- 确认口径：现有 `actualAttendanceStatuses` 列表不变；但只有当最终状态本身也计入实出勤时，底层出勤字段才可参与覆盖。`事假` 不计入实出勤，因此不能被底层 `出勤` 算回。
- 修复验证：已在 `desktop/src/core/summary.test.ts` 增加回归用例，期望实出勤为 `0.44`。
