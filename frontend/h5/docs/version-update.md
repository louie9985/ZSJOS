# 兼职 H5 版本控制与更新

个人中心入口 `/profile/version-update` 展示当前/最新版本、发布时间、更新说明及可展开的历史记录，沿用登录保护。纯前端版本工具无业务授权操作；不新增后端、数据库、业务菜单或通知发布能力。

## 构建与发布

- `package.json` 的 `version` 是显示版本；`releases.json` 按新到旧维护真实更新记录，首条版本必须与包版本一致。不要虚构过去的发布记录。
- 每次 Vite 构建生成唯一 `buildId` 和 UTC `publishedAt`（构建产物生成时间，作为本次发布标记），同一对象注入 JS 并输出 `dist/version.json`。同版本重新构建和部署回滚均按构建不同提示更新，不推断版本兼容性。
- 完整发布同一次构建的 `dist`；先保证资源就绪，再切换入口及清单。不要混用不同构建的 JS 和清单。
- 生产入口 HTML 与 `version.json` 应配置不缓存或重新验证，带 hash 的资源可长期缓存。请求使用 `no-store` 和时间参数，但无法替代 CDN/服务器缓存配置。此功能不修改部署服务配置。
- Vite 开发服务提供相同结构的清单；版本和说明变更后重新启动开发服务才生成新的开发构建标记。

## 检查、提醒与刷新

- 个人中心激活时检查，自动检查间隔五分钟；版本页进入和手动检查立即请求。同一时刻合并请求，十秒超时。错误独立展示并支持重试，保留上次成功结果时明确标注；不将错误展示为最新版本。
- 个人中心显示“有更新”；仅版本页展示可关闭提示。关闭记录按目标构建保存在本浏览器，不消除入口标记，不代表后端确认或跨设备状态。不在业务表单弹窗或自动刷新。
- 用户确认“立即更新”后保留 URL 路径、原查询参数和 hash，仅设置 `_h5_build` 缓存参数。不清空登录、浏览器存储或同源其他应用缓存。
- 刷新后仍未加载目标构建时显示缓存/发布未完成提示，不循环刷新。存储被禁用时检查和主动刷新仍可用，关闭持久化和跨刷新检测可能不可用。
- 更新说明随前端发布，按普通文本渲染；无富文本注入、后台发布、强制更新、业务消息已读或知晓回执。

## 验证

`node --test tests/version.test.mjs` 验证清单校验、回滚识别和 URL 保留；`npm run build` 执行类型检查和生产构建。浏览器覆盖最新、有更新、失败重试、提示关闭、历史展开、确认刷新及移动/桌面布局。
