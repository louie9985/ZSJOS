# 兼职端登录页

- 账号、密码输入区上方不再显示登录/激活切换按钮。
- 输入区下方的「登录」「企业微信登录」等宽并排；下方显示「首次使用？激活账号」及协议勾选项。
- 激活入口切换到原手机号、新密码、确认密码、邀请码表单，继续使用 `useAuth.activateWithInvite` → `POST /zsjos/auth/activate`，成功后沿用原登录态和跳转流程。激活表单下方可返回登录。
- 协议勾选默认未选中，仅保留当前页面的选择状态；本次未新增登录、激活或企业微信授权拦截规则。
- 仓库暂无正式《用户协议》《隐私政策》页面；入口暂提示未配置，待提供正式链接或正文后接入，不编造法律文本。

## 企业微信应用与身份

兼职授权和 code 换取身份优先使用当前租户的 PARTNER 企微应用；未配置专用应用时，复用同租户已启用且凭据完整的 ADMIN 企微应用。已有 PARTNER 配置若停用或不完整，不回退绕过它，接口返回明确的配置错误。其他社交类型及 ADMIN/MEMBER 授权逻辑不变。复用的是应用凭据，绑定、登录、令牌和通知接收人仍使用 PARTNER 账号身份。

应用配置可用不代表账号已绑定或推送已开启。用户仍需在个人页完成绑定并主动开启企微通知；本次修复不批量修改个人偏好。部署后须以测试账号验证授权回调、绑定、登录回跳和真实消息送达。

三方应用的“用户类型”由 System `user_type` 字典提供：会员 `1`、管理员 `2`、兼职合作方 `3`。
兼职专用企微应用须选择“兼职合作方”，不能以“会员”代替；AgentId 不应包含首尾空格。
`03-bootstrap-dictionary-types.sql` 补齐缺失的系统字典值 `3`，保留已有配置；已部署环境需评估已应用文件校验和，不自动重置版本记录。
此字典补齐不会迁移任何三方应用记录；已有应用的类型调整应按租户和目标记录单独确认执行，保留凭据与其他应用配置。
后台已打开页面可能缓存字典，缓存过期后刷新或重新登录可重新加载选项。

## 企微内网页授权

`GET /part-api/zsjos/auth/wecom-authorize-url` 新增可选 `inWecom` 参数（默认 false，兼容已有扫码调用）。
H5 登录和绑定统一根据 `wxwork` User-Agent 传入该标志：企微内使用 `snsapi_base` 网页授权，其他浏览器保留扫码。
登录页不再自动绕过协议跳转，用户点击“企业微信登录”并同意协议后发起授权。基础授权通常静默，不承诺企微弹窗。
服务端继续使用同租户 PARTNER 应用、既有 state 缓存及校验、code 换取 UserId 和 PARTNER 身份绑定，前端不提交可信 UserId。
未绑定身份不能直接签发登录令牌，用户需先通过已有账号登录后在个人中心绑定；绑定冲突及账号状态校验保持原契约。
应用必须配置兼职端域名为“网页授权可信域名”，成员须在应用可见范围内；外部扫码仍需单独配置授权完成回调域名。
此改动需部署匹配的后端和 H5 后生效；需在手机企微实测授权、未绑定、绑定冲突和取消/失败后重试。

## 未绑定提示与七天免重复输入密码

企微回调返回 `1900000018`（未绑定兼职账号）时，登录页显示“尚未绑定企业微信”弹窗，
说明先用兼职账号密码登录、在“我的 → 企业微信 → 去绑定”关联；新用户先使用邀请码激活。
确认按钮“使用账号密码登录”关闭弹窗并保留登录表单和原目标页。回调 code/state 从地址栏清除，刷新不重复提交。
仅该错误由弹窗处理，不将权限错误、非企业成员、网络失败误判为未绑定。

PARTNER 授权核验通过既有 JustAuth state 校验和企业身份查询取得 UserId，不再调用成员通讯录详情 `/cgi-bin/user/get`，
也不要求手机号或用户详情授权。身份接口本身若返回 60011，仍需检查应用凭据及成员可见范围。
ADMIN/MEMBER 身份获取保持原有实现；授权日志不输出 code、state、令牌或用户资料。

服务端参数 `zsjos.auth.remember-days=7`，移动端 OAuth 客户端访问令牌有效期 7200 秒、刷新令牌默认 604800 秒。
H5 持久化令牌而非密码，在访问令牌过期时自动刷新；刷新不重置原七天截止时间，PARTNER 新访问令牌也不超过该截止时间。
七天从本次成功登录/激活起算；期满、主动退出、账号失效或会话被撤销后须重新登录。
同一浏览器保留存储才可续用；浏览器清理数据及更换设备不共享登录态。该行为无需新增本地密码存储或七天访问令牌。
