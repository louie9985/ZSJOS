# 认证

前端保存统一登录返回的 `accessToken`、`refreshToken` 和 `expiresTime`。请求统一携带 Bearer Token。

Yudao 的未登录响应可能是 HTTP 401，也可能是 HTTP 200 但响应体 `code=401`；两种情况都必须进入同一套刷新流程。工作台使用单例刷新 Promise 合并并发刷新，原请求最多回放一次。登录、刷新和退出接口不参与自动刷新，避免递归。

刷新成功后更新两个令牌并回放原请求；刷新失败时只清理认证令牌，保留主题等本地偏好，并将会话状态切换为未登录。登录成功必须清除上一轮权限加载错误，完成新的权限加载后才进入工作台。

WebSocket 握手沿用框架约定，在 `/infra/ws` 查询参数中携带刷新令牌，以避免短期访问令牌过期后连接立即失效。令牌只用于建立连接，不写入日志或用户可见错误信息；退出登录时全局实时连接随工作台卸载而关闭。

## 记住登录表单

登录页的“记住我”默认不勾选。未勾选时，工作台不保存账号和密码；用户主动勾选并成功登录后，工作台在当前站点的 `localStorage` 中保存账号和 RSA 加密后的密码，有效期为 30 天。退出登录、令牌失效或权限信息加载失败不会删除这份表单缓存；取消勾选、缓存过期、数据损坏或解密失败会立即删除缓存。

登录表单缓存与认证令牌相互独立。“记住我”只控制下次登录页是否预填账号密码，不改变 access token 和 refresh token 的既有持久化、刷新或退出清理规则。登录失败不得写入当前输入内容或延长旧缓存有效期。

前端可逆加密只能避免密码在浏览器存储中直接显示为明文。解密逻辑必须随静态前端发布，因此该机制不能抵御 XSS、同源脚本或能够访问终端浏览器数据的人员，不应被视为安全的凭据保险箱。
