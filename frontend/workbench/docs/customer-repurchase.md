# 历史客户复购

历史客户复购供有现有录单权限的销售、教务使用，允许为彼此录入或负责的客户建立新复购订单。功能权限为服务端返回的 `zsjos:sales-order:create`，页面仍由服务端菜单控制；本次不授予任何账号权限。

## 交互及数据归属

1. 输入客户姓名及手机号或微信号，通过后端准确身份校验后再填写订单。修改身份会使旧校验失效，迟到响应不能恢复提交资格。
2. 已有客户复用客户主档；即使已有客资但没有订单或尚无生效订单，也允许从本入口录入（2026-10-08 确认）。姓名或已填写联系方式冲突、多客户命中、有待处理复购时仍展示具体阻断原因。
3. 完全无记录的历史客户可以继续；只读预检不创建数据，保存购买草稿时通过既有身份占用机制建立主档。
4. 订单姓名和联系方式固定为本次已核验身份。新订单及购买草稿归当前录单人，原客资、商机、首次成交、历史订单及服务关系保持不变。
5. 复用订单编辑器、商品字典、凭证上传和审批流程。重试保留原订单幂等键及同一草稿和凭证，避免响应丢失后重复记账。

统一入口使用 `/zsjos/sales-order/repurchase/check-customer` 和 `/zsjos/sales-order/repurchase`，购买草稿技术类型为 `customer_repurchase`。旧客资详情、本人学员及系统外复购接口保留各自对象权限。详细契约见 [订单 API](../../../docs/api/zsjos-sales-order.md)。

## 验证

测试夹具 `test/repurchase-customer.html` 使用实际页面和订单组件，仅替换测试环境传输层。可在任务专属 Workbench Vite 5195、Admin Vite 5196 启动后，从仓库根目录运行：

```powershell
python frontend/workbench/test/repurchase-customer-browser.py
```

脚本检查桌面及移动宽度、身份失效、错误重试、完整表单、凭证 ID、稳定幂等键和购买草稿引用。夹具数据不进入生产业务选项，也不连接真实业务数据库。`npm run typecheck` 检查工作台类型；管理端独立执行其 `pnpm` 检查。

实际账号授权、目标 MySQL 数据、在线支付到账、审批和通知仍需目标环境联调；模拟传输的浏览器通过不能替代这些验收。
