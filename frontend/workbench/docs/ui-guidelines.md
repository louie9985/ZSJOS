2026-10-25：诊断弹窗沿用原有 Ant Design Form、固定底部提交和原间距。新增诊断采用集中对照：默认当前账号，BusinessTable 紧凑明细按账号编辑阶段、状态及需要的最高点赞，行右侧 danger DeleteOutlined 仅移除本次填写项；明细下方 block dashed PlusOutlined 按需添加，不在顶部全选。候选由业务接口提供可用性和不可选原因。手机明细自然堆叠，不挤压选择框。共用诊断继续使用原表单、服务端字典；各账号指标可展开，加载/错误/重试与草稿保留分别处理。启动诊断与周期节点分开提交；历史修订保留原单账号界面。

本文档是 workbench 页面视觉一致性的唯一参考来源。新建页面、组件或修改共享样式时 **MUST** 先读此文。

机器强制的规则不在此重复 — 参见 `src/styles/styles.guard.test.ts`（禁止硬编码颜色、限定字号列表、强制 page/pane padding 使用 token 等）。

## 1. Token 体系

定义于 `src/styles/tokens.css`。所有自有 CSS 只引用 `var(--crm-*)` 变量。

### 1.1 表面层级

```
layout → chrome → container → elevated
                   ↳ 子块与 container 同色（兼容名 sunken）
```

| 级别 | 变量 | 用途 |
|---|---|---|
| layout | `--crm-bg-layout` | 最底层背景（内容区外） |
| sunken | `--crm-bg-sunken` | 兼容旧命名的子区域底色；使用平面或外阴影，不制造凹陷 |
| chrome | `--crm-bg-chrome` | 侧边栏、header |
| container | `--crm-bg-container` | 卡片/面板主体 |
| elevated | `--crm-bg-elevated` | 浮层/弹窗 |

### 1.2 阴影 elevation

| Level | 变量 | 场景 |
|---|---|---|
| 0 | — | 平面子块，不加阴影 |
| 1 | `--crm-shadow` | 静态面板 |
| 2 | `--crm-shadow-card` | 可交互卡片（默认态） |
| 3 | `--crm-shadow-raised` | hover 抬起 |
| 4 | `--crm-shadow-float` | 浮层 / Modal |
| inset | `--crm-shadow-inset` | 兼容旧命名，运行时映射为标准外阴影；禁止向内暗阴影 |

### 1.3 间距

| 变量 | 默认值 | 用途 |
|---|---|---|
| `--crm-page-pad` | 12px | 页面根元素 padding |
| `--crm-card-pad` | 14px | 卡片 padding |
| `--crm-pane-pad` | 16px | 主从页 detail-pane padding |
| `--crm-gap` | 10px | 主从列间距 / 卡片网格 gap |
| `--crm-sp-1` ~ `--crm-sp-6` | 4/6/8/12/16/24 | 通用间距阶梯 |

上述值随 `data-crm-density` 属性切换（loose / default / compact）。

### 1.4 圆角

`--crm-radius-sm` / `-md` / `-lg` (6/8/10)。随 `data-crm-radius` 切换。

### 1.5 字号

`--crm-font-sm` / `-base` / `-lg` / `-display` (12/14/15/22)。
Guard 允许的 px 字面量白名单：`10, 11, 12, 13, 16, 18, 30`。

## 2. 配方

工作台顶部“系统设置”右侧提供“全局刷新”图标按钮，沿用 Ant Design 文本按钮与 Tooltip。点击执行浏览器整页刷新，保留当前 URL（含查询参数与 hash），重新初始化页面数据；已有的未保存内容 `beforeunload` 提醒继续生效。刷新不承诺保留未保存输入。

### 2.1 标准卡片 `.lead-card`

```css
.your-card {
  min-width: 0;
  padding: var(--crm-card-pad);
  border: 1px solid var(--crm-border);
  border-radius: var(--crm-radius-md);
  background: var(--crm-bg-container);
  box-shadow: var(--crm-shadow-card);
  transition: box-shadow 0.25s ease, transform 0.25s ease;
}
.your-card:hover {
  box-shadow: var(--crm-shadow-raised);
  transform: translateY(-1px);
}
```

### 2.2 凸起子块（raised）

用于卡片内的字段行、统计区等内嵌区域。默认使用轻微外阴影；信息密度高或层级不需要强调时可以去掉阴影，但不得使用向内暗阴影：

```css
.your-raised-block {
  padding: 4px 8px;
  border-radius: var(--crm-radius-sm);
  background: var(--crm-bg-container);
  box-shadow: var(--crm-shadow);
  border: 1px solid var(--crm-border);
}
```

`--crm-bg-sunken` 和 `--crm-shadow-inset` 仅为兼容历史类名保留。新代码应使用 `raised`、`container` 或 `box-shadow: none` 表达层级，禁止 `inset` 暗阴影、明显变暗的子块底色和“洞中洞”效果。

### 2.3 玻璃效果（glass hero/toolbar）

仅在 `data-crm-glass="frosted"` 时生效。必须使用 `--crm-glass-*` 变量：

```css
.your-glass-panel {
  background: color-mix(in srgb, var(--crm-bg-container) 65%, transparent);
  backdrop-filter: blur(var(--crm-glass-blur-strong));
  box-shadow: var(--crm-glass-edge), var(--crm-shadow-card);
}
```

注意 `--crm-glass-edge` 的 none 态是 `inset 0 0 0 0 transparent`（不是 `none`），可安全拼入 `box-shadow` 列表。

### 2.4 详情区 12 列网格（overview grid）

申诉处理使用共用客资详情，默认选中“申诉记录”。所有无效判定周期与轮次默认完整展开，无需点击切换。
主区与审批流程保持 9:3；每轮保留自己的原判快照，申诉材料与审批结果并列，容器不足 900px 时材料单列，不足 700px 时流程在上、正文在下。
原无效结论使用“无效原因：”“备注：”标明快照字段，不将首轮申诉时间冒充原判时间。
原判、申诉和裁决附件使用通用 AttachmentCard；上传使用通用 DeferredAttachmentPicker，保留业务接口允许的图片类型及数量。
历史只读；仅当前授权任务显示裁决表单。提交成功保留详情并刷新结果，关闭详情及切换客资、筛选时保护未提交内容。
仅拥有申诉任务权限时使用服务端返回的申诉专用可见标签，不扩大其他客资信息权限。

所有页面的详情区/概览区内容布局统一使用 12 列网格体系。至少遵守最外层的 **9:3** 主侧分栏比例；二级嵌套可按内容量选择是否细分。

客资跟进记录面板例外（2026-09-28 用户指定）：`.fu-panel-layout` 默认使用 12 列 Grid，`.fu-panel-main` 和 `.fu-panel-aside` 各占 6 列；视口或面板容器宽度不超过 768px 时保持单列堆叠。

**最外层（必须）：**

媒体学员概览（2026-09-18 用户确认）使用 12 栏 9:3 主侧布局。顶部身份、服务与标签通栏、学员服务级工具栏保持结构；右侧统一承载服务状态、兼职账号状态和定位卡状态及当前版本操作，下方为学员档案与现有学员信息表资料。右侧自然滚动，不吸顶。定位访谈阶段、预约、记录数和材料独立标明，不与定位卡审核状态混同。

## 3. 页面骨架

教务团队页面顶部直接展示搜索、筛选、账号状态与刷新工具栏，不单独设置“教务团队”标题或描述占位。工具栏使用统一间距变量，窄屏自然换行，列表与详情紧随其后。

### 日历主体两侧导航

销售客资跟进日历、考期日历和账号日历复用
CalendarSideNavigation（2026-09-30 用户确认预览）。日历主体两侧保留独立窄栏，
左右胶囊箭头垂直居中，不覆盖日期、日程或时间轴，也不随时间轴横向滚动。
桌面按钮为 36×64px，桌面触控设备扩大到 44px 宽；颜色、背景和阴影使用现有主题 token。
手机适配（2026-10-08）：≤768px 时两侧导航的箭头移至日历上方左右两端，均为 44×44px，日期区域占满页面宽度，并提示左右滑动。月历七列保留 700px 可读宽度，月份选择器留在可见区域；考期名称与跨日条完整保留，通过日历内部横向滚动查看。账号日历信息栏缩至 112px，时间轴独立横向滚动，账号行同步增高。个人/课程单日卡片完整显示名称与时间；点击详情后再显示创建人、备注、通用附件/链接及全部编辑、删除、发送通知操作，月格与单日卡片不放这些操作。详见仓库 docs/api/calendar-day-details.md。
原有月份选择、今天、筛选和视图模式保留，已有工具栏上一/下一按钮移至两侧。
个人、课程月历的日期格展示当天全部日程，不再限制前三条或显示“另有”折叠提示。日程宽度跟随日期列，完整标题自动换行（含连续英文），日期行随日程数量及标题高度自然增高；沿用考期日历的紧凑标题字号与内边距，去掉状态蓝点及课程格内重复日期；已有记录的编辑、删除、发送通知统一放入点击后展开的详情面板。移动端仍保留七列内部横向滚动。考期月历保持已有的完整标题与自适应日期行，仅展示所选月份的日期和考期；首尾非本月位置留空且不可点击，不显示多余周行。跨月多日条仅覆盖本月日期，保留延续标记。

月视图切换前后月；账号日历的周、季、年视图仍按对应周期切换，并使用对应的无障碍名称。
个人和课程日历使用顶部“今天＋日／周／月”工具栏，移除年面板和主体两侧箭头。日/周按完整时间轴显示，周一首列，手机周视图内部横向滚动；月份日期格内容保持现有规则。详见仓库 docs/api/calendar-views.md。
两侧导航在加载、空数据和加载失败时保持可用，快速连续切换只能展示最后一次请求结果。
业务接口、权限和数据加载仍由各页面负责，布局组件不持有业务数据。

所有页面根元素：`<section className="workspace-page <feature>-page">`

### 3.1 主从页（inbox 式：左列表右详情）

代表页面：leads/owned、message-inbox、sales-order-inbox、work-plan。

```
<section class="workspace-page <feature>-page">
  <header class="<feature>-filter-shell">            ← 可选：tabs + 筛选行
  <div class="<feature>-inbox-layout">               ← CSS grid
    <aside class="<feature>-list-pane">
      <div class="<feature>-toolbar">
      <div class="<feature>-scroll">                 ← overflow-y:auto; flex:1
        <button class="<feature>-item [active] [unseen]">
        <div class="<feature>-list-sentinel"/>       ← IntersectionObserver
    <main class="<feature>-detail-pane">
```

**CSS 要点：**


## 6. 已知坑

- `.workspace-page-heading` 不存在 → 用 `.page-heading`（定义在 `patterns.css`）
- `.workspace-page` 已提供统一页面间距与不限宽行为，主从页仅按容器需要设置 `height: 100%`，不要重复声明相同 padding/max-width
- `[data-crm-preset="illustration"]` 预设强制 3px 边框 + 硬阴影 → 新视觉块需要尾部兼容覆盖
- `--crm-shadow-float` 运行时与 `--crm-shadow-card` 值相同 → 浮层独立性靠 `z-index` 而非阴影区分
- 在 glass 路径中，`--crm-glass-edge` 的零值是 `inset 0 0 0 0 transparent`，不能写 `none`
- 移动端(≤768px) `compact` 密度强制回落到 default 触控尺寸
- 移动端(≤768px) 表单控件字号被抬到 `--crm-font-mobile-input`(16px)，见 `antd-overrides.css`。这是 iOS Safari 的自动放大阈值：可聚焦控件 computed font-size < 16px 时会放大整个视觉视口，而 `.crm-shell` 是 `position:fixed; overflow:hidden`，放大后只能手动缩回。新控件若自带可聚焦元素，必须补进那份选择器清单（守卫在 `styles.guard.test.ts` 的 mobile input font size）
- 该 token **不随字号档缩放**（`small` 档刻意不覆盖它）：跟随降档会重新跌破 16px，在最需要它的窄屏上把自动放大引回来
- 移动端 Modal 的宽度由 antd 自行收口（≤767px 时 `max-width: calc(100vw - 16px)` 压过调用点传入的固定 `width`），高度由 `antd-overrides.css` 统一改纵向 flex + body 内部滚动 + 头尾固定；调用点无需再自己写 `styles.body.maxHeight`

### 链接填写

日历备注和日程说明使用 LinkedText 的 remark 模式，仅将显式 HTTP(S) 地址渲染为新标签链接，保留原始文字、空白、换行和完整网址（含参数）。覆盖个人、课程、单日/多日考期、跟进日历卡片、共享跟进时间线和日历通知预览；账号日历不增加备注入口。相关输入框通过 Form.Item.extra 常驻显示“支持 http://、https:// 链接；链接前后请用空格或换行分隔。”，不新增提交校验或编辑预览。共享跟进表单的其他入口使用相同提示。

备注链接支持大小写协议；空白、引号、尖括号和中文分隔标点划定候选边界，英文配对括号保留、尾部多余右括号留作文字。无查询参数或锚点时，尾部英文句末标点留作文字；query/hash 中的标点可能属于参数，不推测删除。中文路径不截断、不猜测无分隔中文的业务含义。无效地址、裸域名和非 HTTP(S) 内容仍为文本，不补协议，不执行 HTML，不抓取外部资源。点击、辅助点击和 Enter 激活只操作链接，不触发父卡片；不阻止默认浏览器行为。长链接在容器内换行，固定时间卡片内部可滚动以访问完整备注；跟进时间线继续使用原来的展开/收起交互。默认资源展示模式及其他调用方保持原行为。不排查、修复或迁移旧数据，也不改写历史通知快照。

内容制作、批量审核与发布登记的链接字段统一使用 `ResourceLinkInput`；账号资料依据服务端 `url` 类型接入，素材动态表单（含重复组）依据 `https-link` 类型接入。组件保留输入原文、表单事件、字段 ID、长度限制及禁用状态，允许清空；有效地址复用 `ResourceLink` 提供打开与复制预览，不请求外站元数据。必填、HTTPS 等业务校验仍由原表单和服务端负责，预览不可用不等同于表单校验失败。上传、自动生成只读链接和普通文本不转为链接输入。
