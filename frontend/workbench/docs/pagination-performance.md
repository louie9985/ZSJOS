# Workbench 表格分页与速度优化

日期：2026-09-29。当前阶段：本地源码与隔离验证；未发布到运行服务。

## 已核实的主要请求路径

| 页面/表格 | 翻页是否请求 | 主要慢点 | 本轮处理 |
| --- | --- | --- | --- |
| 我的订单（桌面表格） | 是 | 重复列表加载，翻页同时重查状态数量 | 单一列表 effect；翻页不重查计数；显式刷新仍更新两者 |
| 我的订单（移动端） | 游标续载时是 | 同列表生命周期的重复加载 | 保留游标模式和旧响应隔离 |
| 销售业绩下钻 | 是 | 原后端每页读取全范围事实、逐行权限检查，再截页 | 订单/客资/跟进/任务 SQL count/page；权限范围每请求解析一次 |
| 销售转化下钻 | 是 | 跨接收/订单历史计算；复杂窗口 SQL 实测反而更慢 | 只查期间订单及所需接收历史，复用精确转化算法再分页 |
| 新媒体客资明细 | 原先否，现为服务端分页 | 首次返回全部区间记录；旧后端先读全历史再筛选 | 新增 detail-page，页大小最多 100；取消过期请求 |
| 新媒体成员进度表 | 否，已加载成员数据本地分页 | 总览按成员及日期反复扫全部历史 | 按人预分组、日历一次累加、月目标同请求复用 |
| 公告阅读明细 | 是 | 每页先重查汇总再读明细 | 同一公告面板复用汇总，翻页/筛选只读明细；刷新更新汇总 |
| 素材审批 | 是，每个类型各一次 | 类型请求并发 + 每条任务再查四类关联数据 | 当前页四类数据批量读取；保持 BPM 本人任务与轮次校验 |
| 返现管理 | 是 | 大范围候选、姓名查询及逐条权限关联 | 沿用已交付的批量候选与权限优化，本轮未重复改写 |

本地分页不会因为切页产生列表请求，但进入页面、切换范围、刷新仍可能重新加载来源数据。是否慢不能只看“切页会不会请求”：应同时检查单页后端读取量、关联查询数量和重复请求。

## 保留的边界

- 服务端仍是权限、租户、菜单、人员、部门和历史归属的唯一依据，没有持久化跨用户缓存或截断业务结果。
- 新媒体总览仍读取授权范围历史事实；本轮减少重复遍历，没有将全部总览改为数据库聚合。
- 销售转化仍需形成精确队列再取当前页；首版全 SQL 窗口实现实测回退，未保留该实现。
- 素材审批仍按类型分别分页后合并。类型数量不均时，不能将它视作统一全局排序分页；统一方案需扩展 BPM 公共多流程查询契约并单独验证。当前优化只消除逐条关联查询。
- Notice 汇总按打开面板时刻展示；新阅读通过显式刷新更新。Vue Admin 汇总策略未改变。
- 后端接口字段和素材审批共享契约不变。新媒体员工端切到新增接口，需要先发布后端再发布员工端。
