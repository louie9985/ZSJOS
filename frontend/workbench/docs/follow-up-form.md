# 中世健工作台跟进表单

详情工具栏及跟进日历复用 `FollowUpModal`，详情跟进页签使用 `LeadFollowUpPanel`；两个容器统一渲染 `FollowUpFormFields`，继续各自管理提交、关闭和成功刷新。

## 展示与选择

- 弹窗宽度 720px，跟随视口收缩。表单按实际容器宽度排版：大于 550px 为双列，备注通栏；不超过 550px 为单列。内联表单不强制弹窗宽度，保留时间线主侧结构，详情容器不超过 768px 时上下排列。
- 跟进方式、结果、销售阶段、客资分类使用单选按钮，以服务端 value 标识、label 展示，保持返回顺序。默认展示六项，支持展开/收起；已选项折叠后显示摘要，不改变字段值。客资分类可以清空。
- 普通选项两列、每列最大 140px；时间快捷按钮三列、每列最大 80px。长文本换行，同排等高；触屏扩大点击高度。快捷备注按容器宽度三列/两列/一列展示，同样支持六项折叠。
- 快捷备注追加到原备注，以空格分隔；超过 2000 字则拒绝此次追加并提示，不截断原文。表单仍独立校验备注必填与长度。
- 时间快捷项复用已有分钟/日历天计算；手工改时间或重置后清除快捷项高亮。

## 数据与生命周期

`useFollowUpDictionaries` 使用现有 System 字典 API；销售阶段继续使用 `useLeadSalesStages`。加载、错误、重试与时间线查询分开。失败保留可见错误，重试只重新加载选项；加载或失败时阻止提交，必填选项为空时提示联系管理员。快捷备注为空不阻止手工填写。不提供静态业务选项或生产模拟工具。

保留当前分类和销售阶段的历史标签快照；已停用的当前值显示为不可重新选择的历史项。快照缺失显示“未记录”，不以 code 或当前字典标签编造历史值。后端继续负责持久化快照，本次不修改 API。

关闭弹窗、卸载或切换客资时忽略过期字典响应。切换客资清除旧表单与附件；内联收起保留已输入字段，重置恢复当前客资分类/阶段。无未保存编辑时同步服务器更新后的分类/阶段。输入、快捷操作和附件修改均维护内联 dirty 状态。

直接提交沿用 `useSubmissionGuard` 和延迟上传：提交期间冻结输入、附件及关闭/重置操作；失败保留草稿和上传成功结果；重试沿用未完成意图的幂等键。成功后沿用对应容器的刷新和关闭回调。不增加二次确认。

## 验证入口

从 `frontend/workbench` 运行：

```powershell
npm test -- src/services/followUpForm.test.ts src/services/leadFollowUp.test.ts src/services/deferredUpload.test.ts src/services/submissionGuard.test.ts src/pages/lead-management-unified.guard.test.ts src/styles/styles.guard.test.ts
npm run typecheck
```

浏览器检查三个入口、桌面及 390/320px、狭窄详情容器、明暗主题、键盘操作、长标签与六项以上选项；检查加载/空/拒绝访问/重试、备注长度、时间高亮、草稿切换/重置以及上传/提交失败恢复。组件夹具验证不代替真实登录、真实接口和持久化验收。无 API、schema、权限或依赖变更。

已成交客资仍按服务端 `ADD_FOLLOW_UP` 动作进入跟进。共享表单在 `status=won` 时将下次跟进时间设为选填；不填不安排新的提醒，填写仍须晚于当前时间。销售阶段可继续按字典修改，成交状态保持不变。成交时取消旧任务的规则保留；成交后新建的提醒按后续跟进替换。


## 销售自拓录单自动首跟（2026-09-29）

销售自拓录单未选择新媒体提供方时，备注去除首尾空白后必填，并提示已联系客户且有意向。录单页不增加方式、结果或独立判定备注选项；提交确认步骤可选未来下次跟进时间，摘要展示自动处理及提醒安排。选择提供方会清空不适用时间并恢复原备注校验。

仅直接新建、查重通过的请求，由后端原子完成归属、首跟、判有效和商机。客户端只提交一次创建接口，以 outcome、automaticQualificationApplied、qualificationStatus 展示真实结果；激活和复核不能展示为已判有效，失败重试保留幂等键。普通 FollowUpModal/LeadFollowUpPanel 的时间校验不因该录单路径放宽。

时间线依据 generationSource=sales_self_sourced_auto 展示“销售自拓录单自动生成”，保留录单人、分类/阶段快照和真实发生时间。人工图表分页读取完整历史并排除该来源，加载失败明确报错并可重试，后续人工跟进正常计入。

完整后端与双端契约见 [客资提交](../../../docs/api/zsjos-lead-submission-dispatch.md)。浏览器夹具是独立测试入口，使用合成传输数据，不代表生产认证及 MySQL 环境验收。在分别运行 Workbench Vite 5193、Admin Vite 5194 后，从仓库根目录执行 python frontend/workbench/test/self-sourced-auto-browser.py，覆盖双端桌面 1440/移动 390、备注、时间、提供方、复核/激活/教务分支、失败重试及历史图表。
