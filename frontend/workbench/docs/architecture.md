# 架构说明

客资销售反馈由 Lead 域独立保存，Workbench 在客资详情内填写多行文本和附件，
Partner H5 只读取本人记录。两个客户端复用既有 System 站内消息，无新增连接或消息存储。
详情页签与发送动作均消费后端投影；销售反馈读取权限不扩大客资列表和对象可见范围。

项目是 React + Vite 员工工作台，负责员工端布局、导航和业务交互，不重做管理端，也不建立第二套后端事实源。

基础数据流为：登录 -> Token -> `get-permission-info` -> `menus` -> React 导航模型和路由 -> 本地页面注册表或安全占位页。

工作台优先复用现有 system、CRM 和其他业务 API。新增且由中世健业务拥有的能力可以进入 `yudao-module-zsjos`，但不规划通用 `/zsjos/workbench/*` 聚合接口，也不复制其他模块已有逻辑。

跨模块的完整架构、数据流和所有权规则见仓库根目录的 `docs/architecture/`。

工作台登录后在全局 `RealtimeProvider` 中只建立一条 WebSocket 连接。站内信消息中心和客资派单订阅这条连接；收到事件后重新请求 system 或 ZSJOS 业务 API，WebSocket 负载不作为持久化事实源。连接包含心跳和指数退避重连，客资派单保留定时查询作为断线兜底。

个人消息使用服务端菜单 `/messages/all` 和 `/messages/unread` 进入同一个本地收件箱页面。设置页提供收件箱展示模式偏好，桌面端可在左侧分页列表、右侧详情的双栏结构与分页表格 + 右侧详情抽屉之间切换，移动端仍用列表加详情抽屉。收件箱页面在前端按 `全部 / 客资 / 提现 / 收益 / 申诉 / 系统` 做业务分类聚合，当前不新增后端分类筛选参数。`NotifyMessageProvider` 统一维护顶部铃铛未读数；点击铃铛时通过现有 System API 打开固定高度、列表区域可滚动的未读消息弹窗，仍可进入完整消息页。消息页标记已读或收到 `notify-message-new` 后，通过 HTTP 重新读取持久化消息和未读数。

销售自动派单另有独立 HTTP 页面心跳：只有 WebSocket 已连接、浏览器在线且心跳接口成功时，头部才显示“页面活跃”。接单偏好由后端持久化，页面重连后恢复上次选择；页面离线不改写该偏好，但会停止参与自动轮询。
